# 升级与迁移（MIGRATION）

> 容器版本、ABI 版本、跨版本升级与回退边界。
>
> Last updated: 2026-10-23 · 维护人：K1Super

## 1. 当前不变量

| 项 | 当前值 | 约束 |
|---|---|---|
| 容器格式 | V3 | 更新流程不得修改容器；安装器只替换程序目录 |
| C ABI | `0x000B` | 主进程、worker、DLL 必须处于兼容区间 |
| 事务 | 六阶段事务 + WAL 环形双区 | 更新前必须完成锁库落盘 |
| 数据目录 | 用户容器目录 | 不在安装器替换范围 |

## 2. 兼容矩阵

行表示已安装版本，列表示目标版本。单元格含义：

- `可直接升级`：ABI、容器 schema 与数据布局兼容。
- `需桥接`：目标版本要求的最低版本高于当前版本，必须先安装桥接版本。
- `禁止`：ABI 或容器 schema 不兼容，清单不得声明该升级路径。
- `未验证`：没有代码或测试证据，禁止发布对应清单声明。

| 已安装 \ 目标 | 4.1.x（ABI 0x000B / V3） | 后续 ABI / 容器变更 |
|---|---|---|
| 4.1.x（ABI 0x000B / V3） | 可直接升级 | 未验证，禁止发布 |
| 低于 4.1.x | 需桥接（按清单 `min_version`） | 未验证，禁止发布 |
| 后续 ABI / 容器变更 | 禁止跨级回退，除非矩阵新增证据 | 未验证，禁止发布 |

## 3. 升级前检查

1. 清单 `compatibility.abi` 覆盖 `0x000B`，`compatibility.container` 覆盖 V3。
2. 当前版本不低于清单 `min_version`；否则先安装桥接版本。
3. 安装包 PE `FileVersion` 等于清单 `file_version`，且高于当前版本。
4. 锁库落盘完成、脏数据为空、worker 已销毁。

## 4. 回退边界

- 新版本健康自检失败时，旧版物料保留，用户可通过修复入口重新安装旧版。
- 跨容器 schema 的破坏性迁移不得回退到旧版；回退前必须核对本矩阵与备份。
- 没有 LKG 或历史安装包时，不得向用户承诺“已自动回退”。
- 回退后容器是否可读必须由实测证据确认；未验证组合不得发布。
