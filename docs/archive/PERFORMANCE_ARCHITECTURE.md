## 1. 性能目标与指标

### 1.1 总体目标

Verthys 作为本地高安全数据管理器，性能目标是在**不牺牲任何安全属性的前提下**，提供与主流密码管理器相当或更优的用户体验。具体包括：

- **解锁时间**：在常见硬件（4 核 CPU、16GB 内存、SATA SSD）上，使用 BALANCED 预设（Argon2id 32MiB, 迭代次数校准至约 1.2 秒），从用户输入口令到容器可操作的总时间 ≤ **2.5 秒**（含 Argon2id 派生、超级块加载、索引预热）。
- **记录操作延迟**（单条增删查改）：
  - 添加记录（加密 + 写 Extent + 索引更新 + 事务提交）：**P95 < 20ms**。
  - 查询记录（索引查找 + Extent 读取 + 解密）：**P95 < 10ms**。
  - 删除记录（索引标记 + Extent 引用计数更新）：**P95 < 15ms**。
- **扫描性能**：全量扫描（迭代所有记录，不返回明文）速度 ≥ **50,000 条/秒**；返回明文的扫描速度 ≥ **20,000 条/秒**。
- **内存占用**：
  - 空闲（锁定状态）：**< 50MB**（含 DLL 加载、基础结构、缓存预热）。
  - 解锁后空库：**< 100MB**。
  - 解锁后 10 万条记录：**< 300MB**（含 LSM MemTable、Extent 索引、缓存）。
  - **峰值不超过 512MB**（硬性上限，超出自适应降级）。
- **CPU 占用**：
  - 后台任务（compaction、Merkle 重建、缓存刷新）**单核占用 ≤ 25%**（可配置），且使用 `THREAD_PRIORITY_BELOW_NORMAL`。
  - 前台操作（增删查改）不阻塞 UI 线程（通过异步 IPC）。
- **IO 吞吐**：
  - 顺序写入（导入大量记录）≥ **100MB/s**（加密前数据速率）。
  - 随机读取（查询单条）延迟 ≤ **5ms**（SSD 场景）。
- **资源上限**：所有资源使用均设置**硬性上限**，防止恶意或异常导致系统资源耗尽（如内存泄漏、文件句柄泄漏、线程爆炸）。

### 1.2 性能指标分层

| 层级 | 指标 | 目标值 |
|------|------|--------|
| 用户感知 | 解锁时间 | ≤ 2.5s (BALANCED) |
| 用户感知 | 单条记录操作延迟 | P95 < 20ms |
| 系统资源 | 内存占用 | ≤ 512MB (10万条) |
| 系统资源 | CPU 后台占用 | ≤ 25% 单核 |
| 系统资源 | 文件句柄数 | ≤ 64 个（DLL 内部） |
| 系统资源 | 线程数 | ≤ 16 个（含后台任务） |
| 可靠性 | 性能抖动 | P99 延迟 < 2×P95 |
| 可扩展性 | 10万条记录操作延迟 | 与1万条相比增长 ≤ 1.5× |

> **注**：以上指标基于典型硬件（4C/16G/SSD），在低端硬件上自动降级（见 §7.2）。

## 2. 性能架构设计原则

### 2.1 安全优先，性能次之，但性能可预测

- **任何性能优化不得削弱安全属性**。例如：不允许为了加快解密而缓存明文记录；不允许为了减少 IO 而跳过完整性校验。
- **性能必须可预测**：所有操作的时间复杂度、资源占用须有明确上界，避免出现不可控的尖峰（如全量 compaction 阻塞写入）。

### 2.2 异步化与流水线

- **CPU 密集型任务**（Argon2id、加密解密、哈希计算）尽量**异步执行**或利用**多线程并行**，但必须限制并发度，防止 CPU 争抢导致系统卡顿。
- **IO 密集型任务**（文件读写、缓存刷新）采用**异步 IO**（Windows Overlapped IO）或后台线程，避免阻塞主调用线程。
- **解锁流程**采用**流水线**：Argon2id 派生与索引预读并行，缩短总延迟。

### 2.3 内存可控与零拷贝

- **内存使用须有硬性上限**，所有动态分配均通过安全分配器并纳入记账。
- **数据路径尽量零拷贝**：例如 FlatBuffers 直接映射文件内容，避免额外复制；网络/管道传输使用零拷贝或引用计数缓冲。
- **大块数据（如导出文件）采用流式处理**，避免一次性加载全部明文。

### 2.4 分层缓存与预热

- **多级缓存**：内存缓存（MemTable、Extent 元数据、索引块）→ 温启动缓存（持久化索引摘要）→ 磁盘。
- **预热策略**：解锁时预加载关键元数据（超级块、分区表、Extent 索引头部），使常用操作不触发额外 IO。

### 2.5 背压与降级

- **后台任务具备背压机制**：当系统资源紧张（CPU > 80%、内存 > 80%、IO 队列长）时，自动降低后台任务速率或暂停。
- **性能模式切换**：用户可选择“性能优先”（允许更多后台并行）或“安全优先”（更保守的资源使用），默认“平衡”。

## 3. 关键路径性能优化

### 3.1 解锁路径优化

解锁是用户最敏感的路径，包含 Argon2id 派生、超级块读取与验证、密钥导入 CNG、索引预热等步骤。

#### 3.1.1 并行流水线

```
阶段 1: 读取超级块（IO）           ─┐
阶段 2: Argon2id 派生（CPU）       ─┼─> 并行执行
阶段 3: 验证超级块 HMAC（CPU）     ─┘
阶段 4: 密钥导入 CNG（系统调用）    ─┐
阶段 5: 加载分区表（IO）           ─┼─> 并行执行
阶段 6: 预热 LSM 索引（IO+CPU）    ─┘
```

- 使用**线程池**（固定 2-3 个工作线程）并行执行阶段 2 和阶段 1/3（Argon2id 与 IO 无依赖）。
- **索引预热**与密钥导入并行：在 CNG 导入的同时，后台线程预读 SSTable 的 Bloom Filter 和索引块。
- **温启动缓存**：如果存在有效的 `.verthys.idx_cache` 且校验通过，可跳过 LSM 索引重建，直接加载缓存（包含 MemTable 快照和 SSTable 元数据），将解锁时间缩短至 **1.2s** 以内（BALANCED）。

#### 3.1.2 Argon2id 调优

- **动态校准**：首次创建时校准迭代次数（目标 1.2s），并将基准写入超级块。后续解锁使用该参数，避免每次重新校准。
- **渐进式解锁**：在 Argon2id 计算期间，可先显示 UI 骨架，避免用户等待感。
- **硬件加速**：若 CPU 支持 AVX2，使用 libsodium 的优化实现（已启用）。

#### 3.1.3 超级块读取与法定人数

- **并行读取 3 个副本**：同时发起 3 个异步读，验证 HMAC，取最快有效的 2 个，避免串行读带来的延迟。
- **副本缓存**：超级块内容缓存于内存，后续事务更新时写穿（write-through）。

### 3.2 记录操作路径优化

#### 3.2.1 添加记录（加密 + 写 Extent + 索引更新）

- **加密**：使用 CNG 内核 AEAD，避免用户态密码运算开销（内核调用开销约 5-10μs，可接受）。对于小记录（< 4KB），可以**批量加密**以减少系统调用次数（例如每次事务批量处理 16 条）。
- **写 Extent**：采用**追加写**（顺序 IO），不修改已写数据。使用 `FILE_FLAG_NO_BUFFERING` 优化直写，但需对齐缓冲区（可通过预分配对齐内存池）。
- **索引更新**：LSM 的 MemTable 插入为 O(log n)（跳表），内存操作极快。WAL 写入为顺序追加，异步 fsync。
- **事务提交**：超级块更新采用**异步法定人数提交**：先写 WAL（快速 fsync），然后后台线程写超级块，用户操作在 WAL 写完后即返回（减少等待）。但需保证崩溃恢复正确性（WAL 先行）。

#### 3.2.2 查询记录

- **索引查找**：LSM 查找顺序：MemTable（跳表）→ Level 0 → Level 1 ...，配合布隆过滤器快速排除不存在的 SSTable。对于热数据，MemTable 命中率极高，延迟极低。
- **Extent 读取**：内容寻址哈希直接定位 Extent 偏移，读取并解密。为减少 IO，可对常用 Extent 进行**内存缓存**（LRU），缓存大小默认 32MB。
- **解密**：CNG 内核解密，每条约 5-10μs。

#### 3.2.3 删除记录

- 采用**逻辑删除**（Tombstone），仅更新索引，Extent 引用计数减 1。当引用计数为 0 时，不立即物理删除，由 GC 后台回收。

### 3.3 扫描路径优化

- **全量扫描**：直接遍历 LSM 索引（按 key 顺序），无需读取 Extent 数据，速度极快。仅当需要返回明文时才读取 Extent。
- **流式返回**：使用游标 API，每次 `Verthys_ScanFetch` 返回一批记录（如 100 条），避免一次性加载全部结果。
- **CPU 让步**：扫描循环中每处理 1000 条调用 `SwitchToThread()` 或 `Sleep(0)`，避免长时间占用 CPU。

### 3.4 导入导出路径优化

- **导入**：
  - 使用**批量事务**：每 1000 条记录提交一次，减少超级块提交次数（但需考虑 WAL 大小限制）。
  - **并行加密**：利用多线程对记录进行加密（每线程独立 CNG 句柄），但限制线程数 ≤ 4，避免 CPU 过载。
  - **流式读取**：导入文件采用流式解析，避免一次性加载全部。
- **导出**：
  - **流式写入**：边解密边写文件，使用大缓冲区（1MB）减少 IO 次数。
  - **解密并行化**：同样可并行解密（但需注意输出顺序）。
  - **进度反馈**：通过进度回调报告完成百分比，避免用户焦虑。

### 3.5 后台任务优化

- **Compaction**：
  - 只在系统空闲时触发（CPU < 30% 且 IO 队列 < 阈值）。
  - 单次 compaction 数据量限制（如 64MB），避免长时间阻塞。
  - 使用**分级压缩**，优先压缩 Level 0（最易重叠）。
- **GC**：
  - 批量收集可回收 Extent，单次回收数量限制（如 1000 个），并限制 IO 速率。
- **Merkle 重建**：
  - 分片后台执行，每片 16MB，完成后更新超级块 Merkle 根。
  - 仅在解锁时发现 Merkle 缺失或损坏时触发全量重建。

## 4. 内存管理与资源控制

### 4.1 内存预算与记账

- **全局内存管理器**：所有动态分配（包括普通堆、安全分配器、缓存）统一记账，跟踪当前总内存使用量。
- **硬性上限**：
  - DLL 内部总内存 ≤ **512MB**（可配置，见 §10）。
  - 当达到上限的 80% 时，触发**内存回收**（如清理 Extent 缓存、刷写 MemTable）。
  - 达到 95% 时，**拒绝新操作**，返回 `VERTHYS_ERR_RESOURCE_LIMIT`，避免 OOM。

### 4.2 安全分配器与内存池

- **安全分配器**：用于密钥相关结构，使用 `VirtualAlloc` 加 `PAGE_GUARD` 边界页，并支持锁页。
- **内存池**：对于频繁分配的小块内存（如记录头、索引节点），使用**固定大小内存池**，减少碎片和分配开销。池大小可动态调整，但总量受预算控制。

### 4.3 零拷贝与引用计数

- **FlatBuffers 零拷贝**：容器元数据（超级块、分区表、SSTable Footer）直接映射到内存，不复制。
- **记录返回**：`Verthys_GetRecord` 返回的明文数据使用**引用计数缓冲区**，调用者使用完毕后必须调用 `Verthys_ReleaseRecord`（或由 FFI 层自动管理），避免不必要的拷贝。

### 4.4 线程与句柄限制

- **线程池**：全局固定大小线程池（默认 4 个 worker），用于后台任务和并行加密。**禁止动态创建线程**（除特殊长生命周期线程）。
- **文件句柄**：使用**句柄池**，最多同时打开 8 个文件句柄（容器文件、缓存文件等），超出则 LRU 关闭。
- **CNG 句柄**：每个密钥对应一个 CNG 句柄，总数 ≤ 16（包括临时 record_key 句柄），用完即销毁。

## 5. 并发与异步策略

### 5.1 线程模型

```
主线程（API 调用线程）：
  - 处理同步 API 调用（Verthys_AddRecord 等）
  - 不执行耗时操作（> 1ms），将耗时任务提交到线程池

后台线程：
  - IO 线程：异步 IO 完成处理（Overlapped IO）
  - Worker 线程池（4 线程）：执行加密/解密、Compaction、GC、Merkle 重建等
  - 定时器线程：内存巡逻、运行时哈希校验（低频）

限制：
  - 总线程数 ≤ 16
  - 每个线程的 CPU 占用受优先级和调度策略控制
```

### 5.2 异步操作模式

- **WAL 写入**：`Verthys_AddRecord` 将 WAL 记录写入内存缓冲区，由 IO 线程异步刷盘（每 10ms 或缓冲区满 64KB）。
- **超级块提交**：WAL 写完后立即返回成功，超级块提交由后台线程完成（但需保证在崩溃时能从 WAL 恢复）。
- **索引预读**：解锁时后台线程预读 SSTable 索引块和布隆过滤器。

### 5.3 背压机制

- **内存背压**：当 MemTable 大小达到阈值（64MB）时，触发 flush 到 SSTable；如果 flush 速度跟不上写入，则阻塞写入（或返回 `VERTHYS_ERR_BUSY`）直到有空间。
- **CPU 背压**：后台任务检测系统 CPU 使用率，若 > 80% 则降低自身优先级或暂停。
- **IO 队列背压**：写操作使用有界队列（如 1024 个请求），队列满时阻塞。

## 6. 缓存策略

### 6.1 缓存层次

| 层级 | 内容 | 大小限制 | 失效策略 |
|------|------|----------|----------|
| L1: Extent 数据缓存 | 解密后的 Extent 内容（明文） | 32MB LRU | 记录更新时失效 |
| L2: Extent 元数据缓存 | Extent 索引（哈希→偏移） | 全部加载（常驻） | 无失效（每次事务更新） |
| L3: 索引块缓存 | SSTable 的 Index Block 和 Bloom Filter | 16MB LRU | compaction 时失效 |
| L4: 温启动缓存（磁盘） | 解锁快照：LSM 元数据、MemTable 快照、布隆过滤器 | 与容器文件同目录 | 每次提交后异步更新 |

### 6.2 缓存一致性

- **写入穿透**：所有写操作直接更新内存缓存，并写穿到 WAL，保证崩溃后缓存可从 WAL 重建。
- **温启动缓存有效性**：基于 `container_id` + `txid` + `cache_hmac` 验证，txid 不匹配则忽略并重建。

### 6.3 缓存预取

- **顺序预取**：在扫描或批量读取时，根据访问模式预取后续 Extent 数据（每次预取 4 个）。
- **索引预取**：解锁时预读所有 SSTable 的 Bloom Filter（约 1MB 对于 10 万条），加速后续查找。

## 7. 监控与自调节

### 7.1 性能指标采集

- **内部计数器**：记录操作延迟（分位数）、内存使用、CPU 时间、IO 次数、缓存命中率、Compaction 次数等。
- **暴露接口**：通过 `Verthys_GetDiagnostics` 返回结构化性能数据（非敏感），供上层 UI 展示或日志记录。
- **低频采样**：每 10 秒采集一次系统资源（通过 `GetProcessTimes`、`GetProcessMemoryInfo`），记录峰值。

### 7.2 自适应调节

- **Argon2id 参数漂移**：若连续多次解锁时间超过基准 30%，自动降低迭代次数（但最低 1 次）并触发 rewrap。
- **缓存大小动态调整**：根据当前内存压力，在预设范围内动态调整 Extent 缓存大小（16MB～64MB）。
- **后台任务速率**：根据系统 CPU/IO 负载，自动调整 compaction 和 GC 的速率（如每次处理的数据量减半）。

### 7.3 异常处理与降级

- **资源耗尽保护**：当内存、句柄、线程达到硬上限时，返回 `VERTHYS_ERR_RESOURCE_LIMIT`，并尝试回收资源（如刷写缓存、压缩索引）。
- **性能看门狗**：如果某个操作超过预设时间（如解锁 > 10s），记录诊断日志，并可选择降级模式（如禁用预读）。

## 8. 性能测试与基准

### 8.1 基准测试集

| 测试项 | 方法 | 目标 |
|--------|------|------|
| 解锁性能 | 使用固定口令，测量从调用到可操作 | ≤ 2.5s (BALANCED) |
| 单条记录 CRUD | 循环 1000 次测量 P50/P95/P99 | P95 < 20ms (Add) |
| 批量导入 | 导入 10 万条记录，测量总时间和吞吐 | ≥ 100MB/s（数据速率） |
| 全量扫描 | 迭代所有记录（不返回明文），测量速度 | ≥ 50,000 条/秒 |
| 内存占用 | 使用 `GetProcessMemoryInfo` 监控峰值 | ≤ 512MB |
| 并发压力 | 模拟 4 个并发写入 + 4 个并发读取 | 延迟不劣化 > 2× |
| 长时间稳定性 | 运行 24 小时混合负载，监测内存泄漏和性能衰减 | 内存增长 < 10MB |

### 8.2 性能回归门

- **CI 集成**：每次 PR 运行性能基准（小型版本：1000 条记录），与基线比较，性能下降 > 10% 则失败。
- **夜间全量基准**：完整性能测试套件，生成报告并存储历史趋势。

### 8.3 硬件覆盖

- 在至少两种硬件配置上测试：高端（8C/32G/NVMe）和低端（2C/4G/SATA SSD），确保性能可接受。
- 低端硬件上自动降低后台任务速率，保证前台流畅。

## 9. 避免性能占用过高的保障措施

### 9.1 硬性资源上限

| 资源 | 上限 | 超限行为 |
|------|------|----------|
| 内存 | 512MB（可配置，默认） | 拒绝新操作，触发回收 |
| 文件句柄 | 64 个 | LRU 关闭，超出返回错误 |
| 线程 | 16 个 | 任务排队，不新建线程 |
| CNG 句柄 | 16 个 | 复用或等待 |
| 后台任务并发 | 4 个 worker | 队列长度 ≤ 1024，满则阻塞 |

### 9.2 操作超时与取消

- **所有 API 调用**设置**最大执行时间**（如解锁 10s、单条操作 1s），超时则返回 `VERTHYS_ERR_TIMEOUT`。
- **可取消操作**：扫描、导入导出支持取消标志，调用者可在其他线程设置取消。

### 9.3 智能降级

- **低电量/低性能模式**（通过系统 API 检测）：
  - 暂停后台 compaction 和 GC。
  - 减少缓存预取。
  - 降低 Argon2id 目标时间（但不得低于安全下限）。
- **过热保护**：当 CPU 温度过高（通过 `GetSystemPowerStatus` 等）时，降低后台任务频率。

### 9.4 防御性编程

- **避免忙等**：所有等待使用条件变量或 IO 完成端口，不空转 CPU。
- **内存分配失败处理**：所有分配检查返回值，失败时安全回退（如返回错误、释放临时资源）。
- **整数溢出防护**：大小计算使用 `SafeInt` 或检查溢出，防止分配过大内存。
