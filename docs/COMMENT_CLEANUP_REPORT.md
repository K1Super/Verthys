- 范围：仓库内全部自研代码（前端、Rust 后端、C++ core、安全服务、脚本与 CI）

## 一、执行方式

1. **分批执行**：按代码边界拆为 4 个阶段、17 个子批次并行处理，每批独立读取全文后逐条判断。
2. **只改注释的硬约束**：任务说明中明确禁止修改代码、字符串、日志文本、测试断言、格式与文件结构，禁止 git 写操作。
3. **基线快照校验**：每阶段开始前对目标目录做全量快照，结束后逐文件对比，只有「新增/删除行全部为注释行」才视为合规。阶段 2 曾发现一处子任务在巡检循环中新增代码行，已还原。
4. **构建门禁**：每阶段完成后执行对应语言的编译/语法检查与测试，不以「注释改动不影响运行」为由跳过。

## 三、清理的七类问题

| 类型 | 典型表述 | 处理方式 |
| --- | --- | --- |
| 变更史 / 旧实现叙事 | 「原实现」「旧版」「此前」「根治」「已在 Wave 54 收口」「用户裁定」 | 删除叙事；承载当前约束的改写为对现状的陈述 |
| 外部引用与编号 | `.md` 路径、`docs/...`、URL、`§`、`Wave 56`、`评审 #1`、`项2`、`U1/U2`、`P0-A` | 删除引用片段，必要时用代码内可验证信息补齐 |
| 注释与代码不一致 | `CosmicSubmit` 标注 86% 而变量为 74%；`quantum-flow` 槽高 230px 而代码 160px；`runtime_hash.h` 体积按 48×40 计算而结构为 48×48 | 按当前代码修正数值与符号 |
| 失效描述 | 注释称存在 `perspective 860px` / 3D 入射，实际已改 2D；称存在 `secure_zero_*`、`system32_loader_load` 等已删除符号 | 改为当前实现描述或删除 |
| 冗余重复 | 文件头与 `interface` 重复的 Props/Emits 清单、模块头与子模块重复的命令表、重复的导入说明 | 保留信息量最大的一份 |
| 逐行翻译 / 空话 | 「将 x 赋值为 y」「用于处理相关逻辑」 | 删除 |
| TODO 元信息 | 含日期、人名、工单号的 TODO/FIXME | 删除元信息，保留原因与影响 |

### 典型修正示例

- 前端 `CosmicSubmit.vue`：注释「悬停收敛至 86%」→ 按 `--cs-reach-hover: 0.74` 改为 74%。
- 前端 `LevitationField.vue`：删除「perspective 860px + z 深度入射」的失效描述，改为「逐条显影 + 2D 平移」。
- 前端 `SecurityCenter.vue`：状态说明由四态补齐为五态（含 `device_mismatch`）。
- Rust `background_patrol.rs`：删除「早期实现把两者一律当硬威胁」的历史段，改写为当前分级约束；同步还原子任务误加的一行心跳代码。
- Rust `security_commands/state.rs`：锁中毒注释原称「重置为新实例」，与代码「记录告警后返回 Err」不符，已按代码修正。
- C++ `runtime_hash.h`：体积常量按结构实际布局修正为 `16 + 48×48 = 2320` 字节。
- C++ `anti_inject`：删除不存在的「白名单数组/白名单路径」，统一为「模块信任巡检」。
- 脚本 `check_updater_profile.mjs`：注释称「禁止明文开关」，与代码允许 `--allow-insecure` 不符，已改为「明文传输须显式开启」。

3. **代码缺陷未顺手修复**：`devdock.css` 减少动效选择器疑似指向模板中不存在的节点，属代码问题，已记录未改。
4. **C++ 测试套件未运行**：注释改动不涉及运行时语义，以全量编译作为该阶段门禁。
5. **既有未提交改动**：工作区在任务开始前已存在功能性改动，各阶段均以任务开始时的快照为基线，未触碰。
