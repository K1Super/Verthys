## 关键结论
- **无 P0**：正常路径（崩溃恢复法定选举、WAL 双区回放、SSTable/Manifest 原子切换、partition/extent 索引 AEAD+HMAC 双层认证）闭环成立，未发现可直接稳定复现的内存破坏或密钥泄露路径。
- **最高级别 P1**：三处 — (a) WAL 换区不清零导致第三圈后残留旧帧可能被回放扫描（靠 committed_txid 水位兜底，对齐时窗窄）；(b) SSTable 上界为写后检查，溢出字节已物理落到 extent 分区，覆写密文；(c) delete 在 release 与 lsm_delete 之间失败重试会让 extent 引用计数多减，最坏触发 GC 误删仍被引用的数据块。
- 一致性设计上值得肯定：superblock 写后读验证、commit_quorum 半写靠读法定+丢弃、LSM 新表落盘后才插 Manifest 且失败回滚 next_data_offset、extent 索引“先落数据块后改索引（孤儿不可达）”、warmcache 任何失败静默回退冷启动——这些是正确的崩溃一致性骨架。
