## 3. ADR 列表

状态说明：`提议` 表示待 K0 审核；`接受` 表示已冻结；`拒绝` 表示不做；`待定` 表示需补充信息。

### ADR-KG-001：内核范围限定为 L1

- 状态：提议（K0 冻结）
- 决策：只做内核辅助访问控制；不做 L2 密钥/数据面，不做 L3 全内核化
- 理由：威胁模型不覆盖管理员/内核；L2/L3 攻击面与维护成本远高于收益
- 后果：驱动保持小而窄；安全声明限定为“内核强制的访问保护”

### ADR-KG-002：驱动是策略执行点，不是数据路径

- 状态：提议
- 决策：驱动不读文件、不解析容器、不持有密钥、不做加解密
- 理由：数据面留在用户态，降低蓝屏面与密钥暴露
- 后果：导入/导出性能不受内核影响；驱动失败不损坏数据

### ADR-KG-003：只由 SYSTEM 服务访问驱动

- 状态：提议
- 决策：应用不直接打开设备；服务是唯一客户端；设备 ACL 仅 SYSTEM
- 理由：复用 P2 双向认证，避免在驱动内重复 Authenticode
- 后果：服务是单点；服务不可用时 P2 本身已 fail-closed

### ADR-KG-004：不新增第 12 个特性位

- 状态：提议
- 决策：11 位契约保持 `0x7FF`；内核策略与状态独立
- 理由：避免跨层契约破坏；内核能力不是布尔位
- 后果：UI 增加独立“内核加固”区域；C 层投影不变

### ADR-KG-005：SECURE 默认 preferred，required 为高级选项

- 状态：提议
- 决策：`SECURE` 默认 `preferred`；`required` 需满足策略文件防篡改前置
- 理由：兼顾可用性与高安全；避免驱动故障锁死用户
- 后果：K1 只开放 `preferred`；K2 再评估 `required`

### ADR-KG-006：启动顺序与身份识别

- 状态：提议
- 决策：先 ARM 受保护映像路径；创建挂起 → Job Object → 确认登记 → 恢复；身份 = 进程对象引用 + 创建时间 + 映像路径
- 理由：消除外部进程在保护生效前拿到危险句柄的窗口，防止 PID 复用
- 后果：宿主启动链需要改造；父进程创建句柄仅用于 Job 分配，分配后关闭

### ADR-KG-007：运行中保护丢失立即锁定

- 状态：提议
- 决策：ACTIVE 后连续健康检查失败即锁定库、销毁 worker
- 理由：已解锁会话静默降级风险最高
- 后果：宁可中断会话，不继续无保护运行

### ADR-KG-008：K3 条件启动，K4 不承诺

- 状态：提议
- 决策：文件保护仅在明确需求与 K2 稳定后启动；K4 默认关闭
- 理由：minifilter 风险最高；K4 是架构改造
- 后果：路线图不承诺 K3/K4 交付

### ADR-KG-009：签名路线

- 状态：提议
- 决策：开发用测试签名；生产用 EV + 微软 attestation；K3 按微软要求评估 WHQL/HLK
- 理由：Windows 10 1607+ 只加载微软签名驱动
- 后果：EV 是发布前置；测试签名不得分发

### ADR-KG-010：CI 默认无驱动

- 状态：提议
- 决策：普通 CI 只编译；加载/攻击回归在 VM 门禁
- 理由：CI 不能蓝屏；驱动测试需要真实内核
- 后果：需要 VM 脚本与证据归档

### ADR-KG-011：命名与安全声明

- 状态：提议
- 决策：使用“内核加固/内核强制的访问保护”，不使用“内核态/内核级加密”
- 理由：应用与 worker 仍在用户态；避免误导
- 后果：UI、文档、发布说明统一用词

### ADR-KG-012：`required` 的策略权威

- 状态：待定
- 默认方案：迁移到 P2 服务 `%ProgramData%\Verthys\Security`，预设文件只作展示缓存
- 备选：HMAC 保护 `preset.json`，仅在迁移不可行且维护人批准时使用
- 截止：K2 开始前
- 后果：未定稿前不发布 `required`

### ADR-KG-013：不新增第四个预设

- 状态：提议
- 决策：保持 BALANCED/SECURE/PERFORMANCE/CUSTOM 结构；内核策略作为 `SECURE` 的高级选项
- 理由：避免第四档重复 SECURE 的 11 位能力；避免轨道 UI 重做与持久化代号迁移
- 后果：UI 使用独立“内核加固”区域；不改变三档 + 自定义结构
