## 1. 目标

内核组件的维护成本主要不在代码，而在长期兼容、签名、故障响应与范围控制。本章定义：

- 谁负责什么
- 出问题如何定位、止损、回滚
- 哪些环境必须持续验证
- 新需求如何评审，防止内核范围膨胀
- 如何安全地降级或移除内核能力

---

## 2. 责任

| 角色 | 职责 |
| --- | --- |
| 内核模块 owner | 驱动代码、IOCTL 契约、威胁模型、ADR、代码审查 |
| 服务 owner | P2 服务与驱动客户端、安装/升级/卸载、健康检查 |
| 应用 owner | Rust 状态机、预设事务、UI 状态与文案 |
| 发布 owner | 构建、签名、哈希校验、发布清单、回滚包 |
| 安全评审 | 威胁模型、攻击回归、签名与权限边界 |
| 测试 owner | VM 矩阵、Driver Verifier、兼容性、证据归档 |
| 维护人 | 最终范围裁决、K0/K1/K2 门禁签字 |

同一人可承担多个角色，但每个角色必须有明确责任人。

## 3. 可观测性

### 3.1 驱动状态

服务通过 IOCTL 获取：

- 状态：`UNARMED/ARMED/ACTIVE/DEGRADED/LOST`
- 原因：未安装/未运行/版本不匹配/注册失败/进程退出/驱动卸载/内部错误
- 协议版本、能力位图
- 受保护进程数量
- 拒绝计数、注册失败计数、事件丢弃计数
- 最近错误码与时间

### 3.2 事件与审计

| 事件 | 级别 | 内容 |
| --- | --- | --- |
| 驱动加载成功 | Information | 版本、协议、OS build |
| 驱动加载失败 | Error | 原因、状态码 |
| ARM 成功/失败 | Information/Error | 策略、原因 |
| 进程登记成功/失败 | Information/Warning | PID、创建时间、原因；路径仅记录映像名或哈希前缀 |
| 保护丢失 | Error | 原因、是否已锁定 |
| 驱动卸载 | Information | 版本、原因 |
| 健康检查失败 | Warning | 连续次数、最近错误 |
| 版本不匹配 | Error | 服务版本、驱动版本 |
| 测试签名模式 | Warning | 仅开发/内部；提示不可分发 |

### 3.3 指标

| 指标 | 用途 |
| --- | --- |
| 驱动加载成功率 | 发现兼容性回归 |
| ACTIVE 占比 | 评估内核加固实际覆盖 |
| DEGRADED 占比与原因 | 发现安装/版本/兼容问题 |
| 保护丢失次数 | 事故预警 |
| 蓝屏/异常重启次数 | 驱动稳定性 |
| 驱动相关崩溃桶 | 版本对比 |
| 升级失败/回滚次数 | 发布质量 |
| AV/EDR 冲突报告 | 兼容性 |

指标只做本地聚合或用户明确同意的遥测；不上传密钥、路径、照片内容。

## 4. 事故响应

### 4.1 分级

| 级别 | 场景 | 目标 |
| --- | --- | --- |
| P0 | 驱动导致蓝屏、无法启动、数据损坏 | 立即止损，回滚/禁用 |
| P1 | 保护可被同用户绕过、签名/权限缺陷 | 尽快修复，发布安全更新 |
| P2 | 兼容性冲突、升级失败、状态误报 | 计划修复，提供规避 |
| P3 | 文案、诊断、非关键 UI | 正常迭代 |

### 4.2 止损顺序

```text
确认影响范围
  → 停止分发/撤回版本
  → 提供禁用策略（SECURE preferred 降级或 off）
  → 回滚驱动包
  → 保留现场（dump、事件日志、driver.artifacts.json）
  → 修复与复现
  → 安全评审后重新发布
```

- 驱动不拥有数据，禁用/回滚不会损坏用户容器
- `required` 场景禁用前必须提供恢复路径，避免锁死用户
- 蓝屏现场保留 Kernel Dump；不在用户机器上自动上传
- 不在事故处理中顺手重构；先止损，再根因

### 4.3 安全漏洞

- 驱动漏洞按内核漏洞处理，优先级高于普通应用缺陷
- 评估是否需要临时禁用内核加固、发布热修复或撤销签名版本
- 如涉及签名私钥，立即轮换证书与重新签名
- 对外披露遵循维护人决策；不在修复前公开细节

## 5. 兼容矩阵

| 维度 | 范围 | 验证频率 |
| --- | --- | --- |
| Windows 10 | 1809、22H2 | 每个大版本 |
| Windows 11 | 22H2、23H2、24H2 | 每个大版本 |
| HVCI | 开/关 | 每个大版本 |
| Secure Boot | 开/关 | 每个大版本 |
| 测试签名 | 开/关 | K1/K2 门禁 |
| AV/EDR | Defender + 至少一种第三方 | 每个大版本 |
| 任务管理器/Process Explorer | 最新稳定版 | 每个大版本 |
| WER | 默认配置 | 每个大版本 |
| 备份/同步软件 | 至少一种 | K3 重点 |
| 硬件平台 | Intel/AMD、常见 OEM | 发布前抽样 |

不承诺：

- 所有第三方安全软件
- 所有 Windows Insider 构建
- ARM64（K1 不承诺）
- 已停止支持的 Windows 版本

## 6. 升级节奏

- K1 通过并接入主构建后，驱动随应用大版本升级；安全修复可单独发布驱动包
- 协议版本独立；驱动与服务必须同版本，不保留 N-1 兼容
- WDK/SDK 固定版本；升级需重新跑 HVCI、Verifier、兼容矩阵
- 证书到期前完成 EV 续期与重新签名；钉扎值同步更新
- Windows 大版本发布后，先在 VM 验证再进入生产
- 驱动升级失败自动回滚上一版；不强制用户重装应用
- 不在用户解锁过程中升级驱动；升级前要求锁定

## 7. 变更控制

任何新增内核能力必须提交：

1. 威胁模型更新（[01-threat-model.md](01-threat-model.md)）
2. ADR（[08-roadmap-adr.md](08-roadmap-adr.md)）
3. IOCTL/状态机变更说明
4. 测试矩阵与证据计划
5. 签名/发布影响评估
6. 回滚方案

评审判据：

- 能否用确定性规则拒绝
- 是否触碰数据面、密钥、容器、用户文件内容
- 无驱动环境能否完整回归
- 是否显著增加蓝屏面或兼容成本
- 是否有明确的用户价值与可验证收益

四项任一不满足，留在用户态；不接受“先加进去再说”。

## 8. 降级与移除

### 8.1 临时禁用

- 策略切 `off` 或 `preferred` 降级
- 服务 DISARM，注销受保护进程
- 驱动保持加载但空闲，或停止驱动
- UI 明示当前为用户态防护

### 8.2 永久移除

```text
发布移除内核能力的应用版本
  → 服务停止并删除驱动
  → 清理驱动文件、服务、设备、注册表
  → 保留用户容器与 P2 状态
  → 文档与 UI 移除内核声明
```

- 不改变容器格式，不要求用户迁移数据
- 不保留死代码与兼容层
- 移除后现有用户态安全能力保持

---

## 9. 文档维护

- 每次驱动/服务/预设变更同步更新 `docs/kernel-guard/`
- 状态矩阵、错误码、事件 ID、测试矩阵必须与代码一致
- 不写入未验证的“已支持”
- 代码注释遵循项目注释规范；不在注释中引用本文档
- 发布前检查文档中的命令、路径、版本是否仍有效

---

## 10. 维护检查清单

每个大版本：

- [ ] WDK/SDK/VS 版本与 CI 一致
- [ ] 驱动加载/卸载/攻击回归通过
- [ ] HVCI/Secure Boot 矩阵通过
- [ ] AV/EDR 抽样通过
- [ ] 升级/回滚/卸载通过
- [ ] 驱动签名有效期与钉扎值正确
- [ ] 事件 ID/错误码/状态文案与代码一致
- [ ] 文档与 CHANGELOG 同步
- [ ] 回滚包可用
- [ ] 无测试钩子/测试证书进入生产

## 11. 风险

| 编号 | 风险 | 对策 |
| --- | --- | --- |
| O1 | 驱动蓝屏影响全系统 | 最小代码、Verifier、VM、灰度、回滚、禁用策略 |
| O2 | AV/EDR 冲突 | 兼容矩阵、可诊断日志、白名单沟通、可禁用 |
| O3 | Windows 更新破坏加载 | 提前 VM 验证、状态可见、修复入口 |
| O4 | 证书过期/轮换遗漏 | 到期提醒、发布检查清单、钉扎值同步 |
| O5 | 范围膨胀 | 变更控制四项判据、ADR、维护人签字 |
| O6 | 文档与实现漂移 | 发布门禁检查、代码审查、状态矩阵对照 |
| O7 | `required` 锁死用户 | 恢复路径、K2 前定稿、审计 |
| O8 | 测试签名误分发 | 构建标记、发布扫描、UI 提示 |
