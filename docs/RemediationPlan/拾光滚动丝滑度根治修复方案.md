# 拾光滚动丝滑度根治修复方案（七层方案评审与实施记录）

> 定位：拾光相册网格滚动性能的专项治理文档。输入为用户侧七层方案（行窗口模型 /
> 零重绘 hover / 滚动静默态 / 优先级调度 / 滚轮平滑器 / 设备分档 / 验证标准）。
> 本文件是该方案的**评审裁定 + 实施记录 + 验证证据 + 真机验收清单**；
> 评审中发现的方案缺陷与项目不符处已直接修改（见 §二 修正清单），实施已落地。
> 无数据模型变更、无存量数据迁移；构建与 git 提交由项目方执行。

## 一、根因复盘（修复前的五个叠加因素，按影响排序）

1. **hover 过渡链在滚动中连续触发**：滚轮滚动时指针停在网格上，卡片从指针下
   掠过——每张卡进入 hover 同时启动 5 组过渡（抬升 transform、阴影 box-shadow、
   缩略图 filter、文字遮罩 opacity、光晕 opacity）。其中**大半径模糊阴影与滤镜
   是重绘型属性**，过渡期逐帧重绘卡片；滚动中同时 2~4 张卡在过渡时帧预算被挤占。
2. **每个滚动帧全量重建可视区列表**：`scrollTop` 每像素变化 → `visiblePhotos`
   全量重算（48 项新建对象 + 新 style/class 对象）→ Vue 对 48 个节点逐个 diff。
3. **新进屏行首次栅格化排队**：每项是独立合成层（translate3d），层内含圆角裁切、
   边框、32px 模糊阴影与图片；快速滚动时新行首次栅格化（大模糊阴影最贵）跟不上。
4. **滚动停顿即启动解密、再度滚动时竞争**：停止滚动 80ms 后启动 4 路并发解密
   （IPC 预取 + Worker 解密 + Blob URL + 图片解码），与滚动帧同抢主线程。
5. **滚轮离散步进无平滑**：Windows 滚轮一格约 100px 跳进，无平滑/惯性实现——
   "丝滑感"的行为层底座。

主路径已具备的正确优化（本波次保留）：虚拟滚动、scroll rAF 节流、`.glass`
去实时毛玻璃、方向感知预取、解密并发上限 4。

> 第二轮复查（§四）另定位一个同权重因素：第一轮实现引入的滚轮平滑把滚动
> 降级为"主线程驱动"（见修正清单 14）——已重写为合成器平滑；同时 `ParticleBackground`
> 在滚动期加入渲染让位。

### 修正清单（直接修改方案内容的地方，均给出理由）

1. **光晕跟随改 transform（不采纳）**：`--shine-x/--shine-y` 只在 mousemove 时
   写入（已由主循环排帧节流），滚动期鼠标不动、变量不变、不产生任何重绘——
   不在滚动路径上；改成"预渲染层 + transform 平移"需要大于卡片的渐变层模拟
   任意中心，复杂度高而收益为零。保留现实现。
2. **阴影层/提亮层直接放 `.photo-card` 内（不采纳该落点）**：`.photo-card` 有
   `overflow: hidden`（圆角裁切缩略图所需），卡内绘制的悬浮阴影会被直接裁掉。
   修正落点：**阴影层 = `.masonry-item::before`**（条目无 overflow 与圆角，
   阴影可外溢；随 hover 与卡片同步 translateY）；提亮层 = `.photo-card::before`
   （卡内合法，无外溢需求）。
3. **层叠顺序与 `.glass:hover` 漂移**（方案未覆盖，必须补）：插入提亮层后需显式
   固化 z 序（图像 1 < 提亮 2 < 文字遮罩 3 < 光晕 4）并用 `isolation: isolate`
   封闭在卡内；同时 `.glass:hover`（全局）会改 border-color 与 box-shadow——
   即使不参与过渡也是"进入瞬间一次重绘"，滚动掠过时同样累积——已用
   `.photo-card.glass:hover` 钉死为恒定值（零重绘）。`contain` 采用
   `layout style` 而不含 `paint`（规避自身盒阴影与 paint 裁剪的规范灰区）。
   条目层 `isolation: isolate` 封闭内部 z，跨条目遮挡维持文档树序。
4. **`[data-scrolling] .photo-reveal { animation: none }`（选择器笔误）**：
   `photo-reveal` 是 @keyframes 名，不是类名；修正为 `.photo-card`。
5. **背景降频走 useFrameGate（不采纳该路径）**：背景星场/星云/流星**全部是
   合成器 CSS 动画**（非主线程任务），无需经帧门控调度器；且引入组件对全局
   调度器的写入耦合。修正为：静默态在 html 根节点挂 `app-scrolling` 类，
   `idle-governance.css` 第 7 节以"通配暂停"暂停 `.ambient-bg` 子树
   （与 idle/reduce-motion/frame-budget 既有治理同款实现，暂停无相位跳变）。
6. **postTask 分片解密（裁剪）**：主线程侧负载是 IPC 消息与状态落点，CPU 已在
   Worker 池；分片需引入 `scheduler` 兼容分支与本可避免的复杂度。以
   "滚动期项边界暂停取新项 + 停稳追帧脉冲"达成同一目标（滚动期不改动解密
   并发面），滚动结束立即补齐，语义更简单且可测。
7. **Blob URL 延迟创建（不采纳）**：离开窗口即 revoke 会导致重进视口必须
   重新解密或长期驻留原始字节（内存/CPU 成本更高）；现行"解密即建、
   卸载/密钥失效统一回收"是正确生命周期。真正的显存/内存由浏览器解码缓存
   管理（并有预热机制优化首帧）。
8. **`% 100 === 0` 整除判定（修正）**：Chrome 滚轮步长随系统"滚动行数"换算
   （100/66/33...），整除判定会漏接管；改为"整数 deltaY + ≥40px 阈值"，
   漏接管只损失平滑（安全退化），误接管才破坏手感。
9. **`maxScroll` 缓存（修正）**：滚动上限随内容高度（解密/导入/删除）变化，
   必须每帧动态读取，不得在挂载时缓存。
10. **外部打断未处理（补）**：插值期间键盘翻页/拖滚动条/程序化滚动会与插值抢
    位置；补"位置与上次写入偏差 > 2px 即放弃插值让位"，杜绝回拉跳变。
11. **触控板误判（补熔断）**：触控板高速滑动可产生整数 ≥40 的 deltaY，特征
    判定无法 100% 区分；补"离散特征以 <25ms 连发 3 次即判定触控板让位原生"
    （鼠标棘轮物理上无法达到该频率），误接管损失降为毫秒级。
12. **运行期自动降档（裁剪）**：项目已有 `FrameBudgetMonitor`（P95 帧预算
    评估 → `body.reduced-motion`/`minimal-motion` 降级类 → CSS 动画暂停 +
    粒子密度控制，见 idle-governance.css 第 6 节）；重复实现违反"一处定义"，
    且运行期自动关闭辉光/阴影会造成用户不可预期的观感突变。`prefers-reduced-
    motion` 探测项目亦已全面覆盖（App.vue / useGlobalIdleScheduler 永久 idle /
    idle-governance 第 4 节）。保留：`scrollPerf` 开关对象供人工回退。
13. **no-anim 逐项挂类（顺手修正）**：动画关停是全局状态而非单项属性，挂到
    `.masonry-item` 会让 48 个节点在 1.5s 时各做一次 class patch；迁移到
    `.masonry-cols` 容器级（一次 patch）。
14. **平滑器插值位置（第二轮复查修正，根治级）**：方案（及第一轮实现）把平滑
    插值放在主线程逐帧写 `scrollTop`——`preventDefault` 取消原生滚动即把滚动
    从"合成器驱动"降级为"主线程驱动"：原生滚轮滚动由合成器线程保障、主线程
    再忙也跟手，改为主线程插值后，主线程任何忙碌（Vue 更新 / GC / 绘制）都会
    直接反映为滚动顿挫。已重写为**合成器驱动的平滑滚动**
    （`scrollBy({behavior:"smooth"})` → Chromium ScrollAnimator 在合成器线程
    插值）：主线程零逐帧参与，连滚由浏览器自动衔接，拖滚动条 / 键盘 / 触控板
    由浏览器自动打断让位——手写插值 / 打断 / 让位状态机整体删除（剥离步骤
    9/10 的对应物，复杂度与风险同步下降）。

### 三条铁律 → 实施映射

1. **滚动期主线程不做 O(可见项) 工作** → 行窗口量化（同窗口像素移动零状态写入）；
   跨行重建按"源引用 + 布局键"复用对象；内容未变时数组级引用稳定，
   `watch(visiblePhotos)` 与 Vue diff 在绝大多数滚动帧直接短路。
2. **禁止重绘型属性参与过渡** → 卡片过渡只剩 transform；阴影加深 = 固定阴影层
   `opacity/transform` 过渡；hover 提亮 = 白色叠加层 `opacity` 过渡；
   `.glass:hover` 的边框/阴影漂移被钉死；条目标量为独立堆叠上下文。
3. **滚动期冻结非必要动画与解码** → `scrollQuiet` 状态机：项边界暂停解密取项、
   样式层压平 hover 结果并关停过渡/动画、背景氛围全面让位（`.ambient-bg`
   CSS 通配暂停 + `ParticleBackground` WebGL 渲染帧跳过）；停稳 120ms 后统一
   追帧（立即补齐可视区解密 + 预热运动方向下一行图片解码）。
4. **滚动始终由合成器线程保障**（第二轮补充）→ 平滑滚动经
   `scrollBy({behavior:"smooth"})` 由合成器插值（主线程零逐帧参与）；
   行窗口量化、静默态与 DOM 更新全部退化为低频事件，不构成每帧主线程负载。

### 审查轮（实施后全链路复核，同批次）

按"数据链路 / 交互链路 / 生命周期 / 契约 / 与既有机制交互"五面对全部改动
复读核查，发现并修复 2 处真实缺陷、清理 8 个死导出、1 项悬空能力面登记：

1. **缺陷 A（入场动画解冻重播）**：静默态原以 `animation: none` 冻结入场
   动画——移除动画后，解冻瞬间动画会**从 0% 重新播放**（进入模块 1.5s 窗口
   内滚动 → 停稳后整屏卡片重新淡入闪烁）。改为 `animation-play-state: paused`
   （相位连续，停稳从暂停点继续，与 idle-governance 治理同款）。
2. **缺陷 B（首批解密进度虚假推进）**：首批解密被滚动静默态暂停时，收尾分支
   仍宣告"完成"并置位 `firstFillDone`——进度虚假且剩余项永不续跑。改为
   三分支收尾：静默暂停（保持在途与进度位置，由停稳追帧续跑）/
   用户取消（cancelled）/ 正常完成（done）。
3. **死导出清理**：`loadStage / loadPercent / loadMessage / loadElapsedMs /
   firstFillInFlight / decryptPaused / decryptingMetaIds /
   ensureVisiblePhotosDecrypted` 八个无消费者导出移除（内部实现保留）。
4. **悬空能力面登记**：`retryLoad / cancelLoad / resumeLoad`（取消/重试/恢复）
   在 Wave 50 移除提示横幅后失去 UI 入口——保留实现并加注释诚实标注，
   待产品决策恢复入口或整链清理（见 §八）。

核查通过项（取证式确认，非形式过场）：

- 列表元素更新全为"替换 + triggerRef"式，无就地属性修改——`buildVisibleWindow`
  的"源引用不变即复用"前提成立（grep 全文件确认）；
- 条目/卡片的 z 序封闭（双 isolation）不外泄：`.select-bar`（z 30）、查看器
  （z 2000）、导出对话框（z 4000）层级与旧版完全一致；
- ModuleStage 无 keep-alive（切换即卸载）→ 静默态定时器、`data-scrolling`、
  根类 `app-scrolling` 在卸载路径被 `destroyVirtualScroll` 全部清理；
- `_style` 构造点唯一（visible-window.ts）；`onScroll.cancel()` 在卸载链路保留；
- 平滑器与查看器 wheel（@wheel.prevent）、图片点击、选择模式无事件冲突；
- 引用稳定的完整链路成立：跨行重建仅新进项新建对象 → Vue keyed diff 每跨行
  一次 O(窗口项) 浅比较（style 为字符串恒等、class 归一化后恒等），滚动帧
  零列表 patch——与"每帧 1~3ms"的旧模型对比为数量级改善。

### 第二轮复查（根因重判——用户实测"仍卡顿"后）

用户实测反馈未达预期后，本轮放弃理论推演，改为**环境取证 + 架构核验**。

**环境取证（排除法）**：

- GPU：RTX 3050 Laptop + i7-12700H + 32GB；会话为本地 console（非 RDP，
  RDP 会禁用 WebView2 GPU 合成）；WebView2 `GrShaderCache` 当日活跃更新
  → **排除软渲染假设**；
- 祖先链排查：无活跃 `backdrop-filter` / `filter` 阻断滚动合成（项目既有
  治理已清除），无阻断性 will-change/transform；
- 时间窗证据：用户实测时间窗（20:56–20:59）与后端 92.3s 系统模块哈希基线
  构建（6221 模块，20:56:34–20:58:06）重叠。该任务以最低线程优先级单线程
  运行，**列为干扰变量与对照实验项，不判定为主因**；
- 常驻负载盘点：`ParticleBackground`（全局 WebGL 粒子）随 active 档每帧
  全速渲染——滚动期唯一未覆盖的常驻负载（见下"同轮加固"）。

**架构级根因（本轮重判）**：第一轮实现的滚轮平滑器在主线程逐帧写
`scrollTop`——`preventDefault` 取消浏览器原生滚动后，滚动不再由合成器线程
保障（原生滚轮滚动是"主线程再忙也跟手"的合成器路径），而被降级为主线程
依赖路径：主线程参与的任何工作（Vue 更新 / GC / 绘制）都会直接反映为滚动
顿挫。这是一处**架构降级**——把最流畅的原生滚动换成了最脆弱的主线程滚动。

**根治（已实施）**：重写为合成器驱动的平滑滚动——每次滚格发起一次
`scrollBy({behavior:"smooth"})`，插值由 Chromium ScrollAnimator 在合成器
线程完成；连续滚格由浏览器自动续接；拖滚动条 / 键盘 / 触控板由浏览器自动
打断让位（手写插值 / 打断 / 让位状态机整体删除）。

**同轮加固**：`ParticleBackground` 在滚动静默期跳过渲染帧（先推进
`lastWallClock` 再返回 = 渡越相位冻结，与 CSS `animation-play-state: paused`
同语义；物理 dt 本就受 50ms 钳制不跳变）——把 GPU / 主线程完全让给滚动合成。

### 第三轮红线处置（生产级事故回退：快速滚轮顿挫）

用户实测升级为生产级问题：滚动顿挫在快速滚轮时极其严重、体感劣于修复前。
逐层复盘后锁定两处**由本方案自身引入**的缺陷，另修复一处既有滚动期强制布局
源，并复核确认全部滚动期每帧工作：

1. **滚轮平滑整体移除（红线回退）**：第二轮引入的
   `scrollBy({behavior:"smooth"})` 每格调用在"高频离散滚轮"下机制性失效——
   每格都会取消/重启（或排队）上一个平滑动画：短目标被反复重启 → 速度曲线
   反复从头爬升 → **爬行 + 顿挫**，调用频率越高越严重（与用户"快速滑动时
   极其严重"完全吻合）。第一代主线程逐帧插值同样劣化（滚动主权从合成器搬到
   主线程）。**结论（已固化进配置头注与代码注释）：滚动一律走浏览器原生
   合成器路径，任何 JS 接管都是降级**。`utils/wheel-smoothing.ts` 及 spec、
   `config/scroll-perf.ts` 平滑开关、`usePhotoData` 挂载点全部删除（不留悬空）。
2. **`app-scrolling` 选择器失效范围红线（第二处自引入缺陷）**：静默态 CSS 原用
   `html.app-scrolling .ambient-bg *`——**通配最右端**：html 类每次切换都会把
   文档内全部元素标记为可能失效（全文档样式重算）；慢速逐格滚动（间隔 >
   120ms）时每格两次全文档重算 → 顿挫源。已改为**枚举全部动画元素**
   （`:is(...)` + `.star-bright` 伪元素单列，失效范围收敛到约 200 节点），
   并在 CSS 内固化"新增动画元素必须同步加入列表"的维护契约。
3. **滚动期强制布局源（既有缺陷）**：`useCardShine` 在 mousemove 的**同步阶段**
   执行 `getBoundingClientRect()`（强制同步 reflow）——滚动期 Chromium 更新
   hover 会派发鼠标事件，形成"滚动中每事件一次 reflow"。已改为：同步阶段只
   捕获元素引用与坐标（事件属性派发后仍可安全读取），布局读与写入全部延迟到
   排帧回调（每帧至多一次），且滚动静默期直接跳过采集（光晕视觉已被样式层
   冻结，采集无意义）。

复核确认（回退后的滚动帧主线程工作清单）：scroll 事件 O(1) 合并、跨行才
patch（O(窗口项) 浅比较）、静默类切换进/出各一次（失效范围已收敛）、背景
氛围暂停失效范围收敛、`ParticleBackground` 渲染跳过、HomeView 与安全管理
中心在拾光模块不挂载（无其它帧循环）。**滚动驱动权在合成器线程，主线程不
承载任何位置主权。**

**第三轮验证门**：vue-tsc 0 错误；vitest 308 passed（27 文件，平滑相关用例
随实现删除）；CI 两级全通过。

## 六、观感差异与设计边界（已知且有意为之）

1. **hover 提亮损失饱和增益**：原 hover 把缩略图滤镜从 `saturate(0.85)
   brightness(0.9)` 提到 `saturate(1.1) brightness(1)`——滤镜过渡是重绘型属性
   必须移除。替代提亮层为 `rgba(255,255,255,0.08)`（≈ 原亮度差），
   饱和度不再上升（合成器无法等价实现 saturate 增益）。静态基色（未悬浮观）
   保持不变。
2. **hover 边框提亮消失**：旧版 hover 时 `.glass:hover` 会把卡片边框提亮为
   `--border-hover`（无过渡、瞬变重绘一次）；新体系为"零重绘"将边框钉死为
   常量（恒定 `--border-glass`）。1px 边框的微弱亮度差让位于滚动路径的
   重绘归零，如需恢复须改用独立边框层（opacity 过渡）承担。
3. **滚动中 hover 视觉冻结**：滚动期间卡片保持静止态（不抬升/不提亮/不显光晕
   与文字遮罩），停止 120ms 后恢复——这是"静默态"的语义选择：滚动帧的
   稳定与干净优先于 per-card 反馈。若希望滚动中也保留抬升（仅牺牲其它视觉），
   调 `usePhotoData` 静默态样式块即可（层已分离，改动是局部的）。
   延伸：进入模块 1.5s 入场窗口内滚动时，正在播放的入场动画被暂停在中间帧
   （停稳后从暂停点继续，**不会重播**——这正是审查轮把冻结方式从
   `animation: none` 改为 `paused` 的原因）。
4. **滚轮接管边界**：系统"滚动 1 行"设置（deltaY≈33）不接管（保持原生离散
   以保护触控板）；阈值 40px 与单格增益在 `config/scroll-perf.ts` 单点可调。
   平滑曲线由浏览器合成器内置（不自定义 easing），连滚由浏览器自动衔接。
5. **位置坐标整数量化**：条目 `_left/_top` 取整（亚像素偏移消除，文本/位图
   免于重采样），宽度保留分数值——最大视觉偏差 <0.5px。
6. **滚动主路径由合成器线程保障**（第二轮根治的核心语义）：任何后续改动
   不得再以 `preventDefault` + 主线程逐帧写 `scrollTop` 的方式接管滚动——
   那会把滚动从"主线程再忙也跟手"降级为"跟随主线程状态"。
