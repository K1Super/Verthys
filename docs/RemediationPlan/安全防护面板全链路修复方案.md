方案日期：2026-09-29
方案依据：《安全防护面板全链路审查清单》（`docs/RemediationPlan/安全防护面板全链路审查清单.md`，2026-09-29）

## 一、红线与交付承诺（禁止降级条款）

执行期间以下条款不可协商，任何实现不得以"简化 / 临时 / 后续迭代"为由降级：

1. **安全底线恒定（红线能力集）**：调试器检测、反注入、密钥三权分立、应急熔断、锁定清空剪贴板、系统锁屏/注销/断连即锁定、全局密钥导出二次验证——以上能力在全部档位恒定生效，不因档位或用户开关关闭。本方案对其中每一项都保留或强化，不做任何弱化。
2. **能力真实性**：UI 展示的每一项特性必须存在可验证的执行路径；凡无法交付的能力，从产品语义、UI 展示、持久化结构中**移除**，不做"开关伪装"。
3. **单一事实源**：同一份档位策略在任意时刻只有一个权威源（C 运行时策略层），其余各层（Rust / TS / UI）只允许"读取—呈现—执行"，禁止各自维护可写副本。
4. **失败可见**：安全关键配置的应用/恢复/回读失败必须可见（用户提示 + 审计），禁止静默吞掉。
5. **权威不可被缓存回写**：本地缓存（localStorage）只允许作为"迁移来源 + 只读缓存"，任何路径不得以其覆盖受信文件。
6. **每批次独立过门禁**：`vue-tsc` → `vitest` → `npm run build` → src-tauri 测试 → worker 测试 → `run_ci` 全流程；未过门禁不得进入下一批次，禁止跨批次合流提交。

## 三、架构级根治设计

### 3.1 主线 A：视觉状态同步契约（直写 DOM 旁路）

**契约定义**（`SecurityDashboard.vue`）：

- `syncVisualState(pos)` = `writePosToDom(pos)` + `writeLitPos(pos, false)`，是 `--pos/--posw` 的**唯一**写入入口；
- 写入时机三态闭环：**挂载期播种**（`onMounted`）+ **变更期同步**（watch）+ **吸附/键盘/预设同步期落位**（同入口）；
- 拖拽期直写（`tiltLoop`）属于"高频临时通道"，不改变上述三态的契约。

**代码（终版）**：

```ts
/** 视觉状态统一入口：挂载播种 / 变更同步 / 吸附落位共用 */
const syncVisualState = (pos: number) => {
  writePosToDom(pos);
  writeLitPos(pos, false);
};

/* 变更期同步：拖拽期直写优先，避免节流值回跳覆盖指针位置 */
watch(orbitSliderPos, (pos) => {
  if (!dragging.value) syncVisualState(pos);
});

/* 挂载期播种：修复"重进面板回中位"——immediate watch 在挂载前执行
 * （Vue 3.5.39 runtime-core.cjs.js:868 证明 immediate 回调恒同步于
 * watch 创建时执行，flush:'post' 不足以推迟），此处为唯一可靠播种点 */
onMounted(() => {
  latestPos = orbitSliderPos.value;
  syncVisualState(orbitSliderPos.value);
});
```

**禁止事项**：不得恢复 `immediate: true`（其回调必然早于挂载）；不得新增任何第二条 DOM 变量写入通道。

### 3.2 主线 B：单一矩阵事实源（C 权威 + 投影/回读）

**结构**：

```
C 运行时策略层（security_preset.c）
  ├─ 三档矩阵唯一载体：fill_balanced / fill_secure / fill_performance
  ├─ 投影 API：security_preset_feature_bits(preset, out_bits)   // 11 位特性契约
  ├─ 活跃档位查询：security_active_preset(out)                   // 回读校验用
  └─ 快照读取：security_config_snapshot(out)                     // 消费方唯一读路径
        ▲
        │ worker op: get_preset_features / get_active_preset / switch_preset
        │
Rust 编排层（security_commands）
  ├─ security_get_preset_config  → 经 worker 查询 C 投影（删除本地静态表）
  ├─ security_apply_preset       → 落盘 → 切档 → 回读比对 → 不一致则回滚 + 报错
  └─ 本地静态表仅存在于 #[cfg(test)]，作为与 C 投影的一致性断言
        ▲
        │ IPC
        │
TS/UI 层
  └─ 只消费后端返回的 features（禁止任何本地特性矩阵常量）
```

**代码（C 侧，新增）**：

```c
/* 特性位契约（11 位，与 UI/Rust 一致；位序是跨层契约，禁止重排） */
#define SEC_FEAT_ANTI_DEBUG        (1u << 0)
#define SEC_FEAT_ANTI_INJECT       (1u << 1)
#define SEC_FEAT_INTEGRITY_CHECK   (1u << 2)
#define SEC_FEAT_MEMORY_GUARD      (1u << 3)
#define SEC_FEAT_KEY_SEPARATION    (1u << 4)
#define SEC_FEAT_EMERGENCY_RESPONSE (1u << 5)
#define SEC_FEAT_SESSION_LOCK_IDLE (1u << 6)
#define SEC_FEAT_MODULE_PATROL     (1u << 7)
#define SEC_FEAT_CLIPBOARD_GUARD   (1u << 8)   /* 原 clip_clear_on_lock，语义重定义见 5.3 */
#define SEC_FEAT_USB_CLONE_DETECT  (1u << 9)
#define SEC_FEAT_TRACE_CLEANUP     (1u << 10)
#define SEC_FEAT_VALID_MASK        (0x7FFu)

/* 应用侧策略位随配置一起存放（fill_* 填充；CUSTOM 由应用层注入） */
/* SecurityConfig 增加字段：uint32_t app_features; */

int security_preset_feature_bits(SecurityPreset preset, uint32_t *out_bits);
int security_active_preset(SecurityPreset *out);
```

**回读校验（Rust `security_apply_preset` 尾段）**：

```rust
// 切档后回读：活跃档位 + 特性投影与请求比对，不一致即回滚并报错（E_PRESET_VERIFY）
let active = query_active_preset(&app_state)?;          // worker → C
if active != code {
    rollback_preset_persist(&app, &state, prev_persist.clone());
    return Err(format!("E_PRESET_VERIFY: 回读档位不一致: {} != {}", active, code));
}
let features = query_preset_features(&app_state, code)?; // worker → C 投影
Ok(PresetConfig { name: preset_name(code), code, features })
```

**一致性测试**（必须同时存在于两侧）：

- C 测试：对 0/1/2 三档断言 `security_preset_feature_bits` 与文档矩阵逐位相等；
- Rust 测试：`#[cfg(test)]` 静态表与 C 投影一致性（经测试专用 worker 通道或离线比对同一期望文件）；
- 前端测试：UI 特性标签键集合与后端返回键集合严格相等（杜绝 UI 多展示/漏展示）。

### 3.3 主线 C：预设生效时机与信任链

**目标时序（终版）**：

```
应用启动 → worker_init（Verthys_Init，handle 就绪，worker.rs:246-306）
   │
解锁流程（verthys_unlock）
   ├─ 1. ensureWorkerReady
   ├─ 2. 读取受信档位：read_preset_persist_for_path(本次解锁的 verthys_path)   ← 新增按路径读
   ├─ 3. 预解锁应用：worker switch_preset(code)（CUSTOM→BALANCED 基线；失败重试 1 次，
   │      仍失败 → 中止解锁 + 审计 E_PRESET_APPLY_FAILED，禁止降级解锁）
   └─ 4. Verthys_Unlock（此后全部解锁运算运行在正确档位策略下）
        │
解锁成功 → globalKeyReady=true
   └─ SecurityCenter watch → restoreSecurityPreset()（唯一恢复链）
         └─ securityLoadPresetState() → applySecurityPreset(受信码) → UI 状态以回读结果为准
```

**三段式信任规则**：

1. **解锁期**：只从受信文件（按本次容器路径派生）读档位；`localStorage` 不参与（既有解锁收尾的本地缓存 apply 删除，见 B2）。
2. **恢复期**：受信文件有值 → 以其为准应用；无值 + localStorage 有值 → 迁移（应用后**保留** `localStorage` 作为缓存，不再删键）；两端均无 → 应用默认 BALANCED 并落盘。
3. **运行期**：用户显式切换 = 唯一写入路径（落盘 → 切档 → 回读 → 成功才更新 UI），且递增 `presetEpoch`。

## 四、逐项修复设计

### P0-1 游标重进面板回中位（用户报告）

- 根因：见审查清单 3.2（immediate watch 挂载前空转 + 无挂载期播种 + CSS 回落 `var(--pos, 50)`）。
- 修复：按 3.1 全线落地——新增 `syncVisualState`；移除 watch 的 `{ immediate: true }`；`onMounted` 播种；`latestPos` 同步播种。
- 不变量：任何时刻 `--pos` 要么等于 model 值，要么处于拖拽直写态；CSS 默认值 50 永不作为可见初值出现（挂载即被覆盖）。
- 失败路径：`trackEl` 为空时 `syncVisualState` 安全空转（写入函数保持空判），下一次变更或重挂载重试。
- 测试（新增 `SecurityDashboard.spec.ts`）：
  1. 以 `orbitSliderPos=100` 挂载 → 断言 `trackEl.style.getPropertyValue('--pos') === '100.000'` 且 `--posw === '100.00%'`；
  2. 以 0 值挂载 → 断言 `--pos === '0.000'`；
  3. 卸载后以 100 重挂载（模拟退出重进）→ 断言仍为 100（本缺陷的回归断言）；
  4. model 变更（吸附路径）→ 断言 DOM 变量同步更新。

### P0-2 C 层双缓冲被缓存指针击穿

- 根因：`anti_debug_v2` 永久缓存配置指针（`anti_debug_v2.c:145,194,208-219`），二次换档即指向被清零缓冲；读取窗口存在全零快照。
- 修复（C 侧，一次成型）：
  1. 新增 `security_config_snapshot()`（世代号乐观并发校验，见下），作为**唯一**合法读取路径；`security_get_config()` 保留但仅用于"确保初始化"（文档标注禁止跨调用持有返回指针）；
  2. `anti_debug_v2` 删除 `s_config` 静态缓存：每次判定取快照局部变量（`anti_debug_v2_check` 同步改造）；`anti_debug_v2_get_kdf_iters` 按 5.2 移除，不进入迁移清单；
  3. `anti_inject.c:458,521,719,775`、`memory_guard.c:260,322,563` 迁移到快照 API；`emergency.c:230` 为"确保初始化"调用（不读字段），改为新增的 `security_config_ensure_init()`；
  4. `security_preset_switch` 在 `InterlockedExchangePointer` 之后 `InterlockedIncrement(&s_config_gen)`（发布屏障）。

```c
/* 快照读取：任何返回都是某一完整档位的配置，绝无全零/撕裂 */
int security_config_snapshot(SecurityConfig *out)
{
    if (out == NULL) return -1;
    for (int i = 0; i < 8; i++) {
        LONG g0 = InterlockedCompareExchange(&s_config_gen, 0, 0);   /* 全屏障读世代 */
        const SecurityConfig *src = (const SecurityConfig *)s_config_active;
        if (src == NULL) {
            (void)security_preset_init(SEC_PRESET_BALANCED);
            src = (const SecurityConfig *)s_config_active;
            if (src == NULL) break;   /* 初始化失败：进入保守回填（不得朝全零返回） */
        }
        memcpy(out, src, sizeof(*out));
        LONG g1 = InterlockedCompareExchange(&s_config_gen, 0, 0);
        if (g0 == g1) return 0;                                       /* 世代未变：快照一致 */
    }
    /* 极端争用：回填保守基线（fail-safe），禁止朝全零失败 */
    memset(out, 0, sizeof(*out));
    out->preset       = SEC_PRESET_SECURE;
    out->anti_debug   = 1;
    out->anti_inject  = 1;
    out->memory_lock  = 1;
    out->anti_dump    = 1;
    out->app_features = SEC_FEAT_VALID_MASK;
    return -1;
}
```

其中失败回填契约为：`memset 清零后填入"保守基线"`——`anti_debug=1 / anti_inject=1 / memory_lock=1 / anti_dump=1 / app_features=全开`，即任何异常路径都朝"防护更严"方向失败（fail-safe），禁止朝全零方向失败。

- 不变量：读方永不持有跨调用指针；世代校验保证快照内部一致；争用耗尽时按保守基线（而非全零）处置。
- 测试（C，新增并发压力用例）：写线程循环切换三档 ≥10 万次，4 个读线程并发 `security_config_snapshot`，断言每次快照 `preset` 字段与全部字段组合恒为三档之一（无全零、无跨档混合）。

### P0-3 矩阵分歧（单源化）

- 根因：TS/Rust/C 三处矩阵并存；C 侧 `anti_debug`、`usb_shadow_sleep_min` 等与声明不一致。
- 修复：
  1. 按 3.2 建立 C 权威投影 + 回读；**删除** Rust `preset_config_static`（生产路径），仅保留测试期期望表；
  2. 矩阵终版按第五节 5.1 落地（含 `anti_debug` 全档恒定、影子休眠移除、`clipboard_guard` 语义重定义）；`anti_debug_v2_check` 增加对快照 `anti_debug` 位的门控（当前恒 1，保留防御性开关语义，同时消除"只写不读"）；
  3. 删除 TS 侧任何特性矩阵常量（当前无，`presetFeatureList` 只保留键-标签-描述，键集合以回读校验兜底）。
- 不变量：任一时刻"UI 展示值 == 回读值 == 执行值"。
- 测试：C 投影断言（三档逐位）+ 前端键集合断言 + 集成回读断言（B4 门禁）。

### P0-4 运行时策略无启动/解锁期应用

- 根因：`security_preset_init` 仅内部兜底 BALANCED；创建/解锁均不应用持久化档位；SECURE 强化在解锁窗口缺席。
- 修复：
  1. `preset_persistence.rs` 新增 `read_preset_persist_for_path(path)`（按本次解锁路径派生 `.preset.json`，不依赖 `last_verthys_path` 指针；现有 `read_preset_persist` 复用它）；
  2. `verthys_unlock` 命令（`verthys_controller.rs`）在 `ensureWorkerReady` 之后、`Verthys_Unlock` 之前：读受信档位 → `switch_preset(码)`（CUSTOM→0 基线）→ 失败重试 1 次 → 仍失败**中止解锁**（`E_PRESET_APPLY_FAILED` + 审计）——禁止以低档位静默继续；
  3. `verthys_v3_warmcache_disabled_by_preset` 的档位来源由容器头改为**运行时快照档位**（`verthys_api.c:556,628` 两处调用点改造），使温缓存策略与真实运行档一致；
  4. 创建路径（`create_with_preset`）：入参合法域 0/1/2 严格校验（拒绝其余值，不再把 2 归一化为 0）；容器头档位语义文档化（"创建基线"，不作为运行策略源）。
- 不变量：从 `Verthys_Unlock` 第一行起，C 策略字段位即等于受信档位；不相等时解锁不发生。
- 测试：SECURE 容器解锁前置断言 `security_active_preset == SECURE`；应用启动首个解锁即生效（新增 Rust 集成用例）；CUSTOM 容器解锁后活跃档位为 BALANCED 基线。

### P0-5 本地缓存回写权威 / 解锁期竞态

- 修复（B2）：
  1. 删除 `global-verthys.ts:1326-1331` 的解锁收尾 apply（本地缓存值），解锁期策略已由 P0-4 预应用，恢复链为唯一 UI 状态同步路径；
  2. `restoreSecurityPreset` 迁移分支：应用后**保留** `localStorage`（删除 `removeItem` 两行，`security-session.ts:211-213`），消除"缓存空洞 → 下次启动 ref=0"窗口；
  3. 恢复链纳入统一仲裁语义：`restoreSecurityPreset` 在每次 `await` 后校验 `presetEpoch`（既有），并新增"若期间已有用户切换发生则完全放弃本次恢复的落盘动作"的显式短路（当前迁移分支已有、标准分支补全）；
  4. `keyState.securityPreset` 初值语义保持"缓存快照"，但**任何写路径**必须先读受信文件（apply 前置校验：仅"后端无值"才允许以缓存迁移）。
- 不变量：受信文件的写者只有两类——用户显式切换、两端均无时的默认建立；其余路径只读。
- 测试：模拟 localStorage 与受信文件不一致 → 解锁后最终档位 == 受信文件；迁移后空缓存 + 重启 → 不降级；并发恢复 + 用户切换 → 用户选择胜出且无缓存覆盖。

### 5.1 终版特性矩阵（唯一权威，C 侧落地）

特性集合由 12 项裁定为 **11 项**（移除 `shadow_sleep`，理由见 5.2）。

| # | 特性键 | 显示名 | BALANCED | SECURE | PERFORMANCE | CUSTOM |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | anti_debug | 调试检测 | 开 | 开（+激进退出） | 开 | 恒开（锁定） |
| 2 | anti_inject | 注入拦截 | 开 | 开 | 开 | 恒开（锁定） |
| 3 | integrity_check | 完整校验 | 开 | 开 | 关 | 恒开（锁定） |
| 4 | memory_guard | 内存保护 | 开 | 开 | 关 | 恒开（锁定） |
| 5 | key_separation | 密钥分立 | 开 | 开 | 开 | 恒开（锁定） |
| 6 | emergency_response | 紧急熔断 | 开 | 开 | 开 | 恒开（锁定） |
| 7 | session_lock_on_idle | 空闲锁定 | 30 分钟 | 10 分钟 | 60 分钟 | 开关（开=20 分钟 / 关=不自动锁定） |
| 8 | module_patrol | 模块巡检 | 开（30 分钟周期） | 开（10 分钟周期） | 关 | 开关（开=30 分钟周期） |

裁定说明：

- **anti_debug 全档恒定**：检测成本为常数级（`IsDebuggerPresent`/`NtQueryInformationProcess` + 线程上下文检查），不构成性能档的减负对象；性能档减负集中在锁页、防转储、巡检、USB、痕迹、校验六类高开销能力。此裁定消除"性能档关闭反调试"的语义拉扯，并与"核心防护不随自定义关闭"的既有 UI 契约一致。
- **clip_clear_on_lock 语义重定义**：锁定清空剪贴板为恒定底线（`verthys_controller.rs:1353` 现状保留）；本开关语义收敛为"剪贴板监听（检测外部写入即清空）"，显示名改为"剪贴板防护"、描述改为"锁定清空恒开；开启后额外监听并清除外部写入"。BALANCED/PERFORMANCE 由现值 true 修正为 false（与当前真实行为一致，非新增降级）。
- **CUSTOM 基线**：C 运行时恒按 BALANCED 策略基线加载（`switch_preset(0)` 显式应用，禁止沿用上一个标准档的残留策略）；核心 6 项按上表恒开，应用侧 5 项按用户开关执行。

### 5.2 移除项与遗留字段裁定

执行归属：C 侧字段与 KDF 惩罚机制移除随 B4；`shadow_sleep` 的 UI/Rust/TS 全链路移除（含绑定再生成、测试夹具同步）随 B5A。

| 项 | 处置 | 理由 |
| --- | --- | --- |
| `shadow_sleep`（UI 特性 + Rust 字段 + `usb_shadow_sleep_min`） | **全链路移除** | 无数据源（C 未提供加密索引导出通道，无内存驻留索引能力），Rust `ShadowSleep` 无调用者；继续展示即虚假能力。Rust `usb_guard.rs` 内部结构保留（不进入产品语义），后续如需交付另立专项 |

## 九、自查与"再三确认"台账

本方案落笔前已完成的代码级证据核对（防方案自身缺陷）：

1. **Vue 3.5.39 watcher 语义**：`runtime-core.cjs.js:868`（`runsImmediately = cb && immediate || …`）与 `@vue/reactivity.cjs.js:1957-1962`（immediate 分支同步 `job(true)`）——证明 `flush:'post'` 不足以推迟 immediate 回调，P0-1 修复改为 `onMounted` 播种（审查清单已同步勘误）。

4. **会话守卫事件面**：`session_guard.rs:337-352`（WTS 锁屏/注销/远程断连/控制台断连→锁定）；`:357-361`、`:680-682`（挂起→锁定仅高安全）——"系统锁屏恒开、挂起高安全"的现状与矩阵一致。
5. **剪贴板守卫行为**：`clipboard_guard.rs:1-29`（30s 过期 + 高安全下外部写入即清空）——`clip_clear_on_lock` 语义重定义依据。
6. **导出二次验证恒开**：`useGlobalKey.ts:23,534-539`——`export_reauth` 字段移除依据。
7. **调试器检测响应**：`anti_debug_v2.c:186-191` + `emergency.c:226-231`（KILL 级应急无条件）——KDF 惩罚机制移除依据；`anti_debug_v2_get_kdf_iters` 全仓无调用者、`is_punish_mode` 仅测试引用。

12. **矩阵采集点**：`preset.rs:46-118`、`security_preset.c:28-102` 全文比对（含影子休眠方向相反、`anti_debug` 无消费者）。
