# 容器附属数据目录收口修复方案

> 定位：本文件是「容器附属数据（sidecar）目录收口」方向的唯一施工方案。
> 全文逐条对照当前代码核实（核实依据见 §2），既是评审结论，也是可直接施工的执行文档。
> 目标：新建 / 打开 `.verthys` 容器时，其状态、预设、导入日志、块台账、温缓存、锁诊断
> 六类附属文件不再散落在容器同级目录，全部收口到容器专属目录 `<容器路径>.d/`；
> 存量库首次访问时懒迁移收口，用户零操作。
> 边界：不改容器文件格式与 `verthys.h` ABI；不动应用级文件
> （`%LOCALAPPDATA%\com.verthys.app\.verthys_last_path`、`pepper.bin`）；不改前端交互。

## 一、命名契约（单一事实源）

### 1.1 目标布局

```
D:/data/
├── Vault.verthys                 ← 容器文件（用户选择的位置，原位不动）
└── Vault.verthys.d/              ← 附属数据目录（新建/首访时自动创建）
    ├── state.json                  ← 容器状态（原 <p>.state）
    ├── preset.json                 ← 安全预设受信文件（原 <p>.preset.json）
    ├── import.wal                  ← 导入 WAL（原 <p>.import.wal）
    ├── import.wal.snapshot         ← WAL 去重快照（原 <p>.import.wal.snapshot）
    ├── import.chunks.json          ← 块归属台账（原 <p>.import.chunks.json）
    ├── idx_cache                   ← 温启动缓存（原 <p>.idx_cache，C 层生成）
    └── container.lock              ← 锁持有者 PID 诊断旁路（原 <p>.lock，C 层生成，会话期存在）
```

目录名 = 容器路径 + `.d`（`Vault.verthys` → `Vault.verthys.d`）。

### 1.2 为什么是 `<容器路径>.d`

| 判据 | `<容器>.d` 方案 | 替代方案（容器搬进 `Vault/` 同名文件夹） |
| --- | --- | --- |
| 映射确定性 | 容器路径 → 目录路径为纯函数，无需登记表 | 需改变用户选定路径语义（容器不再落在所选文件位置） |
| 排序与归属 | 资源管理器排序紧贴容器，`x.verthys` / `x.verthys.d` 相邻 | 父目录只剩一个文件夹，但容器真实位置被隐式改写 |
| 惯例 | `.d` 为 Unix 附属数据目录惯例（`conf.d` / `rc.d`） | 无惯例支撑 |
| 改动面 | 派生点集中改造（Rust 5 处 + C 2 处），容器路径与 ABI 不变 | 需改前端保存对话框语义 + 创建响应需回传真实路径（`VerthysResponse` 现无 path 字段） |
| 旧库兼容 | 懒迁移可无损吸收旧文件 | 旧库不迁移，双布局长期并存 |

裁定：采用 `<容器路径>.d`。容器文件位置、前端交互、ABI、锁语义全部不变。

### 1.3 契约表（新路径 ⇄ 旧路径 ⇄ 迁移策略）

| 数据 | 新路径（权威写路径） | 旧路径（只读回退 + 一次性迁移） | 迁移策略 |
| --- | --- | --- | --- |
| 状态 | `<p>.d/state.json`（+ `state.json.tmp`） | `<p>.state`（+ `<p>.state.tmp`） | 首次读取命中旧文件 → 解析成功 → rename 进新目录 → 删旧 tmp |
| 预设 | `<p>.d/preset.json`（+ `preset.json.<pid>.<seq>.tmp`） | `<p>.preset.json` | 同上 |
| WAL | `<p>.d/import.wal`（+ `import.wal.tmp`） | `<p>.import.wal` | WAL 与快照（`import.wal.snapshot`）成对迁移，随 WAL 公开入口触发 |
| 台账 | `<p>.d/import.chunks.json`（+ `.tmp`） | `<p>.import.chunks.json` | 首次加载命中 → rename |
| 温缓存 | `<p>.d/idx_cache`（+ `idx_cache.tmp`） | `<p>.idx_cache` | 不回迁数据（可再生产物）：读「新路径优先，旧路径只读回退」；`save` 成功后 best-effort 删旧；`delete` 双删 |
| 锁诊断 | `<p>.d/container.lock` | `<p>.lock` | 无迁移；创建前 best-effort 建目录；关闭时 best-effort 双删并回收空目录（目录内如仍有其他附属数据则保留） |

`<p>` = 容器完整路径（如 `D:/data/Vault.verthys`）。派生路径只允许在容器路径之后
**追加**，不改写原字符：分隔符沿用输入原生体系（C 侧统一以反斜杠拼接目录与文件名），
`\\?\` / `\\.\` 长路径前缀原样保留——Win32 对带前缀的路径不做正斜杠归一，
改写输入会导致附属文件不可达；两侧构造必须命中同一文件。

### 1.4 双端契约（Rust ⇄ C 防漂移）

`idx_cache` 与 `container.lock` 由 C 层生成，是唯一跨语言命名的两个文件：

- Rust 侧权威实现：新增 `verthys-tauri/src-tauri/src/repository/container_layout.rs`；
- C 侧镜像实现：`verthys_warmcache_v3.c`、`verthys_container_lock.c` 各自内部函数；
- 两侧文件头互相标注契约，并各带契约测试钉死路径：
  - Rust：`container_layout` 单测断言归一化后 `sidecar_dir_for("C:/data/v.verthys") == "C:/data/v.verthys.d"`、`idx_cache_file_for(...) == "C:/data/v.verthys.d/idx_cache"`，并断言反斜杠输入与 `\\?\` 前缀原样保留；
  - C：`save` 后断言 `test_warmcache_v3.d\idx_cache` 存在、legacy 不存在，`delete` 后两者皆不存在。

## 二、现状全量盘点（逐条代码核实）

结论：全部附属文件均为「容器路径 + 后缀」派生，无任何登记表 / 数据库记录路径，
因此收口改造可行且不产生孤儿引用。

| 数据 | 现行派生点（已核实） | 生成方 |
| --- | --- | --- |
| `.state` | `verthys_state.rs` `get_state_file_for_verthys`（L238-241）；tmp L343、L376 | Rust |
| `.preset.json` | `preset_persistence.rs` `preset_file_for`（L47-50）；tmp L115-121；stray tmp 清扫 L158-173 | Rust |
| `.import.wal` | `verthys_wal.rs` `wal_path_for`（L128-135）；快照 L137-144；tmp L272-278 | Rust |
| `.import.chunks.json` | `verthys_chunks.rs` `chunk_ledger_path_for`（L98-104）；tmp L132-138 | Rust |
| `.idx_cache` | C：`verthys_warmcache_v3.c` `v3ic_build_path_w`（L108-121），load L180、save L401、delete L543；Rust 预热：`verthys_controller.rs` `preheat_cache_file`（L573-612） | C（主）+ Rust（仅预读） |
| `.lock` | C：`verthys_container_lock.c` `verthys_lock_sidecar_path`（L42-61），record L67-93，delete L119-125 | C |

配套事实核实：

- 写路径调用方全部封装在上述模块内（`write_state_file_atomic` 被 device_controller /
  unlock / create 调用；WAL 由 `verthys_batch_controller` 经模块公开函数驱动；
  台账由 `import_writer` / GC 经模块函数读写），**调用方无任何直连路径拼接**；
- 前端（`verthys-tauri/src/`）无任何附属文件路径引用（已全量检索 `preset.json` /
  `idx_cache` / `import.wal` / `chunks.json`，仅命中无关的 JS `state` 属性名）；
- 日志脱敏 `security/cleanup.rs` 的「含 `.verthys` 的 token → `<VERTHYS>`」规则
  对 `x.verthys.d` 目录名继续生效，无需改动；
- C 测试沙箱（`test_runner.c` L480-523）已支持递归清理目录，新增 `.d` 目录不产生残留。
- 温缓存写入口的语义：`Lock` 时同步写（`verthys_v3_lifecycle.c` L617-646，SECURE 档改为删除），
  失败不影响锁定（持久化优化）；这也决定「新建完成即出现 state + idx_cache」的现状。

## 三、施工总纲（不可违背的工程纪律）

1. **单一事实源**：附属路径只允许由 `container_layout.rs`（Rust）与两处 C 内部函数生成；
   施工完成后全仓不得再出现散落后缀拼接（自检命令见 §7.4）。
2. **读永不因目录缺失失败**：所有读取路径为「新路径优先 → 旧路径回退」，
   目录/文件缺失一律按"不存在"语义处理，绝不中断解锁、导入恢复等主流程。
3. **写只写新路径**：不存在"旧布局回退写"；新目录不可创建（只读介质/权限）时，
   写操作以明确错误上抛（不静默双写两套布局）。
4. **迁移先读后搬**：旧文件先解析成功再 rename；解析失败不迁移、原样保留并上抛原错误
   （保留现场供诊断）。迁移全程幂等，可重入、可重试。
5. **原子写纪律不变**：既有 tmp + fsync + rename 协议逐字保留，仅路径换成新目录；
   同目录 rename 保证原子性不受影响。
6. **删除有界**：任何清理（回滚 / 残留回收）只允许删除**已知命名的附属文件及其 tmp**；
   目录内出现未知文件时只删已知文件、保留目录本体，绝不递归删除未知内容。
7. **C 侧失败不劣化**：`idx_cache` / `container.lock` 保持"best-effort，失败不影响
   容器语义"的既有纪律；C 侧新增目录创建同样 best-effort（缓存写失败=降级冷启动）。

## 四、任务分解（按 P1 → P2 → P3 顺序施工）

### P1-1 新增契约模块 `repository/container_layout.rs`

职责：命名契约的唯一权威定义 + 派生 + 目录保障 + 懒迁移 + 有界清理。
依赖方向：仅依赖 `util::path`（符合 repository 层 CI 红线，无日志以外副作用）。

```rust
/*
 * repository/container_layout.rs — 容器附属数据目录命名契约（单一事实源）
 *
 * 跨语言契约：idx_cache / container.lock 由 C 层生成，命名必须与
 *   core/src/index/warmcache/verthys_warmcache_v3.c
 *   core/src/container/io/verthys_container_lock.c
 * 完全一致；改动本模块必须同步 C 侧并更新两侧契约测试。
 */

/// 目录后缀：<容器路径> + ".d"
pub const SIDECAR_DIR_SUFFIX: &str = ".d";

/// 目录内文件名（短名：身份由目录名承载）
pub const FILE_STATE: &str = "state.json";
pub const FILE_PRESET: &str = "preset.json";
pub const FILE_WAL: &str = "import.wal";
pub const FILE_WAL_SNAPSHOT: &str = "import.wal.snapshot";
pub const FILE_CHUNK_LEDGER: &str = "import.chunks.json";
pub const FILE_IDX_CACHE: &str = "idx_cache";           // C 侧同名
pub const FILE_CONTAINER_LOCK: &str = "container.lock"; // C 侧同名

// —— 新布局派生 ——
pub fn sidecar_dir_for(verthys_path: &str) -> PathBuf;   // normalize + ".d"
pub fn state_file_for(...) -> PathBuf;                   // → join(FILE_STATE)
pub fn preset_file_for(...) -> PathBuf;
pub fn wal_file_for(...) -> PathBuf;
pub fn wal_snapshot_file_for(...) -> PathBuf;
pub fn chunk_ledger_file_for(...) -> PathBuf;
pub fn idx_cache_file_for(...) -> PathBuf;
pub fn lock_file_for(...) -> PathBuf;

// —— 旧布局派生（只读回退与迁移专用）——
pub fn legacy_state_file_for(...) -> PathBuf;   // "<p>.state"
pub fn legacy_preset_file_for(...) -> PathBuf;  // "<p>.preset.json"
pub fn legacy_wal_file_for(...) -> PathBuf;     // "<p>.import.wal"
pub fn legacy_wal_snapshot_file_for(...) -> PathBuf;
pub fn legacy_chunk_ledger_file_for(...) -> PathBuf;
pub fn legacy_idx_cache_file_for(...) -> PathBuf;

// —— 目录保障 / 迁移 / 有界清理 ——
/// 存在且为目录 → 复用；存在但是文件 → Err（明确拒绝）；
/// 不存在 → create_dir（父目录必须已存在，即容器所在目录）。
pub fn ensure_sidecar_dir(verthys_path: &str) -> Result<PathBuf, String>;

/// 幂等迁移：legacy 缺失 → Ok；primary 已存在 → best-effort 删 legacy → Ok；
/// 否则 create_dir + rename（失败上抛，legacy 原样保留供下次重试）。
pub fn migrate_legacy_file(legacy: &Path, primary: &Path) -> Result<(), String>;

/// 有界清理（回滚 / 残留回收共用）：
///   1) 逐个删除新目录内的已知附属文件与 *.tmp，再删除 legacy 同级附属文件；
///   2) 目录若因此清空 → remove_dir（非递归）；
///   3) 目录内存在未知文件 → 保留目录本体，绝不递归删除。
pub fn cleanup_container_sidecars(verthys_path: &str) -> CleanupReport;
```

派生路径长度校验：容器路径已在 `validate_path_input` 受 MAX_PATH=260 约束，
派生路径最长再增约 22 字符（`.d/import.wal.snapshot`）。`ensure_sidecar_dir` 内对派生
路径做 260 长度校验，超限返回明确错误（提示用户缩短容器路径）；不劣于现状
（现最长旧后缀 20 字符，同为同量级风险）。

单测（P1-1 内交付）：目录/文件派生字符串钉死；`ensure` 幂等与"文件占位拒绝"；
`migrate` 三分支（缺失 / 已迁移 / 正常搬移）；`cleanup` 遇未知文件不删目录。

### P1-7 C 层 `verthys_warmcache_v3.c`（含头文件）

```c
/*
 * 命名契约（与 verthys-tauri/src-tauri/src/repository/container_layout.rs 一一对应，
 * 改一侧必须同步另一侧并更新契约测试）：
 *   缓存：<容器路径>.d/idx_cache         （legacy：<容器路径>.idx_cache 只读回退）
 *   临时：<容器路径>.d/idx_cache.tmp
 */
#define VERTHYS_V3IC_DIR_SUFFIX     ".d"
#define VERTHYS_V3IC_CACHE_NAME     "/idx_cache"
#define VERTHYS_V3IC_LEGACY_SUFFIX  ".idx_cache"

static wchar_t *v3ic_build_dir_w(const char *verthys_path);     /* <path>.d */
static wchar_t *v3ic_build_path_w(const char *verthys_path);    /* <path>.d/idx_cache */
static wchar_t *v3ic_build_legacy_path_w(const char *verthys_path);
static VerthysResult v3ic_ensure_dir_w(const char *verthys_path); /* CreateDirectoryW；ERROR_ALREADY_EXISTS 视为成功 */
```

- `verthys_warmcache_v3_try_load`（L159+）：先开新路径；`INVALID_HANDLE_VALUE` 且
  非存在性错误之外的失败语义不变；新路径缺失 → 再试 legacy 路径；两者皆失败 → miss
  （`VERTHYS_OK` + `out_hit=0`，冷启动兜底契约不变）。

| 场景 | 行为 |
| --- | --- |
| 新建库 | 前置建 `.d`；`create → lock(写 idx_cache) → 状态落盘` 全部在新布局；父目录零杂物 |

| 并发（理论上双实例） | 容器锁保证单写者；迁移 rename 失败方按"已迁移"处理并重读新路径（幂等） |

| 孤儿 `.d`（用户移走容器留下目录） | 不自动全盘扫描；属用户可见的显式残留，由用户自行删除（方案边界内不引入扫描器） |

## 六、失败、回滚与安全边界

1. **创建失败回滚**：容器文件 + 已知附属文件（state/idx_cache/lock/tmp）一并清理，
   目录清空即回收；预存目录含未知文件时**只删本次已知产物、保留目录**（杜绝误删用户数据）。
2. **写失败不静默**：`ensure_sidecar_dir` 失败在创建链路为硬错误；在既有库写链路为明确
   `Err` 上抛（原有无权限/只读场景的错误语义不变、不双写旧布局）。
3. **降级运行边界（明示）**：旧版本 App 不认识 `.d`，会视作全新库并重新散落旧布局文件；
   新版再次读取时按契约回收 legacy（新路径优先，旧版产生的会话数据不合并）。
   这是版本契约边界，方案不做"双布局双写"兼容（那会永久破坏收口目标）。
4. **MAX_PATH**：派生路径 +22 字符上限校验，超限明确报错；C 侧失败沿用 best-effort 降级。
5. **安全不变式**：附属文件均不含可用明文密钥材料（既有盘面语义），目录化不引入新暴露面；
   `.d` 目录名含容器名，日志脱敏规则继续命中；锁语义（容器文件锁）与互斥层级完全不变。
