## 三、遗留根因（全部为本次新取证确认，按严重度排序）

### R1【致命】窗口配置：transparent + 强制 GPU 光栅化 → WebView2 GPU 进程不稳定

- 位置：`src-tauri/tauri.conf.json`（L20-25）
- 证据：
  - `"transparent": true` + `"decorations": false` —— 透明窗口在 Windows 走 DWM 分层合成路径，WebView2 在该模式下受限（部分硬件加速/合成优化被关）；
  - `additionalBrowserArgs`: `--enable-gpu-rasterization --enable-zero-copy --ignore-gpu-blocklist` —— **强制开启 GPU 光栅化且无视 GPU 阻断列表**；
  - 组合效果：透明分层合成 + 强制 GPU 光栅化 + 常规/低端显卡 = GPU 进程容易 stall 或崩溃。WebView2 GPU 进程一旦无响应 → 整个页面前端冻结 → JS 事件不被调度 → **"任何功能全部卡死无法关闭"**（关闭请求也需经前端 IPC，见 lib.rs CloseRequested 的 hide+emit 链路，前端不响应则只有 45s 兜底超时）。
- 影响判定：与"滑动/点击立刻全卡、无法关闭"高度吻合，头号嫌疑。
- 修复方向（建议，未实施）：
  1. 关闭 transparent（改不透明窗口，配深色背景 + 自绘路径可控）；若必须透明，移除 `--enable-gpu-rasterization / --ignore-gpu-blocklist`，让 WebView2 自行走稳定合成路径；
  2. 移除 `--enable-zero-copy`（透明分层下零拷贝收益未知、风险显著）。

### R2【高】全屏 WebGL 粒子背景常驻渲染

- 位置：`components/ParticleBackground.vue`（onMounted L224 / renderFrame L621）
- 证据：
  - 4600 粒子：幕布 1000 + 银河盘 3000 + 近景尘埃 600，全部自定义 ShaderMaterial；
  - active 档 60fps 全屏渲染，DPR 满配（×2，`MAX_DEVICE_DPR`）；渡越期申请豁免强制满帧 + DPR 全配；
  - 残影层（渡越期可见，3+3 层）叠加上升 draw call；
  - 渲染器 `powerPreference: "high-performance"` + `antialias`（DPR<1.5 时开）。
- 影响判定：全屏 WebGL 与透明窗口合成、以及下方 Canvas2D 引擎互为叠加，是 GPU/合成器压力的主贡献者之一；且常驻全局（引导页/主界面/管理界面全部盖在上面）。
- 修复方向（建议）：idle 档进一步降 DPR（idle 1.0 已做，deep-idle 可降不透明简化 shader）；或管理界面进入时暂停粒子层（主界面子区已有自身宇宙背景）；或改为静止帧（仅在渡越/交互时激活更新）。

### R3【高】 QuantumDashboard 全屏 Canvas 物理场 60fps

- 位置：`composables/security-center/useQuantumField.ts`（frame L559-826）
- 证据：
  - 粒子池上限 DUst 110 + 碎屑 26 + 吸积盘弧段 ×14 段，每帧 clearRect + 逐元素 integrate + drawImage/stroke；
  - 与 R2 全屏 WebGL 同时运行（QuantumDashboard 置于管理中枢首屏，ParticleBackground 在底层）；
  - 管理界面打开即进入 active 档（resetIdle），双引擎 + CSS 动画三路并满载 60fps。
- 影响判定：CPU/GPU 双饱和的重要来源；帧预算降级通道（frameBudgetMonitor）按 P95>6ms 才降密度，实际单帧开销大概率超阈值前已被重置（拖动即 active）。
- 修复方向（建议）：合并管理区内外的背景渲染职责（进入管理区停 ParticleBackground 或停 QuantumDashboard，二选一）；降低尘埃上限；降帧档提前。

### R4【中】 ManagementHub 每帧 Canvas 渲染 + DOM 直写仍高频

- 位置：`components/management/ManagementHub.vue`（frame L508-726）
- 证据：
  - 每帧：3 单元 transform/opacity 直写 + 3 个 CSS 变量（--boost/--prox/--lift）+ Canvas clearRect + ≤44 mote drawImage + 3 丝链 stroke + 光包 + dashoffset 直写 4 元素；
  - 在 R2（全屏 WebGL）之上叠加，管理引导区首屏双 Canvas 并存。
- 影响判定：中等；与 R2/R3 同屏组合时放大。
- 修复方向（建议）：进入 hub 视图可与 R2 二选一；mote 上限再降；或 idle 档已降频（5fps）但 active 挡仍 60fps。

### R5【中】 background_patrol 哈希基线构建（51~55s）CPU 密集 + 看门狗误杀重启

- 位置：`security/background_patrol.rs`（try_build_async L515 / watchdog_loop L775 / check_hash_baseline_violations L1108）
- 证据：
  - 启动即构建：枚举 System32 + SysWOW64 全部 .dll/.sys（6221 个）逐个 SHA-256，实测 51~55s（日志实证 54814ms / 51021ms）；
  - 构建线程仅 `THREAD_PRIORITY_LOWEST`（无分段让步，LOWEST 仍吃满单核）；
  - 看门狗心跳超时阈值 15s < 构建耗时 → 构建期间心跳超时线程被误判死亡并重启（日志实证"心跳超时（18s>15s）→重启→再构建"），叠加构建成本；
  - 每次巡检（10-40s 一次）=> enumerate_loaded_module_paths + 全部模块哈希重算。
- 影响判定：启动后 1 分钟内显著 CPU 争抢；叠加 R2/R3 渲染满载时推高整体卡顿概率；重启循环浪费。
- 修复方向（建议）：构建循环内分片让步（每 N 个文件 sleep(0)/sleep(1ms)）；看门狗在 building 标志置位期间豁免心跳判定；或基线构建改为惰性/降级（失败不致命，巡检有签名验证兜底）。

### R6【低】 SecurityDashboard 拖拽帧内仍逐帧 clip-path（60fps）

- 位置：`SecurityDashboard.vue`（tiltLoop）+ `dashboard.css`（.bs-survey--lit）
- 证据：已从 250Hz 同步直写降为帧内合并（F5），但 `clip-path: inset(…var(--posw))` 本身仍为重绘属性——拖拽期每帧整层重栅格化 .bs-survey--lit 层。
- 影响判定：低～中；拖拽固有行为，60fps 单层重栅格化在现代 GPU 可承受，但在 R1~R4 满载时推波助澜。
- 修复方向（建议）：潮汐亮层改更廉价实现（两层同源 SVG 以 mask/宽度推进）或降 clip-path 精度更新频率。

### R7【低】高频轮询与监听盘点（非主因，归档）

- `useDefenseStatus` 60s 防御轮询（低频，无害）
- `useSessionTimer` 1s 会话显示 tick（低频，无害）
- `useGlobalIdleScheduler` pointermove 全局监听走 500ms 节流（R5 注释自证，无害）
- `clipboard_guard` 消息循环 / `usb_guard` shadow-timer 1s 轮询（Rust 独立线程低频，无害）
- lock_monitor 5s 锁监控（独立线程，无害）
- `vTip` 全局指令 mouseenter/mouseleave（轻量，无害）

## 五、建议修复优先级

1. **R1（窗口配置）**——移除透明窗口或移除强制 GPU 光栅化参数；一步到位，直接消除"全卡无法关闭"的最强致因。
2. **R2（WebGL 常驻）**——管理区/低档位暂停或降载全屏粒子。
3. **R3+R4（双 Canvas 并存）**——进入管理中枢时与 R2 互斥或降密度、提前降档。
4. **R5（基线构建）**——分片让步 + 构建期看门狗豁免。
5. R6 拖拽 clip-path 降本（可后置）。
