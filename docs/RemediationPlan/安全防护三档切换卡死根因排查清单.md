# 安全防护三档切换卡死 — 系统性根因排查清单

> 状态：排查完成（只读取证，未改任何代码）
> 时间：2026-09-23
> 问题现象：中枢安全防护三档切换（点击锚点 / 拖动滑块）瞬间全应用卡死，所有功能不可用

---

## 一、结论速览（答复三假设）

| 假设 | 判定 | 依据摘要 |
|---|---|---|
| H1：transparent + 强制 GPU 光栅化 → WebView2 GPU 进程不稳定 | **主根因 · 成立** | 窗口配置三参数齐备；双显卡机型；崩溃转储为空（挂起非崩溃）；后端日志全程健康 |
| H2：存在其它问题（渲染爆发放大因素） | **放大因素 · 成立** | 交互首帧唤醒全屏 WebGL 60fps 满 DPR + 拖拽逐帧 clip-path 重栅格化 + 全幅面氛围过渡 |
| H3：三档切换组件本身的问题 | **排除（逻辑层）** | 点击/滑动全链路有界（8s/5s 超时）、IPC 异步不阻塞 JS 主线程、卡死期间后端命令全部快速成功 |

**一句话根因**：在「透明分层窗口 + 强制 GPU 光栅化 + 零拷贝 + 忽略 GPU 阻断列表」的脆弱合成底座上，点击/滑动的第一毫秒触发全局空闲调度器把全屏 WebGL 粒子引擎从 idle 5fps 瞬间拉到 active 60fps 满 DPR，叠加拖拽期逐帧 clip-path 重栅格化与全幅面氛围过渡——GPU 工作负载尖峰击穿 WebView2 GPU 进程的稳定边界，GPU 进程挂起（stall），合成器停摆，整个渲染进程冻结，表现为全应用卡死（含关闭按钮，因关闭链路也要经前端 IPC）。

---

## 二、排查方法论

假设驱动 + 六层取证，每层证据独立交叉验证：

1. **配置层**：窗口透明/合成参数、浏览器启动参数
2. **环境层**：GPU 硬件拓扑（双显卡）、驱动 TDR 事件、WebView2 崩溃转储
3. **组件层**：三档切换点击/滑动全链路代码走读（事件 → 状态 → IPC → 回落）
4. **引擎层**：每帧渲染引擎（WebGL / Canvas / CSS 变量驱动）在交互瞬间的行为
5. **后端层**：Rust 命令实现、锁与超时、运行时日志时序
6. **实证层**：运行日志与卡死时段对齐、崩溃转储存在性判定

## 三、H3 排除证据（组件逻辑层：非冻结根因）

三档切换完整链路走读结果——全部有界、无同步阻塞、无死循环：

| 环节 | 位置 | 走读结论 |
|---|---|---|
| 按下/拖动 | SecurityDashboard.vue onTrackPointerDown/Move/Up | 按下一次缓存布局；拖拽期间零布局读取；帧内合并 DOM 直写（F5 修复在码） |
| 点击吸附 | usePreset.ts snapToAnchor | presetApplying 防重入守卫，立即返回 |
| 应用预设 | usePreset.ts onApplyPreset | `withTimeout(applySecurityPreset, 8000)` 8 秒超时兜底 |
| 会话层 | security-session.ts applySecurityPreset | CUSTOM 高安全路径 3s 超时；标准档先调后端成功后改前端 |
| IPC 本体 | verthys.ts securityApplyPreset | `ipc("security_apply_preset")` 为 Tauri 异步 invoke，**不阻塞 JS 主线程** |
| 后端命令 | src-tauri preset.rs security_apply_preset | 会话授权 → 原子落盘 → worker 通信 5s 超时 → 失败补偿回滚；无全局长持锁 |

排除判据：

- Tauri v2 `invoke` 为异步 IPC，即使后端慢/锁竞争，JS 主线程也只会 await，**不会冻结渲染进程**——组件链路无论如何都制造不出"全卡死"。
- 运行日志实证：解锁、验证、落盘、切档（`security_apply_preset ... None → 0`）、会话守卫全部快速成功，无任何超时/错误——卡死期间后端零异常。
- 前序修复 F1（恢复链双触发收敛）、F2（IPC 超时兜底）、F5/F6（布局缓存/帧内合并）经核验**均在当前代码中**。

**结论：组件逻辑不是冻结根因。但组件所在的渲染层存在两个放大项（见第五节 S4/S5），属于"其它问题"的一部分。**

## 四、H1 成立证据（主根因：窗口配置 + GPU 进程稳定性）

### 4.1 配置层证据

位置：`verthys-tauri/src-tauri/tauri.conf.json`（L20-26），与卡死症状逐条对应：

- `"transparent": true` + `"decorations": false` → Windows 下走 **DWM 分层窗口合成路径**。该路径下 WebView2 的部分硬件合成优化受限，且与 GPU 进程的呈现模型存在已知兼容性风险域。
- `--enable-gpu-rasterization` → **强制 GPU 光栅化**；
- `--ignore-gpu-blocklist` → **无视 GPU 阻断列表**（本应禁用的不兼容适配器也强制启用）；
- `--enable-zero-copy` → 强制零拷贝上传，分层窗口下收益未知、风险显著；
- `--js-flags="--max-old-space-size=1024 --expose-gc"` → 堆上限 1GB（放大项的放大器，见 S6）。

### 4.2 环境层证据（本机实测）

- 机型：**ASUS TUF Gaming F15**，双显卡拓扑——NVIDIA GeForce RTX 3050 Laptop GPU + Intel Iris Xe Graphics。WebView2 GPU 进程的适配器分配 + 透明分层窗口跨适配器合成，正是 GPU 进程挂起的已知高发场景。
- 系统事件日志：**无 Display 4101 TDR 事件**（显卡驱动重置）→ 排除驱动级崩溃，指向更上层的软件栈挂起（WebView2 GPU 进程无响应但未触发驱动重置）。
- WebView2 崩溃转储：`%LOCALAPPDATA%\com.verthys.app\EBWebView\Crashpad\reports` **为空** → 进程是 **stall（挂起）而非 crash（崩溃）**。与"界面全卡死但应用不退出、无崩溃弹窗"的症状完全吻合。
- 后端日志：卡死会话中后端命令全部快速成功（见第三节）→ 冻结点定位在**渲染栈**，不在 Rust/JS 逻辑栈。

### 4.3 机制链

透明分层合成 + 强制 GPU 光栅化 + 忽略阻断列表的组合，在常规/双显卡机型上会使 WebView2 GPU 进程长期处于不稳定运行域；一旦 GPU 工作负载出现尖峰（见第五节 S2→S4 的交互爆发），GPU 进程挂起 → 合成器停摆 → 渲染进程主线程不再调度帧与事件 → **全应用冻结，关闭按钮同样失效**（关闭链路 CloseRequested 需前端 IPC 响应，前端不响应仅剩 45s 兜底）。

## 五、H2 成立证据（放大因素：交互瞬间的渲染爆发）

这些因素单独存在只造成掉帧，但与 H1 底座叠加后成为击穿 GPU 进程稳定边界的负载尖峰：

| 编号 | 放大因素 | 位置 | 证据 |
|---|---|---|---|
| S1 | 交互即唤醒全屏 WebGL 满帧 | useGlobalIdleScheduler.ts L42-48 / L85-96；ParticleBackground.vue | `pointerdown`/`pointermove` 等事件**立即**将空闲档位置 active（节流仅对已 active 态生效）。点击/滑动的第一毫秒，底层 4600 粒子 WebGL 引擎（`high-performance`、active 档 60fps 满 DPR）从 idle 5fps 瞬间满载——**GPU 尖峰与用户操作同帧叠加** |
| S2 | 拖拽逐帧 clip-path 重栅格化 | SecurityDashboard.vue tiltLoop L537-551；dashboard.css L290 | 拖拽期每帧写入 `--posw` → `clip-path: inset(...)` 逐帧变化（`.is-dragging` 关过渡），每帧整层重栅格化亮层（前序清单 R6 残留） |
| S3 | 氛围模式全幅面过渡 | usePreset.ts presetAmbienceMode；dashboard.css L40-73 | 滑块跨 25/75 阈值即切换 `ambience-performance/balanced/secure` 类，`.ambience-glow` 全幅面径向渐变 `transition: background 0.8s` 逐帧重绘；双环/走线/节点同步变色过渡 |
| S4 | 节流联动 Vue 重渲染 | SecurityDashboard.vue updateFromPointer L570-574 | 拖拽期 120ms 节流写 model → 每次触发双星数值、环形 dashoffset、轨道渐变、邻近锚点高亮等整组响应式 patch，与 S2/S3 同帧叠加 |
| S5 | JS 堆 1GB 上限强制 GC | tauri.conf.json L25 `--js-flags` | 三引擎（WebGL + Canvas + DOM）长期运行堆持续增长，逼近上限时触发全量 GC 停顿，与 S1-S4 尖峰时间重合时冻结感显著放大 |

**排除项**（避免误伤）：ManagementHub（--boost/drop-shadow 引擎）与 QuantumDashboard（Canvas 物理场）在三档切换视图（detail/security 分区）中**未挂载**，与本次复现路径无关；前述 F3（drop-shadow 静态化）修复已在代码中，mgmt-hub 逐帧变量现已只驱动 opacity/stroke-width 等合成友好属性。

## 六、根因链总图

```
用户点击/滑动三档切换
        │ ① 触发（S1）
        ▼
pointerdown/pointermove → 全局空闲调度器置 active
        │                    └─ 全屏 WebGL 4600 粒子 60fps 满 DPR（idle 5fps → 满载）
        │ ② 叠加（S2/S3/S4）
        ▼
拖拽帧循环：逐帧 clip-path 重栅格化 + 全幅面氛围过渡 + 120ms Vue patch
        │
        ▼
GPU 工作负载尖峰
        │ ③ 底座（H1）
        ▼
透明分层窗口 + --enable-gpu-rasterization + --enable-zero-copy + --ignore-gpu-blocklist
（双显卡机型适配器不稳定域）
        │
        ▼
WebView2 GPU 进程 stall（挂起，非崩溃：Crashpad 空 + 无 TDR 事件）
        │
        ▼
合成器停摆 → 渲染进程冻结 → 全应用卡死（含关闭，仅剩 45s 兜底）
        │
        ▼
后端仍健康（日志实证：命令全部快速成功）—— 冻结域唯一指向渲染栈
```

## 七、修复建议（按优先级，未实施）

| 优先级 | 建议 | 理由 |
|---|---|---|
| P0 | **移除透明窗口**（改不透明 + 自绘圆角/深色底），或至少移除 `--enable-gpu-rasterization`、`--ignore-gpu-blocklist`、`--enable-zero-copy` 三个强制参数，让 WebView2 走自身稳定合成路径 | 一步消除 H1 底座，直接根治"全卡死无法关闭" |
| P1 | 交互唤醒白名单收敛：将 `pointerdown`/`pointermove` 从立即 active 改为延迟提升（先 30fps 半档，250ms 后满档），或交互路径降 DPR 上限 | 削平 S1 尖峰，保留视觉响应 |
| P2 | 拖拽期 clip-path 改造：亮层改双层 mask/宽度推进等合成友好实现，或拖拽期降低更新精度 | 消除 S2 逐帧重栅格化 |
| P3 | 氛围类切换延迟到松手成功后触发；拖拽期间禁用 `.ambience-glow` 过渡 | 消除 S3/S4 峰值叠加 |
| P4 | 评估移除 `--js-flags` 1GB 堆上限（或调高/移除 `--expose-gc`） | 消除 S5 强制 GC 停顿源 |

不动的部分：组件逻辑链路（H3 已排除）、后端命令（日志健康）、已落地的 F1-F6 修复。

## 八、修复后验证矩阵（供复测存档）

1. 冷启动 → 解锁 → 进入安全防护分区 → 点击三档锚点各 5 次：不卡、不冻、档位标签即时更新。
2. 拖动滑块跨 0/50/100 全程来回 10 次（含快速甩动）：帧率稳定，无 100ms 以上停帧，无全窗口冻结。
3. 卡死验证核心项：切档瞬间快速点击"立即锁定"与窗口关闭按钮，均应立即响应（原卡死时二者必死）。
4. 观察 10 分钟（含失焦再聚焦、窗口最小化恢复）：GPU 进程存活（任务管理器 msedgewebview2 GPU 子进程无消失/挂起）。
5. 复核 WebView2 Crashpad 目录与系统事件日志：无新增 stall 特征（理论上 P0 落地后不再出现挂起）。
6. 门禁全绿：vue-tsc / vitest / npm run build / src-tauri 测试 / worker 测试 / run_ci。
