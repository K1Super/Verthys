# 防截屏与隐私保护总修复方案

> 定位：本文件集内防截屏与隐私保护方向的唯一总方案。由上传方案的逐条评审产出，
> 已按本项目实际实现逐条校正；既是评审结论，也是可直接施工的执行文档。
> 前提：既有加载、导入、导出链路的修复已核实落地。本方向无数据模型变更、
> 无存量数据迁移；构建与部署由项目方执行。

---

## 一、评审结论与校正裁定

上传方案的骨架（令牌三态、原子应用回滚、状态机单飞、隔离与对账、审计扩展块、
前端单例）成立，予以采纳。以下条目经代码核实后必须校正，否则会与本项目实现
冲突或引入新缺陷。

| 方案条目 | 本项目实际 | 裁定 |
| --- | --- | --- |
| 审计"格式标识 + 独立扩展块 + JSON 规范化" | 审计实为 HMAC 链式：`hmac = HMAC(密钥, 事件 JSON ‖ 前驱 hmac)`，行式追加，序列化为 serde 字段序 | 保留链式结构；扩展信息作为事件内的**可选**字段追加（`skip_serializing_if`），历史条目序列化字节不变。不引入格式号、不引入规范化器 |
| "配置文件不再声明窗口，全部窗口由工厂创建"（称影响托盘/单实例/深链/启动画面） | 配置声明唯一主窗口；**不存在**托盘、单实例、深链、启动画面；无动态建窗代码。Tauri 在 `setup` 钩子之前按配置建窗（已核 tauri 2.11.5 源码 `app.rs::setup`） | 不做统一工厂。配置加 `visible:false`，启动序列在**显示之前**完成保护与回读；不变式由"唯一窗口在显示前完成保护"承担 |
| 工厂失败路径"句柄释放是否销毁窗口"待核对 | Tauri 2 中句柄释放不销毁系统窗口（`destroy()` 才销毁） | 语义确认为真；校正后无工厂路径，不需要显式销毁分支 |
| 剪贴板"剥离为独立命令，自然归属清藏模块" | **无清藏模块**；前端无剪贴板监听入口；`ClipboardGuard::write_sensitive` 无调用方；监听仅由隐私模式启停 | 剥离成立；归属改为既有安全档位命令（`security_session_set_high_security`，由安全预设驱动）。**不新增**无消费者的命令与前端包装 |
| 恢复对话框用"内部窗口（前缀豁免）"承载 | 无任何第二窗口，也无前端多窗口入口 | 不新建窗口。启动期回滚失败用原生对话框（重试对账 / 退出）；运行期隔离用应用内恢复对话框 |
| 对账"回滚失败路径按 stuck 清单操作" | stuck 清单只含**还原失败**的窗口，其余窗口在还原成功前可能从未被保护 | 对账一律**全窗口重扫**；stuck 清单只入审计。杜绝"已启用但窗口裸奔" |
| 前端 `try/catch` + 抛出错误码 | 命令统一返回结构化结果（`ok` + `error_code`），`ipc()` 仅在命令返回 `Err` 时抛出 | 保持结果式契约，前端按 `error_code` 分支，不改变既有调用习惯 |
| 方案未覆盖：默认开启 | 现状为手动开启，且模块卸载时会关闭保护 | 防截屏**默认开启**（用户决策：启动一律自动施加，不依赖意图文件、无需手动开启）；移除模块卸载即关闭行为 |
| 方案未覆盖：限流粒度 | 单一 10 次/分钟桶同时锁住开启与关闭 | 按方向分离：开启 10/分、关闭 60/分、采纳 10/分、对账 5/分；状态查询不限 |
| 方案未覆盖：既有缺陷 | 见下 | 全部纳入本方案 |

既有缺陷（本次一并根治）：

1. **关闭令牌在校验时即消费**：关闭失败后凭证已丢，用户无法重试，只能重启。
2. **重启恢复后前端无凭证且无路径接管**：恢复过程生成令牌但不返回给前端；
   前端亦无状态查询命令，界面与后端状态脱节。
3. **`restore_privacy_mode` 前端从未调用**：持久化状态实际不会被恢复（该机制后
   随"启动默认开启"决策整体移除）。
4. **`partial_protection` 把剪贴板失败算作"部分保护"**：掩盖了"保护只有整体成败"的语义。
5. **隐私事件记在剪贴板事件名下**（`CLIPBOARD_MODE_CHANGE`），审计归名错误。
6. **关闭撤销后窗口状态未知**：还原失败时无隔离、无对账，界面仍可能显示"已保护"。

## 二、施工总纲

1. **一处定义、一处消费**：窗口亲和性原语只在安全层定义；限流组件只在工具层定义，
   各命令按实例分离。不引入无人读取的持久化状态与无消费者的包装。
2. **整体成败**：窗口亲和性不提供"部分保护"结果。任一目标窗口失败即整体失败并逆序还原；
   还原本身失败即进入隔离，禁止静默重试。
3. **凭证化**：关闭需授权凭证；成功后即失效、失败后可重试、不可重复使用、
   不可由无授权路径签发。
4. **默认开启、可见前保护**：每次启动一律自动施加保护（无需手动开启）；主窗口在保护生效并通过回读之前不可见。
5. **无轮询、无死代码**：状态变更由用户操作与窗口生命周期驱动，不引入定时轮询；
   被本方案取代的实现必须删除，不留悬空导出与陈旧注释。

## 三、窗口亲和性原语与能力降级

### 缺陷实质

现有封装把"设置成功"当作布尔结果，无法读取窗口当前原始取值。回滚只能把取值
设为目标值的反面，而不是变更前的实际值；若原值是"仅监视器"（旧系统降级模式），
还原会把它错误地写成"无保护"。

### 改法

安全层新增独立模块（`verthys-tauri/src-tauri/src/security/window_affinity.rs`），
提供原始取值读写与能力判定；布尔语义仅作为包装，不再作为回滚依据：

```rust
pub const WDA_NONE: u32 = 0x00;
pub const WDA_MONITOR: u32 = 0x01;
pub const WDA_EXCLUDEFROMCAPTURE: u32 = 0x11;

/// 旧系统不支持捕获排除时降级为仅监视器（捕获结果中呈现为空白矩形，内容仍不可见）。
pub fn protection_value() -> u32 {
    protection_value_for(supports_exclude_from_capture())
}

pub fn set_raw_affinity(hwnd: isize, value: u32) -> Result<(), String>;
pub fn get_raw_affinity(hwnd: isize) -> Result<u32, String>;
```

同时删除安全层内从未被引用的 `WindowPrivacyGuard` 状态机与其私有状态枚举
（原设计试图以布尔状态机约束取值，正是本缺陷的来源）。

### 测试与验收

- 单元：`protection_value_for(true) == WDA_EXCLUDEFROMCAPTURE`、`(false) == WDA_MONITOR`；
  常量取值与系统定义一致。
- 验收：旧系统上启用保护后，捕获结果中窗口为空白矩形而非内容。

## 四、凭证槽位

### 目标行为

| 操作 | 空 | 待采纳 | 生效（无未决租约） | 生效（有未决租约） |
| --- | --- | --- | --- | --- |
| 校验 | 凭证无效 | 凭证无效 | 占用租约 | 租约悬挂 |
| 提交 | 租约过期 | 租约过期 | 租约过期 | 世代匹配则消费至空，否则过期 |
| 释放 | 无操作 | 无操作 | 无操作 | 世代匹配则清除占用 |
| 签发 | 进入生效 | 不变式违反 | 不变式违反 | 不变式违反 |
| 采纳 | 未恢复 | 进入生效并返回明文 | 已采纳 | 已采纳 |

要点：

- 只存摘要（`SHA-256(明文)`），不存明文；明文只在签发/采纳的返回中出现一次。
  后端因此不再持有敏感驻留，原"panic 清零器"注册随之删除。
- 校验即占位（租约），提交才消费；释放保留摘要供重试——修复"关闭失败即失去凭证"。
- 世代号只增不减；提交与释放都校验租约世代，杜绝跨世代误消费。
- 采纳即轮换：待采纳条目在采纳时签发新明文并进入生效态，旧世代立即失效。

### 改法

`verthys-tauri/src-tauri/src/controller/privacy_controller.rs`：

```rust
pub struct TokenSlot {
    state: SlotState,
    next_generation: u64,
    next_lease_id: u64,
}

enum SlotState {
    Empty,
    PendingAdoption { generation: u64 },
    Active { generation: u64, digest: [u8; 32], lease: Option<u64> },
}

impl TokenSlot {
    pub fn rotate(&mut self) -> Result<(String, u64), PrivacyError>;
    pub fn verify(&mut self, plaintext: &str) -> Result<Lease, PrivacyError>;
    pub fn commit(&mut self, lease: &Lease) -> Result<(), PrivacyError>;
    pub fn release(&mut self, lease: &Lease);
    pub fn mark_pending_adoption(&mut self) -> u64;
    pub fn adopt(&mut self) -> Result<(String, u64), PrivacyError>;
    pub fn reset_to_empty(&mut self);
}
```

明文令牌由工具层 CSPRNG 生成（`util::random::random_hex(32)`）；比较使用常量时间实现。

### 测试

消费后重用返回凭证无效；悬挂后再次校验返回租约悬挂；释放后可重试且世代不变；
跨世代提交返回租约过期；重复采纳返回已采纳；空态采纳返回未恢复；非空态签发返回不变式违反；
世代号跨空态不回退。

## 五、原子应用与逆序还原

### 目标行为

收集目标窗口 → 逐个读取原始取值快照 → 逐个设置并回读校验 → 任一步失败即按快照
**逆序还原**。所有失败路径统一走还原逻辑，不用提前返回的错误传播；还原以各自
快照的原值为准。

### 改法

```rust
struct WindowSnapshot { label: String, hwnd: isize, original: u32 }

struct ApplyFailure {
    cause: PrivacyError,
    rollback_failed: bool,
    /// 仅还原失败时非空：未能回到原值的窗口现场（仅入审计）。
    stuck: Vec<WindowSnapshot>,
}

fn apply_atomic(&self, targets: &[WindowTarget], value: u32)
    -> Result<ApplySuccess, ApplyFailure>;
```

快照阶段失败（无副作用）与设置/回读失败（已还原）都表现为"已还原"结果：
窗口世界回到变更前，用户可重试；还原失败进入隔离。

### 测试

设置失败 / 回读失败 / 回读不匹配三条路径都断言已应用窗口全部还原且结果不报"部分保护"；
快照原值为"仅监视器"的窗口还原后仍为"仅监视器"；还原二次失败进入隔离且现场非空。

## 六、并发模型

### 状态机即单飞

过渡标记不设第二份原子量。`Transitioning` 变体本身就是单飞的唯一实现：

```rust
enum PrivacyState {
    Disabled,
    Enabled { generation: u64, protected: Vec<ProtectedWindow> },
    Transitioning { transition_id: u64, target: bool, previous: StableState, started_at: Instant },
    Quarantined { previous: StableState, reason: QuarantineReason, stuck: Vec<WindowSnapshot>, since: Instant },
}
```

- 每次过渡分配单调递增身份号；提交前校验身份仍是自己，否则只写审计、不碰状态。
- 过渡全程运行于阻塞池（`spawn_blocking`）：请求被取消时阻塞任务仍跑至终态并落状态。
- 锁只覆盖首尾两段（选路与落状态），系统调用在锁外执行。
- 身份被取代（看门狗判定卡死）时，除不落状态外还必须**释放未决租约**，
  否则凭证将永久悬挂——这是方案未覆盖的接缝，本方案补齐。
- 看门狗：状态查询与操作入口内联检查 `Transitioning` 的起始时刻，超阈值转入隔离
  （原因记录为卡死），不做后台轮询。

### 测试

并发过渡第二个返回隐私忙；被取代的过渡不覆盖状态且租约已释放；
构造超时过渡后一次状态查询转入隔离；隔离原因区分卡死与回滚失败。

## 七、启动序列（默认开启）

> 本节按用户决策修订（原方案为"意图持久化 + 记忆上次关闭"，已推翻）：防截屏是
> **启动即默认开启**的硬规则——每次启动一律自动施加保护，不依赖任何持久化意图文件，
> 也不需要用户手动开启；会话内显式关闭仅本次会话有效，重启回到默认开启。
> 原意图持久化机制（状态文件读写、旧格式迁移、相关测试）已整体移除。

### 目标行为

- 启动一律自动施加保护：**在窗口可见之前**读快照、设置、回读 → 成功则登记受保护窗口
  并显示（槽位待采纳，前端挂载后采纳取得凭证）。
- 失败且已还原：窗口正常显示，界面如实显示未保护（用户可在界面内手动开启）。
- 还原失败：隔离，不显示主窗口，弹原生对话框（重试对账 / 退出），对账成功后才显示窗口。
- 不持久化任何用户选择与凭证材料：关闭保护只在当前进程内生效。

```rust
pub enum StartupOutcome {
    /// 已保护：槽位为待采纳，前端挂载后采纳取得凭证。
    Protected { generation: u64 },
    /// 未保护：保护尝试失败且已还原（保护默认开启，不存在"按用户选择跳过"）。
    Unprotected,
    /// 需要用户驱动对账（还原失败，窗口状态未知）。
    NeedsRecovery,
}
```

启动序列运行于 `setup` 钩子（Tauri 在钩子之前完成配置建窗；此时窗口已存在但不可见）。
该阶段不接受前端命令（IPC 在钩子返回后才开始派发），因此不存在启动序列与前端查询的竞态。

### 改法

配置：`tauri.conf.json` 主窗口增加 `"visible": false`；`lib.rs` 在 `setup` 中调用启动序列，
按结果决定显示窗口、进入恢复对话框或退出。

原生对话框仅在"还原失败"这一极端状态出现：此时窗口取值未知，显示任何窗口都可能
呈现"看起来受保护、实际未受保护"，因此只给"重试对账 / 退出"两个出口，不提供绕过。

### 测试

- 单元：启动施加成功进入待采纳；失败已还原保持关闭态；还原失败进入隔离（均以假原语覆盖）。
- 集成（真机）：**每次启动窗口出现即处于保护态**（系统截图 / 录屏中窗口被排除），
  无需任何手动操作；会话内关闭后重启回到默认开启。

## 八、隔离与对账

### 目标行为

对账收敛到**失败前的稳定状态**，两个方向都不改变保护强度语义：

| 失败前状态 | 失败的操作 | 对账方向 | 效果 |
| --- | --- | --- | --- |
| 已关闭 | 开启失败 | 清除残留保护，回到关闭 | 与失败前一致 |
| 已启用 | 关闭失败 | 重新加固保护，回到启用 | 增强保护 |

- 对账**一律全窗口重扫**（见第一节裁定），失败清单只入审计。
- 对账自身单飞：进行中再次调用返回忙，不与过渡互相覆盖。
- 隔离是纯运行时状态，不持久化（进程退出后窗口亲和性随窗口消失，持久化只会
  在下次启动制造无法建窗的死锁）。
- 对账成功后：稳定状态为启用 → 重新进入待采纳（前端重新采纳取得新凭证）；
  稳定状态为关闭 → 槽位置空、状态置关闭。

### 改法（与上传方案的差异部分）

```rust
fn force_to_baseline(&self, targets: &[WindowTarget], previous: StableState)
    -> Result<(), PrivacyError>;
// 调用方传入当前全部窗口；stuck 清单不参与取舍。
```

### 测试

全窗口重扫断言（假原语记录到每个窗口都被重设）；卡死隔离后对账不做空操作；
对账至启用后槽位为待采纳；对账至关闭后槽位为空；非隔离状态对账返回非隔离；
对账并发第二个返回忙。

## 九、剪贴板剥离与归属

### 缺陷实质

隐私模式当前联动剪贴板监听，并把"监听启动失败"归入 `partial_protection`
（部分保护）。两种能力的失败模式、恢复手段完全不同，耦合使"整体成败"语义失效。

### 改法

- 隐私模式只负责窗口亲和性，不再启停剪贴板监听；`PrivacyModeResult` 的
  `partial_protection` 字段保留以维持结构稳定，其值恒为假并在注释中标注语义。
- 剪贴板监听归属到既有安全档位命令：`security_session_set_high_security`
  在设置会话高安全的同时启停剪贴板监听与"外部写入即清空"标志；
  监听启动失败如实回报错误码并写审计，不回滚已设置的高安全标志。
- 不新增独立命令：本项目没有清藏模块，也没有前端监听入口，独立命令将没有消费者。
  能力本身已解耦，若将来出现明确调用方，只需在命令层加一行包装。

### 测试

隐私模式切换不再触碰剪贴板监听（假状态断言无调用）；高安全开启后监听标记为真、
关闭后为假；监听启动失败时命令返回失败错误码且会话高安全仍为真。

## 十、前端应用级单例

### 目标行为

- 状态、凭证与单飞存放于模块级单例，不随组件挂卸变化。
- 采纳单飞：重挂载、热更新只会触发一次 IPC；启动对账读状态，需要时采纳取得凭证。
- 切换单飞：连击复用同一 Promise。
- 凭证丢失诊断：后端已启用且槽位为生效态而前端无凭证时，按钮置灰并提示重启接管；
  不提供重新签发入口（签发是无中生有的生成操作，暴露即瓦解威胁模型）。
- 模块卸载不发任何隐私命令。

### 改法

新增 `verthys-tauri/src/session/privacy-session.ts`（模块级单例）：

```ts
export function ensureAdopted(): Promise<void>;
export function togglePrivacy(): Promise<{ ok: boolean; code?: string }>;
export function reconcilePrivacySession(): Promise<{ ok: boolean; code?: string }>;
export const privacyEnabled: ComputedRef<boolean>;
export const privacyBusy: ComputedRef<boolean>;
export const privacyQuarantined: ComputedRef<boolean>;
export const privacyTokenLost: ComputedRef<boolean>;
```

- 采纳时机：主界面挂载时（与既有缓存装配同一钩子）调用一次；拾光挂载时再次调用（单飞幂等）。
- 错误码到提示的映射在拾光界面完成：已还原 → "保护失败，已还原"；隔离 → 打开恢复对话框；
  被取代 → "操作已被新的状态变更取代"；凭证缺失 → "会话凭证丢失，重启应用可重新接管"。
- 拾光按钮：`busy` 或 `tokenLost` 时禁用并使用禁止光标；隔离时点击打开恢复对话框。
  按钮在任何状态均无阴影。

### 测试

连击十次只发一次 IPC；双挂载只发一次采纳；隔离错误返回隔离码；组件卸载不发隐私命令；
凭证丢失时按钮禁用（状态派生断言）。

## 十一、审计扩展块与事件归名

### 缺陷实质

隐私事件当前记在 `CLIPBOARD_MODE_CHANGE` 名下；且缺少过渡身份、世代、回读值等
可追溯信息。

### 改法

- 事件类型改为归名正确的 `PRIVACY_MODE_CHANGE` / `PRIVACY_QUARANTINE` /
  `PRIVACY_RECONCILE`；`CLIPBOARD_MODE_CHANGE` 变体保留（历史日志反序列化兼容），
  标注为历史事件、不得用于新写入。
- 扩展块作为事件的可选字段追加，序列化时字段为空即跳过，历史条目重新序列化
  字节不变、链式校验不变：

```rust
#[derive(Default, serde::Serialize, serde::Deserialize)]
pub struct AuditExtensions {
    #[serde(skip_serializing_if = "Option::is_none")] pub generation: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")] pub lease_id: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")] pub transition_id: Option<u64>,
    #[serde(skip_serializing_if = "Option::is_none")] pub affinity_readback: Option<u32>,
    #[serde(skip_serializing_if = "Option::is_none")] pub rollback: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub stuck_windows: Option<usize>,
    #[serde(skip_serializing_if = "Option::is_none")] pub adoption: Option<String>,
    #[serde(skip_serializing_if = "Option::is_none")] pub reconcile: Option<String>,
}
```

不引入格式标识字段：判别依赖字段存在性即可，且当前实现只在事件对象内扩展，
格式号属冗余（第一节裁定）。

### 测试

历史条目（无扩展字段）校验通过且与新代码写入的记录可混链；
含扩展字段的记录校验通过；删除扩展字段后校验失败（链式传播）。
