# 存签 · 枢钥 统一改造生产方案

> 状态：**待评审（未获批准前不得动任何代码）**
> 适用范围：存签模块类型化改造 + 枢钥模块合并移除 + 模块密钥精简 + 卡片标识与高级筛选
> 前置约束（用户已明确）：**项目未发布 → 不需要任何数据迁移**；**枢钥模块整体移除，其"新增密钥/证书"并入存签新增流程；certs 模块子密钥不再保留**

## 0. 总览与阅读指南

### 0.1 一句话目标

把「存签」与「枢钥」两个高度重复的模块**合并为一个类型驱动的条目库**：新增时**先选类型** → 打开**该类型对应的编辑窗口** → 保存；卡片**尺寸与样式不变**，仅按类型改变展示内容，并在**右上角**显示类型标识；提供**高级筛选**（隐藏式面板，不做常驻筛选条）；内置常用类型并支持**高自由度自定义类型**；随后**整体移除枢钥模块**与其模块子密钥。

### 0.2 范围

| # | 在范围内 | # | 不在范围内 |
|---|---|---|---|
| 1 | 统一条目数据模型（类型 + 字段信封） | 1 | 任何数据迁移／兼容旧格式分支（未发布，零迁移） |
| 2 | 类型注册表（内置 + 自定义，单一来源） | 2 | 拾光 / 清藏 / 钥域 / 中枢 的既有行为 |
| 3 | `+` → 类型选择台 → 类型化编辑窗口 → 保存 | 3 | 加密容器与 C 内核算法层改动 |
| 4 | 卡片右上角类型标识 + 按类型内容展示（尺寸样式不变） | 4 | 主题／设计体系更换（本轮不做新模块主题） |
| 5 | 高级筛选（类型／到期／独立加密／排序） | 5 | 云端／联网类功能 |
| 6 | 自定义类型管理（增删改 + 字段构建器） | 6 | 已废弃的 `TYPE_ACCOUNT_LIST / LEGACY` 与 certs 旧格式清理（列于 P6，**另行确认**） |
| 7 | 枢钥模块整体移除（导航/映射/密钥/组件/常量/测试） | | |

### 0.3 术语

- **条目（Item）**：统一库中的一条记录，等同今天的一条 `TYPE_ACCOUNT` 记录。
- **类型（Kind）**：条目的种类标识（账号／身份证／密钥／自定义…）。
- **类型定义（VaultTypeDef）**：一种类型的声明（字段清单、卡片视图、主标题字段、图标与色调）。
- **精简模块密钥**：合并后统一模块只保留 **一个** 模块密钥（原 `accounts`），原 `certs` 子密钥不再保留。

### 0.4 阅读顺序

§1 现状与影响面 → §2 不变量（红线）→ §3 数据模型 → §4 密钥统一 → §5 交互流 → §6 卡片视图 → §7 高级筛选 → §8 移除清单 → §9 文件清单 → §10 测试矩阵 → §11 风险登记 → §12 分期与门禁 → §13 回滚 → §14 验收标准。

### 1.4 密钥机制事实（决定"子密钥不保留"的可行性）

| 事实 | 位置 |
|---|---|
| GMK **永不离开 worker**；前端通过 `derive_module_subkey` 获取模块子密钥 | `verthys-worker/src/runtime/gmk.rs:L46` |
| 子密钥派生：`HKDF(GMK, info = "verthys/module/" + module_id)` | `gmk.rs:L35`、`L361-L399` |
| 模块密钥记录按 `moduleId` 存于 `TYPE_MODULE_KEY`，支持版本化与自愈清理 | `key/module-auth.ts:L122-L176` |
| 模块密钥写入命名 `module-key-${moduleId}` | `key/module-auth.ts:L518-L583` |

**结论**：子密钥是**按 module_id 确定性派生**的，因此"合并后只保留一个模块密钥"在机制上天然成立——统一模块固定使用 `accounts` 一个 module_id 即可；`certs` 不再出现在任何模块清单与映射中，其子密钥**自然不再被派生**（无需算法层改动）。

**★A 已核验（P0 结论，2026-10-19）**：记录写读 API `verthysAddRecord(type, name, dataB64)` 与 `getRecordsDataB64Batch(ids)` **均不携带 `module_id` 参数**（`lib/verthys.ts:L504-L520`、`cache/composition/verthys-cache.ts:L282-L285`；worker 侧落到 `Verthys_AddRecord`，`verthys-worker/src/runtime/worker.rs:L489-L495`）⇒ **载荷加密由容器层统一承担，模块密钥仅是"进入模块的闸门"**。
**因此合并后不涉及任何重新加密**，只需移除 `certs` 闸门；统一模块固定使用 `accounts` 一个 module_id 即可。

## 3. 数据模型（全新定义）

### 3.1 条目信封

```ts
/** 统一条目载荷：类型 + 字段值（字段值一律字符串，便于掩码与序列化） */
export interface VaultItemPayload {
  kind: string;                    // 类型 id：内置 id 或 'custom:<uuid>'
  data: Record<string, string>;    // 该类型各字段的值（键 = 字段 id）
}
```

- 序列化：`serializeVaultItem(payload)` → JSON → base64（复用既有 `serializeToJsonB64` 能力）。
- 反序列化：`deserializeVaultItem(b64)` → 校验 `kind` 存在且为字符串，`data` 为字符串字典；非法输入 → 返回 `{kind:'account', data:{}}` 兜底并记录告警（**不是迁移**，是防损坏输入的健壮性）。
- 账号类型（`kind:'account'`）的字段 id 与今天的 `AccountFields` **一一对应**：`platform / username / password / note / encrypted / encKey`（`encrypted` 以 `"1"/"0"` 表示），确保账号类型的功能与体验零回归。

### 3.2 类型注册表（单一来源）

新增 `src/constants/vault_item_types.ts`：

```ts
export type VaultFieldKind = "text" | "password" | "date" | "multiline" | "select" | "switch";

export interface VaultFieldDef {
  id: string;                 // 字段 id（稳定，不可改）
  label: string;              // 字段显示名
  kind: VaultFieldKind;
  required?: boolean;         // 必填
  sensitive?: boolean;        // 敏感 → 卡片掩码 + 查看需解密
  options?: string[];         // select 选项
  multilineRows?: number;     // multiline 行数
  hint?: string;              // 字段说明（可选）
}

export interface VaultTypeDef {
  id: string;                 // 'account' | 'custom:<uuid>' | …
  label: string;              // 类型名（卡片标识、筛选、编辑窗口标题都用它）
  icon: string;               // 内联 SVG（与模块导航同风格的描边图标）
  tone: string;               // 类型色调 token 名（用于右上角标识与强调）
  titleField: string;         // 卡片主标题取哪个字段
  cardFields: string[];       // 卡片次行展示字段（≤3）
  searchFields: string[];     // 参与搜索的字段
  fields: VaultFieldDef[];    // 字段清单（顺序=表单顺序）
  builtin: boolean;
}
```

**约束**
- 内置类型为**编译期常量**，不可被用户改写（可隐藏，不可删改字段语义）。
- 自定义类型与内置类型**同构**：UI 完全由 `VaultTypeDef` 驱动，新增类型=新增数据，不新增代码分支。
- 字段 id 全局唯一约定：内置前缀 `f_`，自定义由用户填名称生成 slug（冲突时加序号）。

### 3.4 自定义类型

- **能力**：自定义名称、图标（从内置图标集中选）、色调、字段清单（增删排序）、每字段的 `label / kind / required / sensitive / options`、主标题字段与卡片展示字段。
- **校验**：名称非空且唯一；字段 ≥1；字段 label 唯一；必须指定主标题字段。
- **持久化**：容器内**一条专用设置记录**（类型 id = `TYPE_VAULT_TYPES = 0x0A`，仅此一条，见 §3.5），内容 = 自定义类型数组（`VaultTypeDef` 的可序列化子集）。
- **读写**：走既有记录读写与 flush 路径（`verthysAddRecord` / 删除旧 + 新增）；**不引入新的落盘旁路**。
- **删除语义**：删除自定义类型时，若已有该类型条目 → 二次确认并给出条目数量；删除类型**不删除条目**，条目降级为"未知类型"按 §6.5 兜底展示（可再指派类型）。

### 3.5 记录类型 id 策略

- 所有统一条目继续使用 `TYPE_ACCOUNT = 0x02`（**不新增、不重分配**，见 INV-8）。
- 自定义类型定义记录：使用 **`TYPE_VAULT_TYPES = 0x0A`**（P0 核验结论：`record_types.ts` 已占用 0x01–0x09、0x10–0x13、0x20、0x21；按该文件既定分区「预留扩展 0x08–0x0F」，**0x0A 为空闲值**。`core/include/verthys.h` 的 `VerthysRecordType` 仅作标签集合、未见按值校验逻辑，故前端新增标签无需 C 层改动）。
- 被移除模块释放的值（`TYPE_CERT 0x11` / `TYPE_CERT_LIST 0x21` / `TYPE_CERT_LEGACY 0x06`）：**保留注释说明其历史用途与"已停用"**，不得改作它用。

## 4. 密钥统一方案

### 4.1 目标

统一模块只保留 **1 把模块密钥**（`accounts`）；`certs` 子密钥不再派生、不再有登录/校验入口。

### 4.2 机制（已核验）

- 子密钥 = `HKDF(GMK, "verthys/module/" + module_id)`，GMK 不出 worker（`gmk.rs:L35/L46/L361-L399`）。
- 模块密钥记录按 `moduleId` 读写（`module-auth.ts:L122-L176 / L518-L583 / L594-L618`）。
- ⇒ 只要 `certs` 不再出现在模块清单与映射中，其子密钥**不会被派生**；算法层零改动。

### 4.3 执行动作

1. `useModuleNavigation.ts`：`KEY_REQUIRED_MODULES`、`MODULE_ID_MAP` 移出 `certs`。
2. `key_manager_const.ts`：`MODULE_IDS` / `MODULE_LABELS` 删除 `certs`。
3. `module-auth.ts`：**通用逻辑保留**（它按 id 工作，不硬编码 certs）；仅停止对 `certs` 的调用。
4. 若容器内已存在 `module-key-certs` 记录（开发期残留）→ P5 清理（因未发布，属清理而非迁移）。

### 4.4 不变量

- INV-3（只留一个模块密钥）；`photos / verthys` 两模块密钥**不受影响**。
- 统一模块的密钥闸门行为与今天的存签**完全一致**（进入模块 → 校验模块密钥 → 失败兜底流程不变）。

### 4.5 回滚条件

若移除 `certs` 后出现"进入存签被要求两次密钥/无法进入"等闸门异常 → 立即回滚 §4.3 的 1–2 步（恢复清单与映射），并保留 `CertManager` 组件至定位完成。

## 7. 高级筛选方案

### 7.1 形态（关键：不做常驻筛选条）

- 搜索栏右侧新增**筛选按钮**（图标 + 当前筛选条件计数）；点击展开**筛选面板**（popover，非全屏、非弹窗体系）。
- 有筛选生效时，搜索栏内显示**一行紧凑摘要**（如 `账号 · 银行卡 +1`）与一键清除 —— **不铺开全部选项**（避免重演"9 个类型导航条占地且不美观"）。

### 7.2 筛选维度

| 维度 | 取值 | 说明 |
|---|---|---|
| 类型 | 多选：全部内置 + 全部自定义 | 主维度；与搜索叠加 |
| 到期状态 | 已过期 / 即将到期(可配阈值) / 已设到期 / 未设到期 | 仅对有日期字段的类型生效 |
| 保护状态 | 含独立加密 / 含敏感字段 / 均无 | — |
| 排序 | 最近更新 / 类型 / 名称 / 到期先后 | 影响展示顺序，不影响筛选集合 |

### 7.3 行为约定

- 面板内实时预览**结果计数**（`筛选后 N 条`）；计数为 0 时提供"清除筛选"直接动作；
- 筛选状态为模块内本地状态（不跨会话持久化）；
- 与搜索是**AND 叠加**；
- 空结果：`CosmicEmpty` + 文案「无匹配条目」+ 「清除筛选」动作。

### 7.4 性能

- 筛选在**已加载内存数据**上做（贯穿 `filteredAccounts` 同层），不触发额外 IPC；
- 虚拟滚动阈值与参数不变（INV-1）；筛选结果集变化仅替换渲染数组引用。

### 7.5 不变量 / 回滚

- 不变量：INV-1 / INV-7（空态用 `CosmicEmpty`）。
- 回滚：若筛选面板与虚拟滚动组合出现定位/滚动异常 → 回滚为"仅类型单选"的简化筛选，保留数据结构。

### C.4 两类必须根治的缺陷（用户明确要求，硬性验收）

**D1 自定义类型持久化不得"只写记录不同步缓存"**
- 症状：删除/写入自定义类型时仅落盘、未同步缓存 → 缓存索引仍指向已删除的旧记录 → 重新装载后自定义类型**整体消失**。
- 要求：**删除即失效三层缓存**（`invalidateSummaryRecord` / `invalidateFullRecord` / `invalidateScannedRecord`）；**写入即回填全量缓存**（`addFullRecord` + `setModuleCache`），与 C.3-#9 同模式。

**D2 独立加密必须以"真实密文"落盘，且判据不得只看"取值是否变化"**
- 症状：编辑既有条目、新开启独立加密时，若以"取值未变即跳过加密"为判据，会把**明文**以 `encrypted: true` 名义落盘 → 查看流程按密文解密必然失败 → 用户**永远无法查看**。
- 正确判据（**必须是"既有取值本身是否已是密文"**）：
  - 既有 `encrypted === true` 且密码取值**未改动** → **保留原密文**，**不重新加密**；
  - 既有 `encrypted === false` 且**新开启**加密 → **必须加密**（无论取值是否与明文原值相同）；
  - 密码取值**已改动** → **必须按新值加密**。
- **现状代码同根缺陷（一并根治）**：编辑已加密条目时 `form.password` 此时已是**密文**，而 `L611-L613` 仍对其再次 `encryptPasswordField` → **双重加密**；且 `encrypted && !encKey` 时 `L609` **静默 return**，用户无从得知失败原因 → 必须改为窗口内联错误。
