# 身份验证窗口进度交互优化方案

## 背景与问题定义

### 现状陈述

VerifyView.vue 复用 UnlockView 的同款进度条组件 QuantumProgressFlow，但绑定的是后端真实进度（0→10→40→80→100 离散跳变）。成功路径 postVerifyAnim 立即释放视图，导致可感知故障。

### 问题本质

> 
> **用户面对的是一段"不确定的等待过程"，却被一个"确定但跳变"的信号源直接驱动，导致感知节奏与真实节奏错位。**

三个根因：

- 信号源离散：后端进度为跳变式离散值。
- 感知层缺失：无独立视觉节奏层对信号进行吸收与平滑。
- 业务与动画耦合：业务用固定延时"猜测"动画时长，方向倒置。

### 用户可感知的故障

| 故障 | 后果 |
| --- | --- |
| 进度条瞬跳 | 视觉卡顿感 |
| 成功时未补满即切视图 | 视觉断裂 |
| 失败时进度接近满值 | "虚满后报错"，信任受损 |
| 高刷屏与低刷屏体验差异 | 跨设备不一致 |
| 极慢后端下进度条"卡死" | 用户误判 App 故障 |

## 目标与非目标

### 目标

| 目标 | 衡量标准 |
| --- | --- |
| 平滑 | 真实进度跳变被感知层吸收为连续视觉变化 |
| 可信 | ACTIVE 阶段视觉值**永不到达 100%**；仅 SEALING → DONE 路径可到 100% |
| 解耦 | 业务不感知动画时长；视图切换由 onComplete 事件驱动 |
| 一致 | 帧率无关，60Hz / 120Hz / 掉帧行为一致 |
| 可维护 | 所有节奏参数集中、语义化、单点配置 |
| 可访问 | 尊重 prefers-reduced-motion |

### 非目标

| 非目标 |
| --- |
| 不改动后端进度协议（但依赖协议约束） |
| 不改动 QuantumProgressFlow 视觉样式 |
| 不引入新动画库 |
| 不改变验证业务逻辑的成败判定 |
| 不涉及 UnlockView 本身行为 |

## 术语表

| 术语 | 定义 |
| --- | --- |
| **信号层** | 后端真实进度与终结事件的来源，属业务 |
| **感知层** | 将离散信号翻译为连续视觉节奏的独立层，属动画策略 |
| **呈现层** | 只渲染、不做判断的 UI 组件 |
| **真实进度** | 后端推送进度，取值 [0, 1] |
| **显示真实进度** | 经软上限钳制后的真实进度，取值 [0, softCeiling] |
| **视觉值** | 呈现层实际渲染的进度，取值 [0, 1] |
| **假进度曲线** | 感知层内部生成的、随时间衰减逼近目标值的连续曲线 |
| **plateau** | 假进度爬升期的主要目标值 |
| **softCeiling** | 假进度曲线的绝对上限，严格小于 1 |

| **封顶期** | 假进度曲线从 plateau 缓变逼近 softCeiling 的阶段 |
| **收束** | 终结事件到达后，视觉值走向终态的过程 |
| **收束起点** | 收束动画开始时视觉值所在数值 |
| **onComplete 事件** | 成功收束完成时向业务层发出的事件 |
| **指数趋近** | 一阶指数平滑逼近方式 |

## 系统设计

### 三层架构

**第一层：信号层（业务）**

- 职责：产生真实进度、成功事件、失败事件。
- 契约：只发信号，不感知动画；不使用固定延时等待动画。

**第二层：感知层（核心新增）**

- 职责：订阅信号；维护状态机；生成假进度曲线；输出视觉值；收束完成后发 onComplete。
- 契约：
  - 只订阅信号层，**永不反向驱动业务**；
  - 对呈现层输出视觉值与阶段标识；
  - 暴露 seal / halt / reset 三个入口；
  - 保证单活跃实例。

**第三层：呈现层（UI）**

- 职责：接收视觉值并渲染。
- 契约：无状态、无判断、无计时、无业务耦合。

### 数据流

```
真实进度 ──┐
           ├──► 感知层状态机 ──► 视觉值 ──► 呈现层
成功事件 ──┤        │
失败事件 ──┘        │
                    └──► onComplete 事件 ──► 业务层（切视图）
```

### 层间耦合契约

| 内容 | 违反后果 |
| --- | --- |
| 感知层只订阅信号层，不反向驱动 | 业务被动画状态污染 |
| 业务层不使用固定延时等待动画 | 动画与业务时长硬耦合 |
| 业务层不读取视觉值做业务判断 | 隐式耦合 |
| 呈现层不含任何判断逻辑 | 无法测试、无法复用 |
| 所有节奏参数集中于单一配置源 | 调 UI 需改动多处 |
| 感知层必须在作用域销毁时清理动画帧 | 卸载后报错、内存泄漏 |

## 状态机设计

### 状态定义

| 状态 | 语义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| **IDLE** | 未启动 | 初始 / reset 后 | 挂载或启动 |
| **ACTIVE** | 活跃期（含爬升期与封顶期） | 启动 | 收到 seal 或 halt |
| **SEALING** | 成功收束中 | 收到 seal | 收束动画完成 |
| **DONE** | 成功收束完成 | SEALING 完成 | 卸载 |
| **HALTED** | 失败冻结 | 收到 halt | reset 或卸载 |

### 状态转移

```
IDLE ──启动──► ACTIVE ──seal──► SEALING ──完成──► DONE
                 │
                 └──halt──► HALTED ──reset──► ACTIVE
```

### 状态不变量

| 不变量 |
| --- |
| 视觉值 ∈ [0, 1] |
| 视觉值单调不减（reset 除外） |
| 假进度曲线在任何时刻均不超过 softCeiling |
| **视觉值到达 1.0 仅发生于 SEALING → DONE 路径；ACTIVE 阶段视觉值严格小于 1** |
| HALTED 状态下视觉值不再变化 |
| 同一时刻只允许一个感知层实例处于 ACTIVE / SEALING 状态 |
| seal / halt 指令必须幂等 |

## 详细设计

### 活跃期（ACTIVE）动画策略

活跃期包含两个连续子阶段：**爬升期**与**封顶期**。

#### 假进度曲线公式

**爬升期**

```
fake_climb(t) = plateau * (1 - exp(-approachRate * t))
```

- `t`：从启动或 reset 起算的秒数。
- 语义：快速逼近 plateau，随时间衰减。

阶段切换条件：当 `fake_climb(t) ≥ plateau * plateauReachRatio` 时，进入封顶期。

- `plateauReachRatio`：配置项，建议默认 0.95，取值域 (0.8, 1)。

**封顶期**

```
fake_creep(t2) = plateau + (softCeiling - plateau) * (1 - exp(-creepRate * t2))
```

- `t2`：从进入封顶期时刻起算的秒数。
- `creepRate`：配置项，建议默认 0.05 /s，取值域 (0.01, 0.2)。
- 语义：极缓蠕变，趋近 softCeiling 但永不到达。

连续性保证：切换时刻两段函数值连续。切换点对 `fake_creep` 起点做偏置校正：以 `fake_climb` 切换时刻的实际值为起点，向 softCeiling 蠕动。

**最终假进度曲线**

```
fake(t) = fake_climb(t)                                , t < t_switch
fake(t) = fake_climb(t_switch) + 
          (softCeiling - fake_climb(t_switch)) *
          (1 - exp(-creepRate * (t - t_switch)))       , t ≥ t_switch
```

#### 真实进度软上限钳制

```
realDisplay = min(真实进度, softCeiling)
target      = max(realDisplay, fake(t))
```

- ACTIVE 阶段，真实进度参与 target 计算前，必须先经 softCeiling 钳制。
- 只有在 SEALING 阶段，target 才被显式设为 1.0。
- 若后端真实进度到达 100% 但成功事件尚未到达，显示真实进度仍被钳制在 softCeiling，视觉值不会到 1.0。此场景记录遥测事件。

#### 视觉值指数趋近

```
display(t + dt) = display(t) + (target - display(t)) * (1 - exp(-visualDamping * dt))
```

- `visualDamping`：时间常数的倒数，单位 /s，建议默认 5.5 /s（对应时间常数约 180ms）。
- 性质：无过冲、单调趋近、帧率无关。
- 术语说明：这是**一阶指数平滑**，文档与代码命名统一使用"指数趋近 / exponential approach"。

### 成功收束（SEALING）

触发：业务层收到成功事件后，向感知层发出 seal 指令。
行为：

- 收束起点 = 当前视觉值。
- 收束终点 = 100%。
- 曲线形态：**缓出（ease-out）**，推荐 easeOutCubic。
- 时长：`sealDuration`，建议默认 520ms。
- 动画完成时：状态转 DONE，触发 onComplete 事件。

禁止：瞬跳至 100%；用固定延时替代动画完成事件；动画未完成时提前释放视图。

### 失败收束（HALTED）

触发：业务层收到失败事件后，向感知层发出 halt 指令。
行为：

- 视觉值**冻结在当前值**，不回弹、不清零、不闪烁。
- 错误提示以淡入方式覆盖。
- 进度条进入**视觉降级**：降低不透明度、灰度化或降低对比度。
- 错误最小展示时长 `errorMinDuration`，建议默认 400ms。

#### 失败冻结的视觉权重处理

即使软上限钳制生效，失败时视觉值仍可能落在较高位置。为彻底避免"虚满后报错"的信任损耗：

- 产品层约定：失败时错误提示的视觉权重大于进度条。
- 工程实现：感知层进入 HALTED 时，向呈现层输出 `dimmed` 标识；呈现层据此对进度条做视觉降级。
- 禁止：回弹、清零、闪烁、重播。
- 语义：用户感知从"白等了"转为"确实走到这一步才失败，且系统已给出解释"。

### 时间模型与并发约束

#### 时间基准

- 使用单调时间源（performance.now 等价）。
- 动画驱动基于时间差 dt，**严禁基于帧**。

#### dt 钳制

- 单帧 dt 上限钳制，建议 50ms。
- 防止后台标签页切回时进度条瞬间跳满。

#### 单活跃实例约束

感知层必须保证同一时刻只有一个实例处于 ACTIVE / SEALING。实现方式二选一：

- 方案A（推荐）：模块级单例锁。新实例启动时，若检测到已有活跃实例，先对其执行 halt 并清理，再接管。
- 方案B：上下文 token。业务层在启动新验证前，必须持有唯一 token；感知层校验 token 后决定是否接受启动。

约束：无论采用哪种方案，均须有自动化测试覆盖"并发启动"场景。

### 中断、清理与 reset

#### 中断与清理

- 作用域销毁时，必须取消动画帧调度。
- 中断策略：取消调度，状态置为 HALTED。
- 中断 ≠ 取消业务：业务请求生命周期与动画生命周期相互独立。

#### reset 语义

reset 用于失败后重试。

| 项 | 规范 |
| --- | --- |
| 状态转移 | HALTED → ACTIVE |
| 视觉值 | 重置为 0 |
| 假进度曲线时间基准 | 重置为 reset 时刻 |
| 阶段状态 | 回到爬升期 |
| 动画帧 | 若已有帧在跑，先取消再重新调度 |
| 真实进度订阅 | 保留订阅，新数据按软上限规则参与计算 |
| 幂等性 | 非 HALTED 状态下调用 reset 应被忽略 |

理由：重试是一次全新的验证过程，视觉上应从起点开始，不应从高位继续，避免"进度条悬停在高位"的怪异体验。

## 边界情况

| 场景 | 处理策略 |
| --- | --- |
| **极快成功**（后端 < fastSuccessThreshold 返回） | 按 `fastSuccessStrategy` 处理：   **skipAnimation（推荐）**：跳过进度条动画，立即触发 onComplete；   **minStartPoint**：收束起点上抬至 minSealStart，再执行收束。 |
| **极慢后端** | 假进度曲线到达 softCeiling 后保持不变，不自动到 100% |
| **真实进度回退** | 视觉值单调不减，忽略回退；记录遥测 |
| **收束期收到失败事件** | SEALING 未完成：转 HALTED，视觉值冻结；已 DONE：忽略 |
| **重复 seal / halt** | 幂等：已在 SEALING / DONE 时再次 seal 忽略；已在 HALTED 时再次 halt 忽略 |
| **并发验证** | 单活跃实例约束；新验证启动前必须 reset 或销毁旧实例 |
| **后台标签页切回** | dt 钳制保证视觉值不会瞬间跳满 |
| **ACTIVE 阶段真实进度到达 100% 但成功事件未到** | 显示真实进度被钳制在 softCeiling；视觉值不到 1.0；记录遥测事件（协议异常） |

## 配置项

所有节奏参数集中定义于**单一配置源**，禁止散落业务代码。每项参数必须有语义化命名。

| 参数名 | 语义 | 建议默认值 | 取值域 |
| --- | --- | --- | --- |
| `plateau` | 假进度爬升期目标 | 0.62 | (0, softCeiling) |
| `softCeiling` | 假进度曲线绝对上限 | 0.985 | (0.9, 1) |
| `approachRate` | 爬升期指数衰减速率 | 1.2 /s | (0.5, 3) |
| `plateauReachRatio` | 进入封顶期的判定比例 | 0.95 | (0.8, 1) |
| `creepRate` | 封顶期蠕变速率 | 0.05 /s | (0.01, 0.2) |
| `visualDamping` | 视觉值指数趋近速率 | 5.5 /s | (3, 10) |
| `sealDuration` | 成功收束时长 | 520 ms | (300, 800) |
| `sealCurve` | 成功收束曲线 | easeOutCubic | 缓出族 |
| `errorMinDuration` | 错误最小展示时长 | 400 ms | (200, 800) |
| `fastSuccessThreshold` | 极快成功判定阈值 | 150 ms | (50, 300) |
| `fastSuccessStrategy` | 极快成功处理策略 | skipAnimation | skipAnimation / minStartPoint |
| `minSealStart` | 最小收束起点（策略 B 使用） | 0.35 | (0, plateau) |

### 无障碍降级配置

检测到 `prefers-reduced-motion: reduce` 时整体降级：

| 参数 | 降级值 | 语义 |
| --- | --- | --- |
| `plateau` | 1.0 | 不使用假进度 |
| `approachRate` | ∞ | 视觉值直接等于显示真实进度 |
| `plateauReachRatio` | 1.0 | 不进入封顶期 |
| `creepRate` | 0 | 无蠕变 |
| `visualDamping` | ∞ | 无平滑 |
| `sealDuration` | 0 | 收束瞬间完成 |
| `errorMinDuration` | 保留 | 错误信息仍需可读 |

要求：降级必须整体策略替换，不得散落条件分支。

## 集成点

### 与 QuantumProgressFlow 的接口

| 项 | 规范 |
| --- | --- |
| 输入 | 视觉值（[0, 1]）+ 阶段标识（含 dimmed） |
| 输出 | 无 |
| 组件内部 | 保持无状态、无判断、无计时 |
| 修改范围 | 不修改内部实现，仅确认可复用性；如需 dimmed 支持，以样式标识传入 |

### 与业务层的接口

**业务层向感知层提供**

- 真实进度（响应式数值）
- 成功事件
- 失败事件

**感知层向业务层提供**

- **onComplete 事件的 Promise 化接口**

```
waitForComplete(): Promise<void>
```

语义：返回一个 Promise，在状态进入 DONE 时 resolve；若在等待过程中被 halt 或 reset，则 reject 或按业务约定处理（推荐 reject，附带原因）。

业务层通过 `await waitForComplete()` 等待收束完成，而非使用固定延时。

**业务层禁止**

- 使用固定延时等待动画；
- 直接读取视觉值做业务判断；
- 在 onComplete 之前切换视图。

### 与 useGlobalKey.ts / useViewMode.ts 的接口

| 文件 | 变更 |
| --- | --- |
| `useGlobalKey.ts` | onVerify 成功分支：移除固定 600ms 延时，改为 `await waitForComplete()`；失败分支：保留错误最小展示时长，值取自配置源 `errorMinDuration`（不再硬编码 400ms） |
| `useViewMode.ts` | 同步更新过时注释，说明视图切换由 onComplete 事件驱动 |

语义分离：错误最小展示时长与进度条动画时长是两个独立参数，不得共用常量。

## 验收标准

| 标准 |
| --- |
| 视觉值在任何真实进度跳变下连续变化，无可见跳变 |
| 成功路径进度条平滑补满 100% 后才切视图。例外：极快成功场景（总耗时 < fastSuccessThreshold）按 fastSuccessStrategy 处理；选择 skipAnimation 时允许跳过动画并立即触发 onComplete |
| 失败路径进度条冻结在当前值，不回弹、不清零、不闪烁，且进入视觉降级 |
| ACTIVE 阶段视觉值严格小于 1，即使真实进度推送 100% |
| 60Hz 与 120Hz 屏幕同一时刻视觉值偏差 < 1% |
| 卸载时动画安全中断，无控制台报错 |
| prefers-reduced-motion 下无假进度 |
| 业务代码中无任何动画时长常量 |
| 所有节奏参数集中在单一配置源，且均有语义化命名 |
| 极快成功场景按既定策略正确处理 |
| 错误最小展示时长与进度条动画时长语义分离、参数独立 |
| 已同步更新 useGlobalKey.ts 与 useViewMode.ts 中的过时注释 |
| 假进度曲线公式可被实现者唯一确定，plateau / softCeiling / approachRate / creepRate / plateauReachRatio 关系明确 |
| reset 后视觉值归零、假进度时间基准重置、动画帧重新调度 |
| 同一时刻仅一个感知层实例活跃 |
| onComplete 可被业务层以 Promise 形式等待 |
| 术语统一：一阶指数平滑不得命名为"临界阻尼" |

## 设计核心原则

> 
> **进度条不是"绑定后端数值的 UI 组件"，而是一台"独立的、有生命周期、只订阅不反驱的感知节奏机器"。**
> 
> 
> 动画自己知道自己何时结束，业务只负责发事件，二者通过契约而非时长耦合。
