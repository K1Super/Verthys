# 光包传播与视图切换协同优化

### 问题定义

#### 症状陈述

点击引导单元后：

- 光包沿丝链传播，设计总时长 720ms；
- 视觉上，粒子在最后一段出现**掉帧顿挫**，随后**中途消失**；
- 在 idle（5fps）/ deep-idle（1fps）档位下，自发光包呈现**爬行 + 跳步**的静止观察卡顿感。

#### 根因一：传播截断 + 渲染竞争

##### 传播截断（时序冲突）

- 光包传播总时长：720ms；
- ManagementHub.vue 在 **380ms** 就触发视图切换；
- 380 / 720 = **52.8%** → 传播仅完成约 53% 即被截断。

时序冲突的本质：**视图切换由固定延时驱动，而非由传播完成事件驱动**。

##### 渲染竞争（资源冲突）

- ManagementView.vue 使用**三个独立 `<Transition>`**，且为 in-out 并行模式；
- 离场 hub 的 Canvas 渲染仍在进行；
- 入场 detail 的挂载成本同时发生；
- `mgmt-hub.css` 中的 `filter: blur()` 逐帧对大面域重绘。

三者在同一时间段内争抢主线程与合成器资源，表现为：**粒子最后一段掉帧 → 顿挫 → 中途消失**。

#### 根因二：引擎时钟钳制

现有实现：

```
dt = Math.min(gateDt, 0.05)
elapsed += dt
```

**问题本质**：把"防止单帧跳变"与"时间正确性"混在一个钳制里。

| 档位 | 帧间隔 | 累积 gateDt | 钳制后 dt | 时钟实际流速 |
| --- | --- | --- | --- | --- |
| 正常 | 16.7ms | 0.0167s | 0.0167s | 1× |
| idle（5fps） | 200ms | 0.2s | 0.05s | **1/4×** |
| deep-idle（1fps） | 1000ms | 1s | 0.05s | **1/20×** |

后果：

- 引擎时钟变慢，动画总时长被拉长 4 倍 / 20 倍；
- 光包爬行：视觉位移速度远低于设计值；
- 跳步：每帧跨越的进度增量很大，采样点稀疏。

#### 两问题的乘性叠加

| 场景 | 传播设计时长 | 实际时钟流速 | 380ms 时实际进度 | 切换时完成度 |
| --- | --- | --- | --- | --- |
| 正常帧率 | 720ms | 1× | 380ms 进度 | 53% |
| idle（5fps） | 720ms | 1/4× | 95ms 进度 | **13%** |
| deep-idle（1fps） | 720ms | 1/20× | 19ms 进度 | **2.6%** |

**结论**：修复必须同时覆盖两个根因，单独修任何一个都无效。

#### 用户可感知的故障

| 故障 | 后果 |
| --- | --- |
| 光包中途消失 | 传播过程不完整，视觉断裂 |
| 最后一段掉帧顿挫 | 帧率不稳定，廉价感 |
| 低帧率下爬行 + 跳步 | 静止观察时卡顿感明显 |
| 切换与传播时序错位 | 用户看到"传一半就切" |
| blur 与 Canvas 竞争 | 全局渲染质量下降 |

### 目标与非目标

#### 目标

| 目标 | 衡量标准 |
| --- | --- |
| 传播完整 | 光包在任何可渲染条件下**必到达终点**并完成落定后才切视图 |
| **进度时间正确** | **在页面可见、主线程未长时间阻塞的条件下，传播进度与墙钟时间一致（±5%）；后台返回不追求进度时间正确，只追求视觉完整** |
| 渲染无竞争 | 离场 Canvas、入场挂载、blur 重绘**不得并行争抢** |
| 事件驱动 | 视图切换由**传播完成事件**驱动，不由固定延时驱动 |
| 帧率无关 | 在可渲染条件下，60Hz / 120Hz / idle / deep-idle 下传播进度一致 |
| **完成事件不提前** | **完成事件不因帧率或后台而提前触发；延迟不超过一帧** |

**进度时间正确性精确语义**：

- **进度时间正确性**：指动画进度函数 `progress = (now - startTime) / duration` 在页面可见时与墙钟一致。
- **不覆盖后台场景**：页面隐藏期间，RAF 暂停，进度不推进；返回后从暂停处**继续传播**。
- **不覆盖主线程长时间阻塞**：阻塞期间进度不推进；阻塞结束后跳至正确进度。
- **完成事件触发时长**：独立于进度时间正确性。完成事件在落定视觉呈现后触发，允许后台返回后补播落定。

**边界补充**：

> 
> 后台返回时，若传播阶段尚未完成，光包应从暂停处**继续传播**至终点，再进入落定；**不得直接跳到终点**。这是"视觉完整"的必要组成部分——用户看到的应当是一段连续的传播，而不是"消失的光包突然出现在终点"。

#### 非目标

| 非目标 |
| --- |
| 不改动丝链拓扑结构与路径设计 |
| 不改动光包的视觉样式（粒子形态、颜色、发光） |
| 不引入新动画库 |
| 不改变 ManagementView 的业务内容 |
| 不涉及帧门控本身是否应存在（只修正其与动画时钟的关系） |

### 术语表

| 术语 | 定义 |
| --- | --- |
| **传播** | 光包沿丝链从起点移动到终点的过程 |
| **落定** | 光包到达终点后，短暂的视觉收束（光晕扩散、粒子收敛） |
| **传播完成事件** | 落定视觉呈现后触发的事件，是视图切换的唯一合法触发源 |
| **墙钟时间** | 真实经过的时间，`performance.now()` 等价 |
| **帧步进时间** | 两帧之间的时间差，用于物理积分 |
| **帧门控** | 主动降帧机制（idle / deep-idle），决定"多久渲染一帧" |
| **时间流速** | 动画时间推进速率，应与墙钟一致 |
| **关键动画** | 用户交互的直接视觉反馈，可申请帧门控豁免 |
| **非关键动画** | 装饰性动画，跟随帧门控 |
| **豁免** | 关键动画临时退出低帧模式的机制，可被帧门控拒绝或降级 |
| **合成层** | 浏览器合成的独立图层，可隔离重绘 |
| **错峰** | 将渲染负载在时间上分离，避免并行竞争 |
| **可渲染条件** | 页面可见、主线程未长时间阻塞、设备未处于极端降级状态 |
| **落定逻辑完成帧** | 落定动画最后一帧的逻辑计算完成时刻（rAF 回调执行时刻） |
| **落定触发帧** | 落定逻辑完成帧的下一帧（渲染已发生） |
| **恢复宽限期** | 后台返回后，在检查加速收尾前允许的正常播放时长 |

### 系统设计

#### 三层架构

**第一层：时序编排层**

- **职责**：定义"传播 → 落定 → 切换 → 入场"的严格时序；发出传播完成事件；驱动视图切换。
- **契约**：视图切换只接受传播完成事件；不接受固定延时；不允许并行 Transition。

**第二层：渲染资源层**

- **职责**：管理 Canvas 生命周期、blur 策略、渲染预算错峰；保证任何时刻只有一个重负载渲染任务。
- **契约**：不可见的 Canvas 必须停止 RAF；blur 不参与逐帧动画；离场、过渡、入场、blur 启用分阶段串行。

**第三层：动画时钟层**

- **职责**：为所有动画提供统一的时间基准；分离墙钟时间与帧步进时间；关键动画可申请帧门控豁免。
- **契约**：时间流速恒等于墙钟；帧步进时间只用于物理积分，不用于进度计算；豁免可被拒绝或降级。

#### 数据流

```
点击引导单元
      │
      ▼
时序编排层：状态 IDLE → PROPAGATING
      │
      ▼
动画时钟层：以墙钟时间驱动传播进度
      │
      ▼
渲染资源层：光包沿丝链渲染（关键动画，申请豁免）
      │
      ▼
传播到达终点 ──► 状态 PROPAGATING → LANDING
      │
      ▼
落定逻辑完成帧 ──► 调度下一帧
      │
      ▼
落定触发帧（与传播完成事件同帧）──► 状态 LANDING → TRANSITIONING
      │
      ▼
时序编排层启动切换编排
      │
      ├─► Phase 1：hub 离场（CSS / DOM 层完成）
      │
      ├─► Phase 2：过渡间隙
      │
      ├─► Phase 3：detail 入场
      │
      └─► Phase 4：启用 blur ──► 状态 → DONE
```

#### 层间耦合契约

| 内容 | 违反后果 |
| --- | --- |
| 视图切换只接受传播完成事件 | 传播被截断 |
| 传播进度只由墙钟时间驱动 | 低帧率下时钟变慢 |
| 帧步进时间不用于进度计算 | 与墙钟驱动进度冲突 |
| 关键动画可申请帧门控豁免，但豁免可被拒绝或降级 | 低功耗设计被破坏 |
| 不可见 Canvas 必须停止 RAF | 离场 Canvas 与入场竞争 |
| blur 不参与逐帧动画 | 大面域重绘竞争 |
| 离场、过渡、入场、blur 启用不得并行 | 渲染预算超支 |
| 所有时序参数集中于单一配置源 | 调优需改动多处 |
| 状态机是所有时序决策的唯一裁决源 | 竞态与重复触发 |

### 状态机设计

#### 状态定义

| 状态 | 语义 | 进入条件 | 退出条件 |
| --- | --- | --- | --- |
| **IDLE** | 未启动 | 初始 / reset 后 | 收到点击 |
| **PROPAGATING** | 传播中 | 启动传播 | 到达终点 或 收到中断 |
| **LANDING** | 落定中 | 传播到达终点 | **落定逻辑完成帧的下一帧（与传播完成事件同帧触发）** |
| **TRANSITIONING** | 切换编排中（P1–P3） | 传播完成事件触发（与 LANDING 退出同帧） | 入场完成 |
| **ENTERING** | 入场稳定中（P4 前的等待） | 入场动画完成 | blur 启用完成 |
| **DONE** | 全流程完成 | blur 启用完成 | 卸载 / reset |
| **ABORTED** | 中断（用户返回、卸载、错误） | 收到中断 | 卸载 / reset |

**关键约定**：

- LANDING 的退出条件与 TRANSITIONING 的进入条件是**同一时刻**：落定逻辑完成帧的下一帧。
- 传播完成事件的触发时刻与该状态转移**同帧发生**，不允许分离。
- 实现者不得将 `setPhase('TRANSITIONING')` 与 `emit('complete')` 分离到不同帧。

#### 状态转移图

```
IDLE ──点击──► PROPAGATING ──到达终点──► LANDING ──落定完成帧的下一帧──► TRANSITIONING
                   │                          │                              │
                   │中断                      │中断                          │入场完成
                   ▼                          ▼                              ▼
                ABORTED                    ABORTED                        ENTERING
                                                                             │
                                                                             │blur启用完成
                                                                             ▼
                                                                           DONE
```

#### 状态不变量

| 不变量 |
| --- |
| 同一时刻只有一个状态处于激活 |
| 任何状态转移必须经合法路径，非法转移被拒绝并记录遥测 |
| IDLE → DONE 的完整流程只允许发生一次，DONE 后不接受任何转移（除卸载） |
| ABORTED 后不接受除 reset / 卸载外的任何转移 |
| 传播完成事件在 LANDING → TRANSITIONING 转移时同步发出，且只发一次，与状态转移同帧 |
| DONE 状态下所有 RAF 已停止，所有 Canvas 已卸载 |

#### 幂等与竞态处理

| 场景 | 处理 |
| --- | --- |
| 传播期重复点击 | 忽略 |
| 落定期点击其他引导单元 | 忽略 |
| 切换期点击其他引导单元 | 忽略 |
| 切换期再次收到传播完成事件 | 忽略（事件只发一次） |
| 任意状态下收到中断 | 若不在 DONE / ABORTED，转移到 ABORTED，清理资源 |
| 任意状态下卸载 | 清理资源，不再转移 |

### 详细设计

#### 时序编排层

##### 传播完成事件

**定义**：传播完成事件 = 落定动画的**逻辑计算完成后的下一帧**触发，且与 LANDING → TRANSITIONING 状态转移同帧。

**修正说明**：

- 原表述"落定动画的最后一帧渲染完成后"在浏览器中无法精确实现。
- rAF 回调在渲染前执行，无法直接知道"渲染完成"。
- 实践上采用**双 rAF**：落定逻辑完成的 rAF 回调中，再调度一个 rAF，在下一帧回调中触发事件。
- 语义调整为：**落定逻辑完成帧的下一帧触发**。
- 视觉上：下一帧时，落定动画已至少渲染过一次，用户可见落定效果。

**落定的语义**：

- 光包到达终点时，不应立即触发切换。
- 终点处有可辨识的"落定"表现：光晕扩散、粒子收敛、短暂高亮。
- 落定时长：`landingDuration`，建议默认 100ms，取值域 (60, 200)。

**事件触发时机**：

1. 传播到达终点 → 状态 PROPAGATING → LANDING；
2. 落定动画逻辑计算完成（落定逻辑完成帧）；
3. 调度下一帧（rAF）；
4. 下一帧回调中：状态 LANDING → TRANSITIONING，触发传播完成事件。

**后台场景**：

- 页面隐藏期间 RAF 暂停，落定不推进。
- **返回后，传播阶段从暂停处继续传播至终点**（不得直接跳到终点），再进入落定。
- 落定从暂停处继续，补播完整落定。
- 完成事件的触发时间因此晚于"设计时长"，但**不提前**。

**后台返回的完整行为序列**：

| 返回时的状态 | 行为 |
| --- | --- |
| PROPAGATING（未到终点） | 从暂停处继续传播 → 到达终点 → 完整落定 → 触发完成事件 |
| LANDING（落定中） | 从暂停处继续落定 → 完成落定 → 触发完成事件 |
| TRANSITIONING 及之后 | 无需特殊处理（切换编排不依赖进度时钟） |

##### 视图切换的编排

**唯一合法触发源**：传播完成事件。
**禁止**：

- 禁止使用固定延时触发切换；
- 禁止在传播进行中触发切换；
- 禁止在落定未完成时触发切换。

**编排阶段（严格串行）**：

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| P1 | hub 离场（CSS / DOM 层） | 离场动画完成 |
| P2 | 过渡间隙 | 固定 `interPhaseGap`（建议 0ms） |
| P3 | detail 入场 | 入场动画完成 |
| P4 | blur 启用 | 入场完成后延迟 `blurEnableDelay` |

**阶段间串行约束**：

- P1 未完成，P3 不得开始；
- P3 未完成，P4 不得开始；
- 任何阶段不得与其他阶段并行执行重负载操作。

##### Transition 串行化

**现状问题**：三个独立 `<Transition>` 并行（in-out）。
**修复方案**：

- **方案A（推荐）**：**单一编排控制器**。用单一状态机控制整体切换；每个 Transition 由编排控制器按阶段触发；阶段之间串行。
- **方案B**：**out-in 模式**。将三个 Transition 合并为单一 Transition，使用 `mode="out-in"`。

**禁止**：三个独立 Transition 并行 in-out。

**视觉时长预算**：

- 离场：`exitDuration`，建议默认 240ms，取值域 (180, 360)；
- 入场：`enterDuration`，建议默认 320ms，取值域 (240, 480)；
- 总切换时长 = exitDuration + interPhaseGap + enterDuration，应控制在 600ms 以内。

##### 离场动画的实现约束

**核心约束**：**离场动画必须由 CSS / DOM 层完成，不依赖 Canvas 继续出帧。**

**理由**：

- 离场开始时，hub Canvas RAF 立即停止。
- 若离场动画依赖 Canvas 继续渲染，画面会冻结。
- 因此离场动画必须使用 CSS Transition / Animation 或 DOM 属性变化实现。
- Canvas 在离场期间保留最后一帧，作为静态视觉元素参与离场。

**实现要求**：

- hub 的 Canvas 容器通过 CSS 过渡参与离场；
- Canvas 内容本身不动（保留最后一帧）；
- 离场动画作用于容器（透明度、位移、缩放）。

##### 加速收尾

**触发条件**：

- 触发源：业务层发出"数据已就绪"事件（不是超时）；
- 触发门槛：当前传播进度 ≥ `accelMinProgress`（建议 0.5，取值域 (0.3, 0.7)）；
- 若进度低于门槛，**不触发**加速收尾，等待自然传播完成。

**理由**：从极低进度开始短时间冲到终点，视觉突兀。

**曲线与时长**：

- 加速收尾采用**缓出曲线**（easeOutCubic）；
- 时长与剩余距离成比例：`accelSealDuration = baseAccelSealDuration * (1 - progress)`；
- 上限 `maxAccelSealDuration`（建议 300ms）；
- 下限 `minAccelSealDuration`（建议 120ms）。

**与后台返回的交互**：
页面从后台返回时，若业务数据早已就绪且满足门槛，**不应立即触发加速收尾**，而应先经过一段正常播放的"恢复宽限期"`resumeGraceMs`（建议 150ms，取值域 (80, 300)），再检查是否触发加速。

- **理由**：用户刚回到页面，若立即看到"追赶"式加速，观感突兀；经过一段正常节奏后再加速，观感更自然。
- **行为**：返回后，从暂停处继续正常传播；经过 `resumeGraceMs` 后，若满足门槛则触发加速收尾。
- **边界**：若在 `resumeGraceMs` 内传播自然到达终点，则不触发加速收尾。

**禁止**：

- 禁止在进度低于门槛时触发；
- 禁止牺牲落定完整性（落定仍需完整播放）；
- 禁止通过延长总时长"平滑"；
- 禁止后台返回后立即触发加速收尾。

**参数汇总**：

| 参数 | 语义 | 建议默认值 | 取值域 |
| --- | --- | --- | --- |
| `accelMinProgress` | 加速收尾最小触发进度 | 0.5 | (0.3, 0.7) |
| `baseAccelSealDuration` | 加速收尾基准时长 | 200 ms | (120, 360) |
| `maxAccelSealDuration` | 加速收尾时长上限 | 300 ms | (200, 400) |
| `minAccelSealDuration` | 加速收尾时长下限 | 120 ms | (80, 200) |
| `resumeGraceMs` | 后台返回后恢复宽限期 | 150 ms | (80, 300) |

##### 传播时间契约

**总传播时间** = 传播时长 + 落定时长。
**契约**：

- 传播时长 = `propagationDuration`，建议默认 620ms，取值域 (400, 900)；
- 落定时长 = `landingDuration`，建议默认 100ms；
- 总传播时间 = 720ms（与设计一致）；
- 视图切换在总传播时间结束后才开始。

#### 渲染资源层

##### Canvas 生命周期管理

**原则**：Canvas 的 RAF 调度与视觉可见性严格绑定。

| 事件 | 动作 |
| --- | --- |
| Canvas 可见 | 启动 RAF |
| Canvas 不可见（离场开始） | **立即**停止 RAF |
| Canvas 卸载 | 清理所有资源（RAF、事件监听、缓存） |
| 页面隐藏（visibilitychange） | 暂停 RAF |
| 页面可见 | 恢复 RAF（如仍在生命周期内） |

**离场开始时的动作顺序（严格）**：

1. 时序编排层发出"离场开始"信号；
2. 渲染资源层立即对 hub Canvas 执行 `cancelAnimationFrame`；
3. 清空 hub 的帧调度队列；
4. 标记 hub Canvas 为"不可见"；
5. 时序编排层才开始离场动画（CSS / DOM 层）。

**关键**：第 2 步必须早于第 5 步。

##### Blur 降级

**现状问题**：`filter: blur()` 逐帧对大面域重绘，与 Canvas、Transition 竞争合成器资源。
**根本原因**：blur 被作为**动画属性**参与逐帧渲染，而不是**静态属性**一次性应用。

**修复策略（按优先级）**：

| 策略 | 适用条件 | 说明 |
| --- | --- | --- |
| **isolated（推荐默认）** | blur 源内容动态 | 提升为独立合成层（`will-change: filter` 或 `contain: paint`），隔离重绘；限制 blur 作用区域 |
| **prebaked** | blur 源内容静态 | 构建期或首次渲染时预烘焙为图片 |
| **delayed** | 入场动画期间 | 入场期间禁用 blur，入场稳定一帧后淡入启用 |
| **disabled** | 低端设备 / prefers-reduced-motion | 直接禁用 |

- blur 不得出现在任何逐帧动画属性列表中；
- P4 启用 blur 时不得有逐帧动画并行。

##### 渲染预算错峰

**原则**：任何时刻，只有一个重负载渲染任务在执行。

| 时间片 | 重负载任务 | 其他任务状态 |
| --- | --- | --- |
| 传播期 | 光包 Canvas 渲染（关键） | 其他一切暂停 |
| 离场期 | hub 离场动画（CSS / DOM） | hub Canvas 已停，detail 未挂载，blur 未启用 |
| 过渡期 | 无（合成器处理） | 全部空闲 |
| 入场期 | detail 挂载 + 首帧渲染 | hub 已卸载，blur 未启用 |
| blur 启用期 | blur 一次性应用 | 入场已稳定 |

**禁止**：

- 离场期与入场期重叠；
- Canvas 渲染与 Transition 并行；
- blur 与任何逐帧动画并行。

#### 动画时钟层

##### 墙钟时间与帧步进时间的分离

**核心原则**：

- **进度计算**使用墙钟时间；
- **物理积分**使用帧步进时间；
- 二者不可混用。

**墙钟时间**：

```
elapsed = now - startTime
progress = clamp(elapsed / duration, 0, 1)
```

**帧步进时间**：

```
frameDt = clamp(now - lastFrame, 0, maxFrameStep)
```

**关键洞察**：

- 光包沿丝链传播是**路径动画**，由**进度驱动**；
- 传播进度**只应使用墙钟时间**；
- 帧步进时间只用于：粒子摩擦衰减、拖尾累积等**需要积分**的效果。

**修复后的时钟模型**：

```
// 传播进度：墙钟驱动
progress = (now - startTime) / propagationDuration
// 粒子位置：路径采样
position = path.sample(progress)
// 拖尾累积：帧步进驱动
trail.accumulate(frameDt)
```

##### 帧门控的语义分离

**帧门控的语义**：决定"多久渲染一帧"。
**帧门控不应影响的语义**：动画时间流速。

**当前错误**：帧门控的累积 gateDt 被当作时间流速。
**修复后的语义**：

| 项 | 由谁决定 |
| --- | --- |
| 多久渲染一帧 | 帧门控 |
| 动画进度 | 墙钟时间 |
| 物理积分步长 | 帧步进时间（钳制后） |

**结论**：帧门控只影响采样频率，不影响时间流速。

##### 关键动画的帧率豁免

**定义关键动画**：

- 用户交互的直接视觉反馈；
- 用户会主动注视的动画；
- 传播时间短的动画（如 < 1s）。

**光包传播属于关键动画**。

**豁免接口**：

| 接口 | 语义 |
| --- | --- |
| `requestHighFrameRate(reason, durationHint)` | 请求临时豁免帧门控，返回 `granted / degraded / rejected` |
| `releaseHighFrameRate(token)` | 释放豁免 |

**返回值的语义**：

- `granted`：完全豁免，进入高帧率渲染；
- `degraded`：部分豁免，帧率提升但未达最高（如从 1fps 提升至 30fps）；
- `rejected`：拒绝，维持原档位。

**豁免边界**：

| 条件 | 处理 |
| --- | --- |
| 页面可见 | 允许豁免 |
| 页面隐藏 | **不豁免**（后台无需高帧率） |
| 低电量模式 | 允许 `degraded`，不强制 `granted` |
| 省电模式 | 允许 `rejected`，由帧门控决定 |
| 设备性能档位低 | 允许 `degraded`（降粒子数量，不降时长） |
| 豁免时长超上限 | 自动释放，恢复原档位 |

**豁免时长上限**：`maxExemptDuration`，建议默认 1500ms，取值域 (800, 3000)。

**降级策略**：

- 豁免返回 `degraded` 时，允许**降粒子数量**（视觉降级），但**不降传播时长**；
- 时长不变是硬约束；
- 粒子数量降级是视觉妥协，可接受。

**禁止**：

- 禁止强制帧门控接受豁免；
- 禁止在页面隐藏时豁免；
- 禁止通过降级粒子数量来改变传播时长。

##### 稀疏采样的补偿

**策略 A：拖尾 / 运动模糊**

- 快速移动的光包渲染拖尾；
- 拖尾在视觉上连接稀疏采样点。

**策略 B：加速收尾**

- 检测到掉帧时，按加速收尾逻辑处理；
- 不得改变总时长。

**策略 C：接受稀疏**

- 掉帧极短（< 2 帧）时接受稀疏采样。

**禁止**：

- 禁止通过延长总时长补偿；
- 禁止通过钳制 dt 来"平滑"。

### 边界情况

| 场景 | 处理策略 |
| --- | --- |
| 用户快速重复点击 | 按幂等处理；已启动流程优先完成 |
| **传播期用户切 Tab 再返回** | **RAF 暂停，墙钟继续；返回后从暂停处继续传播至终点（不跳到终点），落定补播完整；完成事件不提前触发；加速收尾需经恢复宽限期** |
| 传播期页面隐藏（visibilitychange） | 同上 |
| 传播期业务数据未就绪 | 传播正常完成；视图切换后展示 loading |
| 传播期业务数据提前就绪 | 按加速收尾规则执行；门槛与曲线明确 |
| 落定期用户点击其他引导单元 | 忽略 |
| prefers-reduced-motion | 传播时长归零；落定归零；直接切换；blur 禁用 |
| 设备电量低 / 性能档位低 | 申请豁免可能返回 `degraded`；降粒子数量，不降时长 |
| 主线程被长任务阻塞 | 阻塞期间进度不推进；结束后跳到正确进度；若跨越终点立即进入落定 |

#### 关键设计决策摘要

1. **传播完成事件是视图切换的唯一合法触发源**——消除固定延时截断。
2. **墙钟时间与帧步进时间分离**——进度用墙钟，积分用帧步进。
3. **帧门控只影响采样频率，不影响时间流速**——修正引擎时钟钳制的根因。
4. **关键动画可申请帧门控豁免，但豁免可被拒绝或降级**——保护低功耗设计目标。
5. **Transition 严格串行**——消除并行竞争。
6. **Canvas 生命周期与可见性绑定**——不可见即停 RAF。
7. **离场动画由 CSS / DOM 完成**——不依赖 Canvas 出帧。
8. **blur 默认 isolated，按场景可切换**——不参与逐帧动画。
9. **落定是传播完成事件的一部分**——到达 ≠ 完成。
10. **状态机是所有时序决策的唯一裁决源**——消除竞态。
11. **后台返回不追求进度时间正确，只追求视觉完整**——G2 精确化；传播必须从暂停处继续。
12. **完成事件不提前，延迟不超过一帧**——G8 独立于 G2。
13. **LANDING 退出与传播完成事件同帧**——状态机与事件语义严格一致。
14. **后台返回后加速收尾经恢复宽限期**——避免"刚回页面就看到追赶"的突兀观感。

#### 设计核心原则

> 
> **动画的"完成"是视觉语义，不是时间语义。**
> 
> 
> 业务只发事件，动画自己决定何时结束。时间正确性由墙钟保证，视觉平滑性由渲染策略保证，两者互不牺牲。豁免机制保护低功耗设计，状态机保护时序完整性，后台语义保护用户视觉完整体验。

> 
> 
> - **动画完成事件驱动业务**，而非固定延时；
> - **时间正确性与视觉平滑性分离**；
> - **关键节奏参数集中配置**；
> - **无障碍与后台场景整体降级**。
