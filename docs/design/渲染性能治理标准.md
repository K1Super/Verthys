# Verthys 渲染性能治理标准
---
## 一、现状基线与问题诊断
### 1.1 性能基线
| 指标 | 当前值 | 目标值 | 差距 |
|---|---|---|---|
| 主界面闲置 CPU 占用（active 档） | 20–30% | < 5% | 4–6 倍 |
| 主界面闲置 CPU 占用（idle 档） | ~8% | < 1% | 8 倍 |
| 每帧 JS 回调次数 | 3+ 次/帧 | 1 次/帧 | 3 倍 |
| GPU 光栅化耗时（blur 类） | 高 | 近零 | — |
| 每帧 draw call（idle 档） | 8 | < 5 | 1.6 倍 |
| 首帧渲染时间 | 未测量 | < 200ms | — |
### 1.2 已确认的根因（按开销排序）
| 问题 | 文件位置 | 预估 CPU 占比 | 置信度 |
|---|---|---|---|
| 3 个 nebula 元素 `filter: blur(80px)` + CSS 动画，每帧 CPU 光栅化 | `UnlockView.vue:46-72` / `CosmicBackground.vue` | 10–15% | 确认 |
| FrameBudgetMonitor 独立 rAF + 每帧 60 元素 P95 排序 | `core/frame-budget.ts:154-197` | 3–5% | 确认 |
| TransitionEngine 积分历史 O(n) shift + 线性搜索 | `composables/useTransitionEngine.ts:79-101` | 1–2% | 确认 |
| 多个并行 rAF 循环（3+），每帧多次 JS 回调调度 | 多文件 | 3–5% | 确认 |
| DPR=2 恒定，idle 档无降分辨率 | `ParticleBackground.vue:183` | 2–3%（idle 档更大） | 疑似 |
| 残影拖尾层静止态仍全量渲染 draw call | `ParticleBackground.vue` orbitMembers | 1–2%（idle 档） | 确认 |
### 1.3 已完成的正确决策（保持不变）
以下设计经独立复核确认正确，治理过程中不得改动：
- ✅ 粒子位置全部在 GPU 着色器内计算，CPU 每帧只写 8 个 uniform
- ✅ 显式 GPU 资源生命周期管理（登记制 + forceContextLoss + dispose）
- ✅ 帧门控四档制（active / settling / idle / deep-idle）
- ✅ 全局空闲状态机统一管理交互 / 失焦 / 可见性
- ✅ WebGL 暖机帧消除启动频闪
- ✅ 双缓冲预挂载（PREWARM_MOUNT / PAGE_HANDOFF）
- ✅ 积分历史环形采样（swirlAt 历史插值）
- ✅ 预加载点精灵纹理（避免运行时纹理上传卡顿）

## 二、治理原则与红线
### 2.1 五条铁律
1. **合成器优先**：任何持续动画只允许操作 `transform` 和 `opacity`，禁止动画化 `filter`、`width`、`height`、`left`、`top`、`box-shadow`。
2. **单帧循环**：全应用最多一个主 rAF 循环，所有每帧任务通过统一注册接口注册，禁止组件各自开 rAF。
3. **静止即降载**：无用户交互时，自动降级帧率 / 分辨率 / draw call 数，视觉不可感知为准。
4. **大效果预渲染**：任何 `blur(>20px)` 的静态效果，预渲染为纹理，禁止运行时实时 filter。
5. **统计不阻塞帧**：性能监控类计算（排序 / 统计 / 决策）必须在帧间隔外执行，不得在每帧回调内做 O(n log n) 操作。
### 2.2 美学红线
- 粒子密度不得低于 80%（降级档位仅在硬件不足时触发，用户主动使用时满配）
- 残影拖尾视觉效果在渡越期间不得消失；静止态可隐藏残影层，但渡越启动时必须立即恢复
- 相机视差跟随效果不得移除（仅降低采样率，保留交互感）
- 星云光晕颜色、大小、位置不得改变（仅改渲染方式，不改视觉参数）
- 启动动画时序编排不得缩短
### 2.3 帧门控与关键动画契约
帧门控四档制是全应用降载的核心机制，关键动画（如光包传播、验证进度收束）需要临时豁免。统一契约如下：
| 项 | 规范 |
|---|---|
| 帧门控职责 | 决定“多久执行一次任务”，不影响动画时间流速 |
| 关键动画定义 | 用户交互的直接视觉反馈、用户会主动注视、时长 < 1s |
| 豁免接口 | 请求返回 `granted / degraded / rejected` 三态；释放接口以 token 为单位 |
| 页面可见性 | 页面隐藏时不豁免 |
| 低电量 / 省电模式 | 允许 `degraded` 或 `rejected`，由帧门控裁决 |
| 豁免时长上限 | `maxExemptDuration`，默认 1500ms |
| 降级策略 | `degraded` 时允许降粒子数量，**不降传播时长** |
| 释放时机 | 关键动画结束、状态机进入 DONE / ABORTED 时立即释放，不得等待超时 |
| 禁止 | 禁止强制帧门控接受豁免；禁止在页面隐藏时豁免；禁止用降级改变动画时长 |

**多关键动画并发**：
- 豁免采用**引用计数**：每个 `granted` 增加计数，每个 `release` 减少计数；
- 计数为 0 时才恢复原档位；
- `granted` 与 `degraded` 混合时，取**最严格档位**（`degraded` 的降级效果优先）；
- `rejected` 不参与计数，仅记录遥测。

**与关联文档的一致性**：本契约与 `DESIGN-HUB-TRANSITION-001` §6.3.3 完全对齐。
### 2.4 帧步进时间与墙钟时间分离契约
**核心原则**（与 `DESIGN-HUB-TRANSITION-001` §6.3.1 一致）：
- **进度计算**使用墙钟时间，不受任何钳制；
- **物理积分**使用帧步进时间，可钳制；
- 二者不可混用；
- 任务签名必须同时接收二者，由任务自行决定使用哪个。

**两个时间参数的定义**：
| 参数 | 定义 | 用途 | 是否钳制 |
|---|---|---|---|
| 帧步进时间 | 距离**上一次任务实际执行**的累积时间，钳制至 `maxFrameStep` | 粒子摩擦衰减、拖尾累积等**物理积分** | 是，上限 50ms |
| 墙钟时间 | 真实经过的时间，`performance.now()` 等价 | 动画进度、状态推演、时间戳记录 | 否 |

**帧步进时间的语义精确定义**：
> 帧步进时间 = 距离**上一次任务实际执行**的时间差，而非距离上一次 rAF 回调的时间差。

在低帧率档位下，rAF 仍可能每 16.7ms 回调一次，但帧门控决定任务只在特定帧执行。若帧步进时间按 rAF 间隔计算，物理积分会以 60Hz 的 dt 推进但只执行 5fps，导致物理时间变慢 12 倍。

**正确语义**：
- 主循环维护“上一次任务实际执行时刻”；
- 若当前帧无任何任务执行（既无 mustRun 也无 throttled），整帧跳过，**不更新该时刻**；
- 下一帧有任务执行时，帧步进时间 = 当前时刻 - 上一次实际执行时刻；
- 该值再被钳制至 `maxFrameStep`。

**契约约束**：
- 任务**禁止**使用帧步进时间计算动画进度；
- 任务**禁止**使用墙钟时间做物理积分（会导致长帧过冲）；
- CR 必须检查任务是否误用。

**为什么必须分离**：
在 deep-idle（1fps）档位下，若任务误用帧步进时间做进度计算，会重现“低帧率下爬行”。本契约从接口语义层面杜绝此类误用。

## 三、分阶段治理方案
### 阶段一：止血治理
#### T1.1 nebula 光晕预渲染
**目标**：消除 3 个大半径 blur 的实时 CPU 光栅化开销。
**方案要点**：
1. **预渲染管线**：应用启动时（bootstrap 阶段），用 OffscreenCanvas 离屏渲染 3 张径向渐变纹理，每张对应一个 nebula 光球的最终模糊效果；导出为 dataURL 或 Canvas 直接作为 CSS background-image。
2. **CSS 改造**：删除 `filter: blur(80px)`，改为 `background-image` 引用预渲染纹理；位移动画仍作用于 `transform`。
3. **纹理生成脚本**：提供构建时生成脚本，产物自动注入到 CSS / JS 常量；设计参数（颜色、大小、模糊半径）集中在 `config/nebula-textures.ts`。
4. **主题与 DPR 适配**：
   - 纹理生成函数接受 `themeKey` 参数，使用 `Map<themeKey, textures>` 缓存；
   - 纹理分辨率按 DPR 生成多套（至少 1x / 2x），或使用足够高的固定分辨率（如 800×800）并由 CSS 缩放；
   - 生成参数集中在配置文件。
5. **启动占位策略**：
   应用启动时 Worker 尚未返回，此时 nebula 必须有可用的初始视觉，避免“从无到有”的闪烁。
   | 阶段 | 视觉表现 | 说明 |
   |---|---|---|
   | 启动至 Worker 返回前 | CSS 径向渐变（无 blur）作为**占位** | 视觉上近似 nebula，无色差闪烁 |
   | Worker 返回后 | 200ms 透明度过渡替换为正式纹理 | 无突变 |
   | `nebulaBakeTimeout`（500ms）超时 | 维持占位不变，记录遥测 | 不阻塞启动 |

   占位的 CSS 径向渐变参数（颜色、中心、半径）必须与正式纹理的视觉参数一致，确保过渡时无位置 / 颜色跳变。
6. **Worker 异步烘焙**：
   - 主题纹理在 Web Worker 中异步烘焙，避免主线程卡顿；
   - 烘焙期间使用旧纹理 + 过渡透明度，避免闪烁；
   - 烘焙超时 500ms，超时后降级为纯色 + CSS 径向渐变近似；
   - Worker 生命周期：常驻，接收 `{ themeKey }` 消息，返回 `{ themeKey, imageBitmap }`；
   - 缓存策略：最多保留 4 套，LRU 淘汰。


#### T1.2 FrameBudgetMonitor 降频 + 环形缓冲
**目标**：消除独立 rAF 循环的每帧排序开销，并正确测量帧内 JS 执行时间。
**方案要点**：
1. **测量对象修正**：主循环在调用所有任务前后记录时间戳，计算**任务总耗时**，作为帧预算输入；帧步进时间仅用于物理积分和调度，不用于帧预算。
2. **采样与决策分离**：每帧只做 O(1) 写入环形缓冲；每 60 帧才执行一次 P95 计算与降级 / 升级决策。
3. **合并到主渲染循环**：删除 FrameBudgetMonitor 自己的 rAF，由主循环每帧调用记录接口，消除第二个 rAF 调度开销。
4. **环形缓冲替换 shift**：使用固定长度 `Float32Array(60)`，用 `head` 索引覆盖写入，O(1)，零分配。

**验收标准**：
- [ ] 独立 rAF 句柄数量从 3 → 2
- [ ] P95 排序频率从 60 次/秒 → 1 次/秒
- [ ] 帧预算输入为任务总耗时，而非帧间隔
- [ ] 降级 / 升级逻辑功能不变（测试验证）

### 阶段二：管线统一
#### T2.1 主渲染循环统一
**目标**：全应用单一 rAF 入口，所有每帧任务注册制，并与帧门控、关键动画豁免、任务分类、错误去重、帧步进时间语义集成。
**架构契约**：
1. **单一主循环**：全应用唯一 rAF 循环，所有每帧任务通过注册接口加入；组件禁止自行开 rAF。
2. **任务签名**：任务接收两个参数——帧步进时间（钳制，用于物理积分）与墙钟时间（不钳制，用于进度计算）。
3. **帧步进时间语义**：
   - 主循环维护“上一次任务实际执行时刻”，而非“上一次 rAF 回调时刻”；
   - 若当前帧无任何任务执行（既无 mustRun 也无 throttled），**整帧跳过，不更新该时刻**；
   - 下一帧有任务执行时，帧步进时间 = 当前时刻 - 上一次实际执行时刻，再钳制至 `maxFrameStep`；
   - 该语义确保低帧率下物理积分以正确的累积时间推进，避免“物理时间变慢”。
4. **任务分类**：
   | 类型 | 注册选项 | 行为 | 典型任务 | 数量限制 |
   |---|---|---|---|---|
   | **mustRun** | 显式标记 | 不受帧门控节流，每帧执行 | 输入处理、状态机推演、可见性响应 | ≤ 2 个，单个 < 0.1ms |
   | **throttled**（默认） | 不标记 | 跟随帧门控，低帧率下跳过若干帧 | 粒子渲染、视差跟随、统计采样 | 不限 |

   **约束**：mustRun 任务必须极轻量，否则破坏降载目标；CR 必须审查每个 mustRun 任务的必要性；数量超过 2 个时应合并或重新设计。
5. **帧门控集成**：
   - 帧门控提供“本帧是否执行任务”的查询接口；
   - 帧门控提供豁免请求 / 释放接口，返回 `granted / degraded / rejected`；
   - 豁免期间，“本帧是否执行”恒为真；
   - 豁免释放后，立即恢复帧门控档位；
   - 页面隐藏时，帧门控拒绝豁免，主循环暂停。
7. **迁移范围**：
   | 现有 rAF | 迁移方式 | 任务类型 |
   |---|---|---|
   | ParticleBackground 帧循环 | 替换为注册接口 | throttled |
   | FrameBudgetMonitor 帧循环 | 替换为注册接口（用任务总耗时） | throttled |
   | UnlockView aura 帧循环 | 替换为注册接口 | throttled |
   | useCosmicBackground 视差帧循环 | 改为按需注册（鼠标移动时注册，静止后注销） | throttled |
   | useCardTilt 倾斜帧循环 | 改为按需注册（卡片悬停时注册） | throttled |
   | 输入处理 | 新注册 | **mustRun** |
   | 可见性响应 | 新注册 | **mustRun** |

**验收标准**：
- [ ] rAF 回调从 3+ 个独立 → 1 个主循环
- [ ] idle / deep-idle 档位下，throttled 任务按帧门控频率执行
- [ ] mustRun 任务在任何档位下每帧执行，且耗时 < 0.1ms
- [ ] 帧步进时间反映“距离上次任务实际执行的累积时间”，低帧率下物理积分正确
- [ ] 整帧跳过时不更新“上次执行时刻”，下一帧的帧步进时间正确累积
- [ ] 关键动画豁免时，所有任务每帧执行，传播时长与设计一致
- [ ] 所有现有动画功能 100% 保留
- [ ] 组件卸载后任务自动注销，无泄漏
- [ ] 页面隐藏时不执行任务，返回后恢复
- [ ] 任务连续错误 10 次后自动禁用，控制台不刷屏

#### T2.2 TransitionEngine 积分历史环形缓冲
**目标**：消除每帧 O(n) shift 和 O(n) 线性搜索。
**方案要点**：
1. **环形缓冲**：使用固定长度 `Float32Array` 预分配时间戳与数值数组，`head` 索引覆盖写入，O(1) 零分配。
2. **二分查找**：时间戳单调递增，使用二分查找定位查询时间所在区间，O(log n) 替代 O(n) 线性搜索。
3. **插值**：在相邻两个采样点之间线性插值，保证视觉连续性。
4. **容量选择**：64 个采样点，覆盖 0.7s @ ~90fps，留有余量。

**验收标准**：
- [ ] 残影拖尾视觉效果与改造前逐帧对比无差异
- [ ] 内存分配从每帧 push / shift → 零分配
- [ ] 查询从 O(n) → O(log n)

### 阶段三：静止态深度优化
#### T3.1 DPR 自适应
**目标**：无交互时自动降低渲染分辨率，节省 GPU 填充率，保证切换平滑，并与关键动画豁免协同。
**方案要点**：
1. **档位 DPR 策略**：
   | 空闲档位 | DPR | 视觉影响 | 性能收益 |
   |---|---|---|---|
   | active | min(dpr, 2) | 满配 | 基线 |
   | settling | min(dpr, 1.5) | 近不可感知 | GPU 填充率降 ~44% |
   | idle | 1.0 | 粒子边缘略柔化 | GPU 填充率降 75% |
   | deep-idle | 1.0 | 同 idle | 同 idle |

2. **防抖与合并执行**：
   - 档位切换后延迟 200ms 应用 DPR 变更，避免档位频繁切换时反复重设；
   - 像素比设置与画布尺寸重设必须在**同一防抖窗口内合并执行**，避免两次帧缓冲重分配；
   - 切换后必须**立即渲染一帧**，避免空白。
3. **豁免优先级契约**：
   **核心原则**：**豁免优先于未决档位切换。**
   | 事件 | 行为 |
   |---|---|
   | 豁免被批准 | 立即取消所有未决的 DPR 切换；直接应用 active 档 DPR；不等待防抖 |
   | 豁免被拒绝 | 未决 DPR 切换按原计划执行 |
   | 豁免释放 | 按当前档位重新调度 DPR 切换（走 200ms 防抖） |

   豁免批准时，若存在未决的 DPR 切换（如 idle 档的 1.0），需要**放弃未决值**，而非立即应用它。

   **契约约束**：
   - 豁免批准时，任何未决的 DPR 目标值必须被**丢弃**，不得被应用；
   - 豁免批准时，DPR 必须切换至 active 档对应值，不等待防抖；
   - 豁免释放后，按当前空闲档位重新调度 DPR 切换。

#### T3.2 静止态残影层降级
**目标**：无渡越时不渲染残影拖尾层，减少 draw call，并与关键动画豁免联动。
**方案要点**：
1. **可见性切换**：静止态（`warpEnv ≈ 0`）残影层隐藏，不提交 draw call；渡越进行中（`warpEnv > 0.01`）正常渲染。
2. **与关键动画豁免联动**：
   - 渡越启动时**必须立即申请帧门控豁免**，与残影层恢复**同步发生**；
   - `granted` 时：残影层恢复 + 帧率提升至 60fps，1 帧内完成；
   - `degraded` 时：残影层恢复，帧率部分提升，允许 1–2 帧延迟；
   - `rejected` 时：残影层恢复，但帧率维持原档位，接受可感知延迟，并在遥测中记录；
   - **禁止**只恢复残影层而不申请豁免；
   - **禁止**申请豁免但不恢复残影层。
3. **Token 生命周期**：
   | 项 | 规范 |
   |---|---|
   | 申请时机 | 渡越启动时（`warpEnv` 从 0 跨越阈值），且当前无 token 时 |
   | 释放时机 | 渡越结束时（`warpEnv` 回到阈值以下），且当前有 token 时 |
   | 幂等性 | 重复申请 / 重复释放均被忽略 |
   | 跨渡越复用 | **不允许**。每次渡越结束后 token 被重置为 null，下次渡越重新申请 |
   | 与卸载的关系 | 组件卸载时若有未释放 token，必须立即释放，避免帧门控泄漏 |

   token 代表一次豁免的生命周期；跨渡越复用会导致引用计数与实际动画数量不一致，破坏 §2.3 的引用计数契约。

**验收标准**：
- [ ] idle 档 draw call 从 8 → 3（3 个本体层）
- [ ] 渡越期间残影拖尾效果 100% 保留
- [ ] 残影层切换无闪烁
- [ ] 渡越启动时残影层在 1 帧内恢复可见（豁免 granted 时）
- [ ] 渡越启动时同步申请豁免，无“残影层恢复但帧率仍 5fps”错位
- [ ] token 在渡越结束后被重置，下次渡越重新申请
- [ ] 组件卸载时未释放 token 被立即释放
- [ ] 豁免 rejected 时接受延迟并在遥测中记录

### 阶段四：CSS 动画全面治理
#### T4.1 合成器化审计清单
**原则**：所有 CSS `animation` / `transition` 只允许 `transform` 和 `opacity` 属性。
**必须整改项**：
| 文件 | 当前问题 | 整改方案 |
|---|---|---|
| `UnlockView.vue` nebula | `filter: blur(80px)` 实时计算 | T1.1 预渲染 |
| `components.css` 卡片 hover | 若有 `box-shadow` 动画 | 改为 `opacity` 叠加层 |
| `qd-panel.css` | `backdrop-filter: blur(6px)` | 优先禁用，用半透明纯色 + 预渲染噪点替代；若必须保留，限制区域、降低半径，低端设备 `disabled` |
| 全局搜索 `animation:` | 检查每个动画的属性 | 非合成器属性一律整改 |

**`backdrop-filter` 处理决策**：
- 若背后是粒子动画，`backdrop-filter` 会每帧采样并模糊，开销极大；
- 首选禁用，用半透明纯色 + 预渲染噪点纹理替代；
- 若设计不可妥协，限制作用区域（如仅面板边缘），降低模糊半径至 ≤ 4px；
- 低端设备 / `prefers-reduced-motion` 下直接 `disabled`。

**验收标准**：
- [ ] 全项目 `filter` 属性不出现在 `animation` / `transition` 目标属性中
- [ ] DevTools Layers 面板，无“重绘”类型的动画层
- [ ] Performance 面板，paint 事件次数下降 > 90%
- [ ] `backdrop-filter` 已按上述决策处理，无逐帧模糊竞争

## 四、工程化规范
### 4.1 新动画组件开发规范
任何新增动画组件必须遵守以下规范：
1. **禁止自带 rAF**：通过主循环注册接口注册帧回调。
2. **禁止动画化非合成器属性**：只动 `transform` / `opacity`。
3. **禁止实时 blur**：大半径模糊效果必须预渲染为纹理。
4. **静止即降载**：无交互时自动降低帧率或关闭非必要渲染。
5. **GPU 资源显式释放**：组件卸载时必须 dispose 所有 GPU 资源。
6. **关键动画使用豁免接口**：如需临时高帧率，申请豁免并在结束时释放；token 不得跨渡越复用。
7. **页面隐藏时暂停**：通过帧门控和 visibilitychange 统一处理，不得自行恢复。
8. **禁止混用帧步进时间与墙钟时间**：进度用墙钟，积分用帧步进。
9. **mustRun 任务必须极轻量**：单个 < 0.1ms，总数 ≤ 2。
10. **残影层与豁免联动**：渡越启动时同步申请豁免，禁止只切可见性。

## 八、附录
### 8.1 术语表
| 术语 | 定义 |
|---|---|
| 合成器 | GPU 合成层，只操作 transform / opacity 时零 CPU 开销 |
| Rasterize | 光栅化，CPU 重新绘制元素内容（filter / width 变化触发） |
| DPR | 设备像素比，2x 表示渲染分辨率是 CSS 像素的 4 倍 |
| draw call | 一次 GPU 绘制提交，数量影响 CPU-GPU 通信开销 |
| 帧门控 | 根据空闲档位控制帧率与任务执行频率的调度机制 |
| 关键动画 | 用户交互的直接视觉反馈，可申请帧门控豁免 |
| 豁免 | 关键动画临时退出低帧模式的机制，可被拒绝或降级 |
| 主循环 | 全应用唯一主 rAF 循环，所有每帧任务注册于此 |
| 墙钟时间 | 真实经过的时间，不钳制，用于进度计算 |
| 帧步进时间 | **距离上一次任务实际执行**的累积时间，钳制至 `maxFrameStep`，用于物理积分 |
| mustRun 任务 | 不受帧门控节流的任务，每帧执行，用于输入处理与状态推演 |
| throttled 任务 | 跟随帧门控节流的任务，低帧率下跳过若干帧 |
| 引用计数豁免 | 多个关键动画并发时的豁免管理机制，计数为 0 才恢复原档位 |
| 豁免 token | 一次豁免生命周期的句柄，不得跨渡越复用 |
| 整帧跳过 | 当前帧无任何任务执行时，主循环跳过任务调度且不更新“上次执行时刻” |
| 启动占位 | Worker 烘焙完成前使用的 CSS 径向渐变，视觉近似正式纹理 |
