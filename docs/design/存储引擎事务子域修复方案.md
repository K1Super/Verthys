## 第二部分 修复方案（定稿）

### 三条不变量（写入 `CONTRIBUTING.md` 评审 Checklist）

1. **破坏性操作（release/remove）前，内存态 Manifest 必须拥有完整可回滚快照，且释放必须推迟到持久化成功之后。**
2. **AEAD nonce 计数器恢复必须由 WAL 与索引帧共同夹逼：`floor = max(persisted, max_replayed_nonce + MARGIN)`，禁止回退。**
3. **所有持久化字段的写侧必须携带与结构体声明类型严格一致的上界校验，写路径禁止截断。**

---

### S-001 修复：Manifest 影子事务（修正版）

> **【关键修正 1】** 原评审报告"先备份再 release"的建议不完整——备份拷贝的是浅指针，release 后指针悬空，回滚会 UAF。正确做法是**把 release 推迟到 `manifest_save` 成功之后**。

#### 数据结构

```c
typedef struct {
    VerthysLsmManifest   snapshot;      /* count/txid/next_seq/... 元数据快照 */
    VerthysLsmTableMeta  tables[VERTHYS_LSM_MAX_TABLES]; /* 表数组浅拷贝 */
    size_t               removed_idx[VERTHYS_LSM_MAX_TABLES];
    size_t               removed_n;
    bool                 active;
} VerthysManifestTxn;

int  manifest_txn_begin (VerthysLsm *lsm, VerthysManifestTxn *mt);
int  manifest_txn_commit(VerthysLsm *lsm, VerthysManifestTxn *mt);   /* 内部释放被摘除表 */
void manifest_txn_abort (VerthysLsm *lsm, VerthysManifestTxn *mt);   /* 只恢复内存态，不 release */
```

#### 语义契约

- `begin` 在任何 release/remove 之前完成数组浅拷贝，此时 `bloom_bits/blocks` 指针仍有效。
- 事务期间只修改 `lsm->manifest` 数组与元数据，**不触碰任何旧表资源**。
- `commit` 内部负责释放被摘除表的惰性缓存与释放影子缓冲——**调用方不得手动 release**。
- `abort` 仅恢复内存态，不 release——因为输入表资源仍由内存 Manifest 持有。
- `manifest_save` 成功后，**仅当** `commit` 内部释放；一旦 release 过某表，禁止走 abort。

#### 重写 `compact_locked`

```c
static int compact_locked(VerthysLsm *lsm, ...) {
    VerthysCompactionInput in = {0};
    VerthysLsmTableMeta new_table = {0};

    if (pick_and_merge(lsm, &in, &new_table) != VERTHYS_OK) {
        release_inputs(&in);
        return VERTHYS_ERR;
    }

    VerthysManifestTxn mt;
    if (manifest_txn_begin(lsm, &mt) != VERTHYS_OK) {
        release_inputs(&in);
        sstable_drop(&new_table);   /* 见下文孤儿文件处理 */
        return VERTHYS_ERR_RESOURCE_LIMIT;
    }

    /* 内存态应用变更：记录被摘除表、插入新表、推进 txid/next_seq */
    manifest_apply_compaction(lsm, &mt, &in, &new_table);

    int rc = manifest_save(&lsm->manifest);
    if (rc != VERTHYS_OK) {
        manifest_txn_abort(lsm, &mt);   /* 只恢复数组，不 release */
        sstable_drop(&new_table);
        return rc;
    }

    /* 落盘成功，commit 内部统一释放被摘除表 + 影子缓冲 */
    manifest_txn_commit(lsm, &mt);
    return VERTHYS_OK;
}
```

> **【关键修正 2】** 消除 commit 释放语义矛盾。方案定稿为：**`manifest_txn_commit` 内部释放被摘除表**，调用方不直接操作 `mt.tables`。原方案 2.3 示例中的手动 `for ... release` 必须删除，否则与 commit 内部释放构成 double free。

> **【关键修正 3】** `sstable_drop(&new_table)` 必须明确语义：如果 `new_table` 已落盘，`sstable_drop` 要负责删除磁盘文件（避免孤儿 SSTable）；如果尚未落盘，只释放内存。建议拆成两个 API：`sstable_free_mem()` 与 `sstable_delete_disk_and_free()`，并在新表 `frame_write` 落盘后设置 `new_table.persisted = true`。

#### 回归测试
- 注入 `VERTHYS_LSM_TEST_HOOK_FAIL_MANIFEST_SAVE`，断言失败后当前进程 `get/scan` 仍命中全部输入表键。
- ASAN + `_CrtSetDbgFlag` 检查回滚后无悬空 bloom 指针。
- 断点计数验证 `commit` 路径下 release 恰好调用 `removed_n` 次，无重复释放。

### S-002 修复：nonce 追赶协议化（修正版）

> **【关键修正 4】** 原方案 `decode_be64_prefix(rec->u.extent.nonce)` 假设 12B nonce 前 8B 是大端计数器。**必须先用单元测试锁定 `verthys_cng_aead_encrypt` 的 nonce 布局**，再决定解析方式。

#### 前置：确认 nonce 布局（阻塞项）

在实现追赶逻辑前，必须回答：

- 12B nonce 的组成是 `[4B random][8B counter]`、`[8B counter][4B random]`，还是 `[12B 混合]`？
- 计数器是 BE 还是 LE？
- 计数器从 0 还是 1 开始？每次加密 +1 还是 +N？

做法：

```c
/* verthys_crypto_cng.h 中新增显式文档 */
/* AEAD nonce 布局约定：
 *   nonce[0..3]  = 随机盐（每分区一次性生成）
 *   nonce[4..11] = 8B 大端单调计数器，从 0 开始，每次 encrypt +1
 * 任何修改此布局的提交必须同步更新 verthys_wal.c 的 nonce 编解码。 */
```

并在 `verthys_cng_aead_encrypt` 入口加断言：

```c
VERTHYS_INTERNAL_ASSERT(a->nonce[0..3] == a->salt, VERTHYS_ERR_CRYPTO);
```

同时用单元测试验证：连续加密 N 次后，提取的计数器严格等于 `N-1`（或 `N`）。**若布局无法确认，则退化为"全 nonce 字节比较取字典序最大"的保守策略**——虽然牺牲一些精度，但不会误判。

#### 恢复上下文

```c
typedef struct {
    uint64_t max_extent_nonce_counter;   /* 从 WAL EXTENT 记录的 nonce 提取 */
    uint32_t replayed_groups;
    uint32_t dropped_groups;
} VerthysTxnRecoverCtx;
```

#### 回调中提取

```c
static int txn_recover_replay_cb(void *ud, const VerthysWalRecord *rec, bool replay) {
    VerthysTxnRecoverCtx *ctx = ud;
    switch (rec->type) {
    case VERTHYS_WAL_REC_EXTENT: {
        uint64_t n = extract_nonce_counter(rec->u.extent.nonce);  /* 布局确定后实现 */
        if (n > ctx->max_extent_nonce_counter)
            ctx->max_extent_nonce_counter = n;
        if (replay) { /* 现有重注册逻辑 */ ctx->replayed_groups++; }
        else        { ctx->dropped_groups++; }
        break;
    }
    }
    return 0;
}
```

> **定稿语义：重放组和丢弃组都计入追赶。** 原评审报告"只对重放组计数"的表述作废——只要密文已在盘上，nonce 就已被消耗，丢弃组的孤儿块同样不能重用 nonce。

#### 收尾收敛点

```c
static int txn_recover_finalize(VerthysTxn *t, const VerthysTxnRecoverCtx *ctx) {
    uint64_t persisted = 0;
    verthys_extent_index_get_nonce_counter(t->extent_part, &persisted);

    uint64_t floor = persisted;
    uint64_t candidate = ctx->max_extent_nonce_counter + VERTHYS_WAL_NONCE_RESTORE_MARGIN;
    if (candidate > floor) floor = candidate;

    /* 禁止回退 */
    if (floor < persisted) return VERTHYS_ERR_CRYPTO;

    if (verthys_cng_aead_restore_nonce_counter(&t->extent_part->aead, floor) != 0)
        return VERTHYS_ERR_CRYPTO;

    /* 立即固化，防止后续崩溃导致回退 */
    return verthys_extent_index_save(t->extent_part);
}
```

#### `restore_nonce_counter` 加断言

```c
int verthys_cng_aead_restore_nonce_counter(Aead *a, uint64_t target) {
    if (target < a->nonce_counter) return VERTHYS_ERR_CRYPTO;   /* 禁止降序 */
    a->nonce_counter = target;
    return 0;
}
```

#### MARGIN 定标

原方案 MARGIN=64 对 LSM 条目够用，但 Extent 块尺寸大、单事务消耗可能几十个。**建议 `VERTHYS_WAL_NONCE_RESTORE_MARGIN` 提升为 256**，并把推导理由（单事务最大 extent 块数 × 2）写进头文件。

#### 回归测试
- 单测：模拟"数据块写 WAL → 崩 → 索引帧未保存"，断言 `aead.nonce_counter >= max_wal_nonce + MARGIN`。
- 模糊测试：随机在六阶段协议任意点 SIGKILL，重启后验证 nonce 计数器单调不回退。
- 日志挂载点记录每次加密的 nonce 序号，比对全程无重复。

### S-003 + S-004 修复：写侧守卫统一化

新建 `verthys_persist_guard.h`：

```c
#define VERTHYS_GUARD_U32(name, val)  \
    do { if ((uint64_t)(val) > UINT32_MAX) return VERTHYS_ERR_INVALID; } while (0)

#define VERTHYS_GUARD_SIZE_PLUS(name, val, tag)  \
    do { if ((uint64_t)(val) > (uint64_t)UINT32_MAX - (uint64_t)(tag)) \
             return VERTHYS_ERR_INVALID; } while (0)
```

应用：

```c
/* vfmt_write, verthys_format.c:194 */
VERTHYS_GUARD_U32("data_size", records[i].data_size);
put_u32le(blk, (uint32_t)records[i].data_size);

/* vfmt_write_streaming, verthys_format.c:548 */
VERTHYS_GUARD_U32("pt_size", pt_size);

/* verthys_extent.c:125 */
VERTHYS_GUARD_SIZE_PLUS("pt_len", pt_len, VERTHYS_EXTENT_TAG_BYTES);
```

**v2 格式升级**：`VerthysFmtRecord.size` 与 Extent 帧头 `size` 字段升为 `u64`，放路线图，不在本次变更范围。

**Property-based 测试**：对三个写入 API 随机传入 `[0, UINT64_MAX]` 边界附近值，断言要么返回 `VERTHYS_ERR_INVALID`，要么往返读写一致，**绝不出现写成功但读回失败**。

```c
#  define VERTHYS_INTERNAL_ASSERT(cond, rc) \
     do { if (!(cond)) return (rc); } while (0)

```

**S-005 应用**：

```c
bool found = false;
for (size_t i = 0; i < lsm->manifest.count; i++) {
    if (lsm->manifest.tables[i].seq == seq) {
        memmove(&lsm->manifest.tables[i],
                &lsm->manifest.tables[i+1],
                (lsm->manifest.count - i - 1) * sizeof(lsm->manifest.tables[0]));
        found = true;
        break;
    }

VERTHYS_INTERNAL_ASSERT(found, VERTHYS_ERR_INTERNAL);
```

#### S-006 锁访问收敛

> **【关键修正 5】** MSVC `#pragma warning(suppress: 4090)` 只抑制下一行，不是块级。改用 `push`/`disable`/`pop`：

```c
/* verthys_lsm_internal.h */
#pragma warning(push)
#pragma warning(disable:4090)   /* SRWLOCK 是内核同步原语，const 强转属 Windows 惯例；
                                   迁移非 MSVC 工具链时必须重新评估 */
static inline void lsm_lock_shared(const VerthysLsm *lsm) {
    AcquireSRWLockShared((SRWLOCK *)&lsm->lock);
}
static inline void lsm_unlock_shared(const VerthysLsm *lsm) {
    ReleaseSRWLockShared((SRWLOCK *)&lsm->lock);
}
#pragma warning(pop)
```

把 3 处豁免收敛到 1 处。

#### S-007 注释治理

> **【关键修正 6】** 不做 CI ±20% 校验（实施成本高、易误报）。直接改写成编译期表达式：

```c
/* 约 sizeof(VerthysWalRecord) ≈ 600B（name 内联 511B） */
```

## 第四部分 结论

### 定稿要点

1. **S-001**：不采用"先备份再 release"局部补丁（会悬空指针），改用 **Manifest 影子事务**——事务期间只改数组，release 推迟到 `manifest_save` 成功之后；`commit` 内部统一释放被摘除表，调用方不得手动 release；`sstable_drop` 拆分为内存释放与磁盘删除两个 API。
2. **S-002**：**先锁定 12B nonce 布局**再实现追赶；重放组与丢弃组均计入；`floor = max(persisted, max_replayed + MARGIN)`；`restore_nonce_counter` 禁止降序；追赶后立即保存索引帧固化；MARGIN 建议提至 256。
3. **S-003/S-004**：用 `VERTHYS_GUARD_U32` / `VERTHYS_GUARD_SIZE_PLUS` 统一写侧守卫，v2 格式升级另立路线图。
4. **S-005~S-010**：用内部断言、锁访问收敛（`#pragma push/disable/pop`）、`sizeof` 注释、ADR 文档化四件套批量治理。
5. **三条不变量**写入贡献指南，把本次评审成果固化为团队规范。

### 修正了什么

原评审报告的 S-001 局部补丁会导致悬空指针；原修复方案的 commit 释放语义存在 double free 风险、`sstable_drop` 语义不明、S-002 nonce 布局假设未验证、S-006 pragma 抑制方式无效。**以上五处均已在本定稿中修正。**

### 修复后的子域状态

- **关键不变量可证明**：非降序断言、影子事务不变式、写侧守卫宏把"顺序敏感"转化为"状态机不可能错"。
- **边界防御自动化**：property-based 测试 + 断言覆盖 S-003/S-004/S-005。
- **设计权衡有据可查**：ADR 把"评审认为可接受的降级路径"从口头共识变为可追溯文档。
- **可维护性提升**：锁豁免从 3 处收敛到 1 处；注释与 `sizeof` 对齐；Manifest 变更有明确事务边界。
