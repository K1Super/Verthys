# 开屏星系动画审查清单

审查日期：2026-09-24
审查范围：应用启动 → 星系逆渡成型（intro 3s）→ 点击进入 → 正渡（enter 5s）→ 主界面
涉及代码：
- `verthys-tauri/src/composables/useTransitionEngine.ts`（渡越序列引擎）
- `verthys-tauri/src/components/ParticleBackground.vue`(星系渲染与帧循环)
- `verthys-tauri/src/composables/useAppTransition.ts`（页面流转编排）
- `verthys-tauri/src/App.vue`（根视图与双缓冲预挂载）
- `verthys-tauri/src/components/UnlockView.vue`（引导页品牌动画与点击离场）
- `verthys-tauri/src/app/constants.ts`（转场节点常量）

## 一、审查结论摘要

整体架构质量高：包络三段 smootherstep 全程 C2、缠绕为积分量角度恒连续、
着色器零 CPU 上传、双缓冲预挂载、展示/编排/渲染三层解耦等设计均为顶级水准。

但「启动后自动逆渡期间点击打断」这一交互路径存在明显可感知的突兀感，
根因并非单点 bug，而是 **四层叠加的时序与数学设计缺陷**（见第二节），
叠加后形成「点击后先愣了一下 → 星系突然失力停滞 → 整体反向 + 相机甩动」的观感。

另发现若干未达顶级标准的质量问题：无障碍降级缺失、时序耦合无代码约束、
离场动画对未完成入场态的硬切等（见第三节缺陷清单）。

## 二、打断突兀根因分析（核心问题）

启动 0-3s 星系执行逆渡（反向缠绕成型），用户在 3s 内点击 `UnlockView`，
`onEnter` → 320ms 后 `emit("enter")` → `phase="warping"` → 引擎 `triggerEnter()`。
最终用户在画面上看到的是以下四层缺陷的叠加：

### 缺陷 01 —— 打断后总包络出现深谷（视觉"失力停滞"）【P1 · 突兀主因】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts) `update()` 中 `warpEnvVal = Math.min(introEnv + enterEnv, 1)`。
- 现象：打断后 intro 残余包络自当前值 0.5s 衰减、enter 包络自零按 5s 周期爬升，
  两序列独立推进，其和先跌后升——假设在逆渡峰值（包络≈1.0）处点击，
  打断后约 1s 时刻总和跌至 0.2 量级再爬回。星系收缩/相机 Z 冲程/粒子亮暗
  全部随环境强度联动 → 「画面先松驰、停半拍、再重新收紧」。
- 根因：自然点击路径包络 0→1 单调；打断路径被刻意压到深谷再回升，
  与自然路径形态不一致，感知为"被打断"。
- 修复方向：打断时不应让两序列独立衰减叠加，而应对**总强度**做连续交叉淡化
  （在打断时刻的总强度基础上，沿 0.5s 平滑过渡到 enter 包络对应强度），
  保证总和单调不回退，打断与自然点击包络曲率一致。

### 缺陷 02 —— 缠绕方向 0.5s 内穿轴反转 + 相机甩动（"急刹-回旋"）【P1 · 突兀主因】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L183-L189)（`dirW = enterEnv − introEnv`、`swirl` 符号积分）、
  [ParticleBackground.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/ParticleBackground.vue#L685-L716)（`dirSmooth` 阻尼与相机俯仰/侧摆/lookAt）。
- 现象：`dirW` 从 -1（逆渡满反向）在 0.5s 内越零再到 +1（正渡），
  缠绕角速度减速→停→反向加速；相机以 `-120*arc*dirSmooth` 从 +120 侧
  甩向 -120 侧，`lookAt` 同步穿轴 → 相机在屏幕中央以最大角速度扫过（甩鞭）。
  `kEnv=0.08` 的阻尼滞后使 `dirSmooth` 过零时转速峰值更高。
- 根因：数学上角度积分 C0 连续，但**速度符号反转发生在极短窗口**，
  感知层"整体旋转反向"是明确的定性变化；角度连续 ≠ 旋转方向连续感受。
- 修复方向：打断后加入"方向减速走廊"——先让方向权重在 0.8~1.2s 内
  由当前位置平滑滑向 0（旋转减速驻停），再启动正渡 ramp；或对相机方向
  采用不对称阻尼（正渡方向加速、反向瞬时抑制），消除大幅穿轴甩动。

### 缺陷 03 —— 320ms 延迟造成"点击后星系滞后响应"【P1 · 直接观感来源】

- 位置：[UnlockView.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/UnlockView.vue#L192-L199)（`setTimeout(() => emit("enter"), 320)`）、
  [ParticleBackground.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/ParticleBackground.vue#L823-L839)（`watch(phase)` → `triggerEnter`）。
- 现象：点击后 320ms 内星系**继续逆渡做"倒卷"动作**，用户以为没点到；
  320ms 后星系突然被中断并反向 → 「先愣一下、再猛地换向」。
  同时 enter 时钟晚于点击 320ms 启动，而 `PAGE_HANDOFF` 仍从点击时刻起算
  3100ms 交接 → 实际交接在 enter 包络 x≈0.556（未到设计的 0.62 峰驻），
  星系尚在持续收拢时界面即淡出，编排声称的"峰驻处交接"漂移。
- 根因：320ms 是为等字符弹射前段而设的固定延迟，但它延迟了引擎响应，
  且未被编排常数纳入（`PAGE_HANDOFF` 未扣除该延迟）。
- 修复方向：将 320ms 延迟并入时序派生的基准（点击 t0 与引擎 t0 对齐），
  或改为 `UnlockView` 离场动画与引擎打断同帧触发、仅字符层做视觉补偿；
  交接节点应基于引擎时序而非独立飞表计时。

### 缺陷 04 —— 早期打断时品牌动画"入场→离场"硬切【P2】

- 位置：[UnlockView.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/UnlockView.vue#L380-L381)（`.leaving .brand-char` → `char-eject` 0.62s）。
- 现象：品牌字/谱线仍在入场组装（3s 充能）的中途被点击时，
  动画直接整体切换到离场弹射/塌缩——未完成的笔画瞬间跳变成"外抛"，
  观感为一次跳切；谱线塌缩耗时 0.55s 与字符 0.62s 亦存在相位差。
- 根因：离场动画未感知入场动画的当前进度，无补间衔接。
- 修复方向：离场时按入场进度做定量回退/补间（进度 <50% 直接整页淡出快移，
  进度 >50% 才走弹射），避免"组装到一半突然弹飞"。

## 三、质量缺陷与低质项清单

### 缺陷 05 —— 无障碍缺失：reduced-motion 未下穿启动引擎【P1 · 合规】

- 位置：[App.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/App.vue#L62-L65) 仅跟踪偏好用于 CSS；
  [ParticleBackground.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/ParticleBackground.vue) JS 侧无任何 reduced-motion 开关。
- 现象：`prefers-reduced-motion: reduce` 用户启动时仍强制经历 3s 逆渡 +
  5s 正渡的大幅 WebGL 运动（CSS 静止仅覆盖 main-layer 过渡）。
- 修复方向：reduced-motion 下跳过 intro 自动逆渡（introDone 置位）、
  enter 改为极短淡变；引擎门控增加开关位。

### 缺陷 06 —— 打断瞬间包络导数不连续（破坏 C2 宣称）【P3】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L166-L174)。
- 现象：intro 包络原处于上升/峰值段（斜率为正），打断帧起从当前值衰减，
  smootherstep 起点导数恰为 0 → 包络自身速度瞬时归零，加速度脉冲；
  与文件头"全程 C2 连续"声明不符（该声明只对未打断路径成立）。
- 修复方向：打断衰减起点改用与打断时刻**导数连续**的接续曲线（Hermite
  匹配当前斜率），或文档收窄声明范围。

### 缺陷 07 —— 时序耦合仅靠注释，无代码级约束【P2】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L26-L27)（INTRO_T=3.0 硬编码）与
  [UnlockView.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/UnlockView.vue#L208-L209)（充能 3.05s / 进入舱 3.25s）。
- 现象：引擎逆渡时长、品牌充能时长、进入提示浮现时长三处独立硬编码，
  相互对齐只依赖注释约定；任一改动即失步。
- 修复方向：统一收敛为共享常量源（同 `ENTER_T_MS` 模式），编排节点集中定义。

### 缺陷 08 —— 打断强依赖点击时刻，感知差异大【P2】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L195-L198)。
- 现象：0.5s 内点击（逆渡刚开始，包络≈0）→ 打断几乎无感；
  1.5-2.5s 点击（逆渡中段/峰值）→ 缺陷 01/02 的谷值与反转最剧烈；
  2.8s 后点击（逆渡近完成）→ 又几乎无感。同一交互三档表现，中段最突兀。
- 修复方向：对打断时刻分档处理（早期直接切正渡、中段走减速走廊、
  末期按自然收尾），或统一走缺陷 01/02 修复后的恒定平滑路径。

### 缺陷 09 —— 残影历史采样在打断早期可能回零【P3】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L92-L95)（早于最早样本返回 0）。
- 现象：打断初期残影层（t-lag 采样）可能插值到 0 相位，
  拖尾弧线短暂"退回原点"再正确，偶发视觉小暇。
- 修复方向：残影历史在渡越窗口内预埋首样本（t=0, v=0），或 clamp 到最新值。

### 缺陷 10 —— 相机视差与打断谷值叠加（次要）【P3】

- 位置：[ParticleBackground.vue](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/components/ParticleBackground.vue#L690-L693)（`parallax = 1 - envSmooth`）。
- 现象：打断谷值期 envSmooth 回落，视差灵敏度骤升，鼠标轻微移动即放大抖动。
- 修复方向：视差恢复设定更长的阻尼走廊，与缺陷 01 的包络修复联动。

### 缺陷 11 —— enterClock 重复置零的风险面【P3】

- 位置：[useTransitionEngine.ts](file:///c:/Users/Administrator/Desktop/Verthys/verthys-tauri/src/composables/useTransitionEngine.ts#L195-L198)。
- 现象：`triggerEnter()` 无条件 `enterClock = 0`，若未来有入口在 enter
  进行中再次触发（如热更新重放 phase），正渡将重头播放造成跳变。
  当前调用路径受 `leaving` 守卫保护不受影响，属防御性缺口。
- 修复方向：加入"enter 进行中再触发则忽略"的幂等守卫。

## 四、总体评级与结论

| 维度 | 评级 | 说明 |
|---|---|---|
| 数学建模（包络/积分/连续性） | 优 | 未打断路径 C2 连续，无微颤，积分量角度恒连续 |
| 渲染架构（着色器/零上传/框架） | 优 | CPU 每帧三 uniform，鲁棒性好 |
| 编排架构（双缓冲/依赖解耦） | 优 | 展示/编排/渲染三层解耦规范 |
| 打断交互（点击中路径） | 不合格 | 缺陷 01-04 叠加 → 明显突兀，未达顶级标准 |
| 无障碍/合规 | 不合格 | reduced-motion 未下穿引擎（缺陷 05） |

结论：动画主体架构顶级，但「启动逆渡期间的点击打断」交互是唯一的显著
质量缺口，需按 P1（缺陷 01/02/03/05）→ P2（缺陷 04/07/08）→ P3
（缺陷 06/09/10/11）顺序整改，每批独立过门禁（vue-tsc、vitest、
npm run build）后再进下一批。

## 五、验收清单（自测步骤）

打断无突兀的验收判据（全部满足才算达标）：

1. 启动后任意时刻（0s / 1.5s / 2.8s / 3s+）点击进入，星系不应出现
   "先停滞半秒再加速"的失力谷值；
2. 打断时星系缠绕方向反转必须经过可感知的减速走廊（≥0.8s 滑向驻停），
   不得出现瞬间反向回旋或相机穿轴甩动；
3. 点击后 320ms 内星系即随点击响应，不得继续逆渡造成"没点到"错觉；
4. 点击后 UnlockView 品牌字/谱线离场与入场进度平滑衔接，无"组装到
   一半弹飞"；
5. 页面交接时刻与实际「峰驻 + 消散」观感一致，不再出现"星系未收拢
   界面已切走"；
6. 系统开启 reduce-motion 时，启动无全屏大幅运动（跳过逆渡、正渡极短）；
7. 打断、重复点击（防抖窗口内）、快速双击均不产生跳变/闪帧/残留；
8. 帧率档位切换（60/30/5/1fps）下打断路径均无异常；
9. 回归：自然点击（3s 后）与未点击自动驻留的观感与整改前一致。

## 六、整改建议实施顺序

- 批次 1（P1）：缺陷 01+02+03 一并重做打断合成（总包络交叉淡化 +
  方向减速走廊 + 时序源对齐），这是突兀感的全部根因；
- 批次 2（P1）：缺陷 05 reduced-motion 下穿引擎；
- 批次 3（P2）：缺陷 04 品牌动画离场补间 + 缺陷 07 时序常量收敛 +
  缺陷 08 打断分档；
- 批次 4（P3）：缺陷 06/09/10/11 收口。
