# 照片引擎边界审计 — 产品上限、协议预算与样本数据

> 状态：执行中 · 最后更新：2026-11-19 · 维护人：K1Super
>
> 目的：确认方案中不存在“把样本数据当成产品边界”的问题，并给出可复现的判定规则与回归测试。

## 1. 结论

- 生产代码没有 10MiB 照片上限。唯一照片产品上限是 `photo_max_bytes = 104,857,600`（100MiB）。
- 10MiB、17.73MiB、24.43MiB、50MiB、100MiB 均为基准样本，不是产品边界。
- 发现并修复一处设计值与生产实现不一致：生产照片分块实际为 1MiB，而架构、数据模型、验收与 E2E 均按 4MiB 描述/测量。该问题属于同型的“设计值未落到生产事实”，已纳入 Phase 1 前置整改。
- 协议预算（IPC 载荷、请求/响应行、单批块数、单批记录数）不得用于拒绝合法产品输入；越界必须切批或流式处理。
- 安全限制（路径授权、回退锚点代数、解析帧上限）只能用于拒绝越权/损坏/攻击输入，不得拒绝正常大文件。

## 2. 边界分类

| 类别 | 当前取值 | 是否允许拒绝用户输入 | 说明 |
| --- | --- | --- | --- |
| 产品上限 | `photo_max_bytes = 100MiB` | 是 | 单张照片唯一产品上限；等于上限接受，超过 1 字节拒绝 |
| 产品上限 | `user_file_size_limit = 2GiB`、`max_export_single_bytes = 2GiB` | 是 | 文件保险箱与单文件导出的统一上限 |
| 协议预算 | `ipc_max_payload = 12MiB`（base64 口径） | 否 | 超出必须切批；单条记录必须可单独装入一次 IPC |
| 协议预算 | `ipc_max_request_line = 16MiB`、`ipc_max_response_line = 24MiB`、`ipc_max_line = 32MiB` | 否 | 帧开销与编码放大后的硬上限；调用方按预算切分 |
| 协议预算 | `max_chunks_per_ipc = 32` | 否 | 与字节预算同时生效，实际批大小取两者较小值 |
| 协议预算 | `add_records` 单批 512 条 | 否 | worker 写入上限；导入侧按 128–512 条切批 |
| 协议预算 | 记录名上限 `max_record_name_bytes = 1024` | 否 | 记录名由系统派生，不承载用户长文本 |
| 安全限制 | 单路径 grant：32 条 / 30s / 一次性 | 仅限单文件操作 | Phase 1 批量导入改用 job 级 grant（≤10,000 路径 / 10 分钟 / 成员校验） |
| 安全限制 | G0-A2：32 代 / 30s 锚点推迟窗口 | 否 | 超窗强制提交；不是照片大小限制 |
| 安全限制 | `parse_max_frame_count = 100,000`、`parse_max_frame_bytes = 64MiB` | 否 | 解析器防恶意分配；单帧上限大于照片分块上限，正常照片不会触达 |
| 工程默认值 | `photo_chunk_size = 4MiB` | 否 | 存储分块参数，可在预算内调整；不产生用户可见的大小上限 |
| 工程默认值 | `payload_chunk_size = 1MiB` | 否 | VENC 容器帧与旧路径兼容口径，不是照片存储分块 |
| 工程默认值 | 缩略图 400px / 45,000 字符 | 否 | 编码档位自动降级，失败不阻塞导入 |
| 工程默认值 | 批量聚合窗口 12ms、IPC 水位 80% | 否 | 调度参数，不影响正确性 |
| 基准样本 | 10 / 17.73 / 24.43 / 50 / 100MiB | 否 | 只出现在测试、基准与验收矩阵，禁止写入生产判定 |

## 3. 审计发现与整改

### F1 生产照片分块口径不一致（高）

- 现象：`src/workers/photo-crypto.worker.ts` 使用 `CHUNK_SIZE`，其值为 `PAYLOAD_CHUNK_SIZE_BYTES = 1MiB`；而 `docs/photo-engine` 的架构、数据模型、验收和 `e2e_measure.rs` 均按 4MiB。
- 影响：按 100MiB 照片计算，生产产生 100 个块记录，设计与实测为 25 个；G0-A2 的锚点代数摊销、IPC 轮次与存储记录数量全部偏离设计口径。
- 整改：新增 `photo_chunk_size = 4MiB` 作为照片存储与 VENC 帧上限的唯一口径，生产照片加密路径改用 `PHOTO_CHUNK_SIZE`；`payload_chunk_size = 1MiB` 仅作为旧 1MiB 数据兼容与块集最坏情况上界的推导口径。
- 兼容：读取侧按 `PhotoMeta.chunkIds` 逐块解析，不依赖固定块长；存量 1MiB 块可继续读取。VENC 容器格式版本不变，帧上限与存储分块同源为 4MiB：旧 1MiB 帧容器继续可解析，新导出按 4MiB 帧输出。
- 回归：预算生成器新增单条 4MiB 块必须可单独装入一次 IPC、且至少两块可同批的不变式；前端分块测试覆盖 17.73/24.43/100MiB。

### F2 `PB_CHUNK_RECORD_B64_MAX` 由 1MiB 推导（中）

- 现象：该常量按 `payload_chunk_size` 计算为 1,398,188。
- 影响：当前无运行时消费者，但后续原生导入或校验一旦引用，会把 4MiB 块误判为超限。
- 整改：改由 `photo_chunk_size` 推导；保留 `payload_chunk_size` 用于 VENC 与旧数据上界。

### F3 块集记录上界按 1MiB 最坏情况保留（低）

- 现象：`chunk_set_plain_max` 按 `photo_max_bytes / payload_chunk_size` 推导，即 100 个块引用。
- 判定：这是兼容性上界，不是写入口径；保持 1MiB 推导可同时容纳存量 1MiB 块集与新 4MiB 块集，不构成错误。
- 约束：新导入若写瘦身布局，实际块数更少，必然落在该上界内。

### F4 路径授权 32 条 / 30s（中，已纳入 Phase 1）

- 现象：现有 `path_grants` 为单路径、一次性、30s、最多 32 条。
- 判定：这是单文件操作的防越权限制，不是照片大小或数量产品上限。
- 整改：Phase 1 新增 job 级 grant（≤10,000 路径、10 分钟、绑定 job_id、只读成员校验），批量导入不得复用单路径 grant。

### F5 10MiB 仅存在于样本与历史报告（已确认）

- 生产常量、校验、数据库与协议中没有 10MiB 判定。
- G0-A2 报告已改为尺寸矩阵，并标注旧 10MiB 单点结果口径不可直接比较。

### F6 单块密文预算少算 10 字节（高，已修复）

- 现象：`chunk_crypto_overhead` 原为 64 字节，实测 4MiB 块密文 base64 恒为 5,592,504 字符，而 `PB_CHUNK_RECORD_B64_MAX` 为 5,592,492。
- 根因：分片密文实际开销为 74 字节——内容域标签 6 + 分片头 28（uuid 16 + seq 4 + total 4 + pt_len 4）+ nonce 24 + 认证标签 16；原值遗漏了 10 字节。
- 影响：任何按该常量做单条校验或跨层批预算的调用方都会把合法 4MiB 块误判为超限。
- 整改：`photo_budget.schema.json` 的 `chunk_crypto_overhead` 改为 74，重新生成两侧常量；E2E 对每个实际块断言长度 ≤ `PB_CHUNK_RECORD_B64_MAX`。
- 回归：生成器单块/两块 IPC 不变式；worker+DLL E2E 的逐块长度断言。

## 4. 强制规则

1. 任何会拒绝用户输入的常量必须先在本文登记类别；未登记不得进入生产判定。
2. 基准样本只能出现在测试、基准与验收文档；生产代码禁止出现样本尺寸字面量。
3. 协议预算越界必须切批/流式/分片，不得转化为文件大小上限。
4. 安全限制必须写明“拒绝的是越权、损坏还是攻击”，不得顺带限制正常大文件。
5. 新增或修改预算常量必须走 `constants/photo_budget.schema.json` 与生成器，禁止手改生成物。
6. 每个产品上限必须有边界测试：等于上限接受、上限 +1 拒绝、上限内多尺寸通过。

## 5. 回归清单

- [x] `ceil(size / photo_chunk_size)` 对 1B、4MiB、4MiB+1、17.73MiB、24.43MiB、50MiB、100MiB 的结果符合预期。
- [x] 100MiB 照片接受；100MiB + 1 字节拒绝；两者错误信息不同。
- [x] 单条 4MiB 块密文 base64 可单独装入一次 IPC；至少两块可同批。
- [x] 存量 1MiB 块照片可读取、导出（VENC 1MiB/4MiB 帧往返测试；读取按 `chunkIds` 逐块解析）；删除沿用既有测试。
- [x] 新导入 4MiB 块照片可读取、导出；worker+DLL E2E 校验块数与 meta 引用。
- [x] VENC 容器旧 1MiB 帧可解析，新导出按 4MiB 帧输出并被当前解析器接受。
- [x] 批量 job grant 支持 1,000 / 10,000 路径；第 10,001 条拒绝；跨 job 复用拒绝；过期由 TTL 实现并有单测覆盖成员校验。
- [x] 10MiB 仅作为测试样本出现，生产代码检索无命中。
