# 代码审查维度规范

> 审查人格的维度附录 · 按需加载 · 不单独作为人格使用

本文件展开审查维度的检查点。变更触及某维度时读取对应章节；未触及的维度不检查、不声明「已检查」。发现级别、证据要求与裁决规则以人格内核为准，本文件不重复定义，也不按命中条目数量升级。

读取不到本文件时，按内核「高危面最小清单」执行，并在汇报中声明「附录未加载」。不得假装已读过。

---

## 一、意图与范围

- 实现是否覆盖需求与验收判据；是否只完成了一半。
- 是否夹带无关改动、顺手重构、批量格式化。
- 是否缺少配套变更：迁移、配置、开关、文档、测试、调用方更新。
- 删除与重命名是否遗漏引用；生成物与锁文件的变化是否合理。
- 提交信息是否与变更一致；是否夹带无关文件、生成物或凭据。
- 生成代码与第三方包默认不逐行审查；检查来源、版本与差异是否合理，影响正确性时按缺陷处理。

## 二、正确性

- 空值、空集合、极值、负数、零、超长输入、Unicode、时区与夏令时。
- 边界与差一错误；类型转换与精度丢失；金额与计数是否使用可精确表示的类型。
- 整数溢出、除法与取模边界；计数与配额是否会出现负数或回绕。
- 失败路径：异常是否被吞、是否用默认值掩盖错误、是否留下半完成状态。
- 状态机：非法转移、重复提交、重试重复执行、顺序颠倒。
- 资源：文件、连接、句柄、锁、临时目录在成功与失败路径是否都释放。
- 返回值与错误码是否与调用方预期一致；是否把内部错误暴露给外部。

## 三、安全

- 每个新增入口是否经过认证与授权；对象级权限是否校验，不能只校验「已登录」。
- 认证与授权令牌的过期、刷新、撤销与重放防护是否完整。
- 跨信任边界的输入是否校验类型、长度、范围、编码与白名单。
- 对象绑定与批量赋值是否使用字段白名单；敏感字段是否可被外部覆盖。
- 注入汇点：SQL 或 ORM 原生拼接、命令、模板、响应头、日志、LDAP、XPath。
- 解析器与正则：XML 是否禁用外部实体；正则是否存在灾难性回溯。
- 路径与文件：规范化、白名单、上传类型与大小、存储位置、执行权限。
- 网络：SSRF 目标限制、重定向跟随、开放重定向与回调地址白名单、超时；回调与 Webhook 验签。
- 反序列化：不可信数据不得进入危险反序列化；模型输出不得直接执行。
- 加密：标准实现、安全随机源、密钥来源、密码哈希、常数时间比较。
- 密钥轮换、旧数据兼容与失效路径是否明确。
- 输出与日志：错误不泄露堆栈与内部路径；日志不含凭据与完整个人信息。
- 敏感信息是否进入 URL、查询串、Referer 或浏览器历史。
- 默认值：调试关闭、CORS 最小、Cookie 安全属性、TLS 校验、安全响应头与第三方资源白名单、最小权限。
- 状态变更接口是否有 CSRF 防护；Cookie 的 SameSite、Secure、HttpOnly 是否与场景匹配。
- 敏感接口的限流、防重放、幂等与审计。
- 多租户场景下查询条件、缓存键、唯一约束与导出是否都带租户边界。
- 新增依赖：必要性、维护状态、许可证、已知漏洞、锁文件差异。

## 四、数据与迁移

- 迁移是否可回滚；回滚是否会丢数据；是否有备份或快照。
- 向前兼容：滚动发布期间新旧版本能否同时读写。
- 回填是否幂等、可分批、可中断续跑；锁影响与执行窗口。
- 事务边界与隔离级别；是否存在部分成功。
- 索引与约束的创建方式是否阻塞写入；大表操作是否分批。
- 删除、软删除、级联与保留期；导出与迁移是否留痕。
- 事件消费的幂等、顺序与重复投递；是否假设了「恰好一次」。

## 五、并发与资源

- 共享可变状态、锁顺序、锁范围、死锁风险。
- 检查与使用之间的时间差（TOCTOU），尤其是文件、权限与临时路径。
- 异步任务的取消、超时、上下文传播；线程池与队列是否有界。
- 连接、句柄、订阅、监听器在异常路径是否释放。
- 重试是否有退避与上限；是否会造成重试风暴。
- 背压、限流、降级与优雅停机。

## 六、契约与兼容

- 新增字段是否可选、默认值是否兼容旧客户端。
- 删除、重命名、类型变更、错误结构变更是否破坏调用方。
- 状态码、分页上限、排序稳定性、幂等键是否符合既有约定。
- 配置键的默认值与缺失行为；开关打开与关闭两条路径是否都成立。
- 版本化、弃用期与迁移指引是否齐全。

## 七、性能

- 复杂度与数据规模上界；是否存在随数据增长失控的路径。
- 循环内的 IO、查询、序列化；N+1；缺失索引；无界集合与缓存。
- 热路径中的阻塞调用、锁竞争、同步等待。
- 缓存一致性、穿透与失效策略。
- 缓存键是否包含租户、版本与用户边界，避免跨用户或跨版本命中。
- 只报有机制的性能问题，并给出量级或测量方式；不凭直觉要求微优化。

## 八、可维护性

- 分层与依赖方向；是否跨层直连、形成环、引入隐式全局状态。
- 职责与命名是否达意；是否存在一次性抽象、死代码、无依据的兼容层。
- 临时开关、兼容层与迁移辅助代码是否有移除计划与负责人，避免永久分支。
- 重复逻辑是否已出现漂移；关键常量是否散落。
- 文件与目录是否出现职责混杂的膨胀或平铺，导致定位与变更成本上升；拆分建议须说明边界与收益。
- 注释与实现是否一致；不一致按缺陷处理，不按文档问题处理。
- 错误分类与传播是否清晰；是否用宽泛异常覆盖不同失败语义。

## 九、测试

- 测试能否在实现回退时失败；恒过、无断言、只验证不抛异常的测试视为未覆盖。
- 断言行为与边界，还是断言内部实现与调用次数。
- 失败路径、边界值与恶意输入是否覆盖；是否只覆盖正常流。
- 确定性：时间、随机、网络、顺序、休眠、共享状态是否会导致波动。
- 隔离与清理：用例之间是否互相污染；是否依赖执行顺序。
- 新增分支是否有对应用例；测试是否为了通过而放宽了原断言。
- 删除、跳过或用条件屏蔽测试是否有需求变更依据；是否用测试改动换取通过。
- 测试夹具是否含生产数据、真实个人信息或未脱敏样本。
- 是否为了测试在生产代码中加入专用分支或开关；覆盖率数字不能代替失败路径与断言语义的检查。

## 十、可运维性

- 关键节点是否有结构化日志；日志是否含凭据或完整个人信息。
- 是否有可观测指标与告警；失败是否可定位。
- 启动时是否校验配置；缺失配置是否显式失败而不是静默降级。
- 健康检查、迁移步骤、回滚路径与部署顺序是否明确。
- 面向用户的错误信息是否可行动，且不泄露内部细节。

## 十一、界面与交互（仅当变更触及）

- 加载、空、错误、禁用与处理中状态是否完整；重复提交是否被阻止。
- 异步竞态：旧请求覆盖新状态、卸载后更新、乐观更新回滚。
- 不可信内容进入 DOM、富文本、URL、样式与脚本的路径是否安全。
- 键盘可达、标签与焦点顺序是否被破坏。
- 不因纯审美阻断合并；视觉偏好按建议处理。

## 十二、文档与注释

- 公共接口、配置、迁移与运维文档是否随行为同步。
- 示例与 README 是否仍可执行；是否描述了已删除的行为。
- 注释是否解释原因而非重复代码；是否与当前实现矛盾。
- 注释是否符合仓库既有规范；是否引入外部文档引用、编号或链接，导致脱离上下文不可验证。
- 注释、示例与文档是否含凭据、令牌或真实个人信息。
- 变更记录是否符合仓库既有惯例；不为凑格式新增文件。

## 十三、生成代码与来源不明的实现（仅当可识别）

- 核对 API、参数、配置项、返回结构是否存在于当前依赖版本；不存在即为阻断候选，按可达性定级。
- 检查是否用默认值、空实现、宽泛异常吞掉失败；是否留下未使用的抽象与「以后可能用」的兼容层。
- 测试是否与实现同构、复制了同一错误假设；断言是否只验证 mock 调用。
- 注释与实际行为是否一致；是否存在为通过审查而写的说明。
- 复制逻辑是否已与原处漂移；安全默认值是否被改成便利默认值。
