# 注释约束词表

- 用途：AI 与人工编写、审查代码注释时的禁用词与改写依据
- 配套：`docs/references/comment-standards.md`（分层要求与完整规则）、`.trae/rules/project_rules.md`（注释红线摘要）
- 适用范围：`.ts` / `.vue` / `.css` / `.js` / `.rs` / `.c` / `.h` / `.cpp` / `.ps1` / `.mjs` / `.py` / `.yml` 中的注释
- 不适用范围：测试用例名字符串、日志模板、错误消息、UI 文案、配置值（这些是代码字符，不是注释）

---

## 一、判定三步

1. **确认载体**：目标文本是否真的是注释（`//`、`/* */`、`///`、`//!`、`#`、`<# #>`、`<!-- -->`）。不是注释就不在治理范围。
2. **确认性质**：是否在描述「过去如何」或「指向外部资料」。描述当前约束、边界、失败路径的句子，即使含相近词也不违规。
3. **改写而非删光**：句子里有有效约束时，改写为对当前实现的陈述；只有纯叙事才整句删除。

---

## 二、硬禁用词（出现即违规）

### 1. 变更史与旧实现叙事

| 禁用词 / 句式 | 说明 | 改写方向 |
| --- | --- | --- |
| 原实现、原逻辑、原代码、原方案、原流程、原路径、原有做法 | 描述被替换的实现 | 直接写当前实现及其约束 |
| 旧实现、旧逻辑、旧方案、旧流程、旧版实现 | 同上 | 同上 |
| 此前、原先、曾经、上一版、历史基线、早期实现、初版 | 时间回溯 | 删除；约束部分改为现状 |
| 已删除、已移除、已废弃、已下线、已收编、已迁移、彻底移除、根除、根治 | 变更结果 | 删除；需要防回归时写「不得恢复 X，否则 Y」 |
| 修复点、修复前、修复后、改造后、重构后、本版改为、新版改为、改用、替换了 | 修复过程 | 改为「必须/禁止 + 原因」 |
| 被否决、不再采用、不再使用、不再保留、保留兼容签名 | 决策史 | 删除；保留唯一的当前契约 |
| 用户反馈、用户要求、用户裁定、用户校正、用户偏好、按用户要求 | 外部溯源 | 删除；需求依据不进注释 |
| 据经验、一般来说、众所周知 | 无依据断言 | 删除或改为可验证约束 |

### 2. 外部指向与编号

| 禁用项 | 示例 | 处理 |
| --- | --- | --- |
| 文档路径 | `docs/xxx.md`、`README.md`、`xxx.spec.ts` 作为指向 | 删除；把规则本身写进注释 |
| 链接 | `http://`、`https://` | 删除（数据来源可保留名称与版本，不保留 URL） |
| 章节 / 条款 | `§3.2`、`第 5 章`、`见 2.1 节` | 删除 |
| 工单 / 评审 | `#123`、`评审 #1`、`PR #45`、`Issue 88` | 删除 |
| 里程碑 / 代号 | `Wave 54`、`P0-A`、`R-10`、`T-1`、`M2`、`U1/U2`、`N2/N5`、`项2`、`阶段 4.6` | 删除编号，保留语义 |
| 跨文件指引 | 「见 xxx.ts」「详见 xxx 头注」「参考 xxx 实现」 | 删除；写清约束或改用当前文件内可解析的符号名 |

### 3. TODO 元信息

| 禁用 | 允许 |
| --- | --- |
| `TODO(2025-09-18, 张三, #123): 优化` | `TODO: 并发写入需补幂等键，否则重试会重复落盘` |
| `FIXME: 以后再说` | `FIXME: 超时分支未覆盖，网络抖动时会悬挂` |

规则：TODO / FIXME / HACK 只写「待办原因 + 不处理的后果」，不带日期、人名、编号。

## 三、慎用词（按语义判断，不一律删）

| 词 | 合法用法（保留） | 违规用法（改写或删除） |
| --- | --- | --- |
| 旧版 / 旧格式 / 旧数据 | 「兼容旧版 WebView」「旧格式载荷仍需可解析」「旧版备份导入」——描述现行兼容的数据形态 | 「旧版布局在这里」「旧实现把…」——描述代码演进 |
| 历史 | 「历史记录」「历史耗时」——业务数据 | 「历史上曾…」「历史基线」——变更史 |
| 迁移 | 「迁移前先校验锚点」——当前迁移流程的步骤 | 「从 A 迁移到 B 后…」——已完成的演进 |
| 不再 | 「归零后不再复位」——当前行为 | 「不再使用旧接口」——变更史 |
| 兼容 | 「需兼容 v1 容器」——当前契约 | 「保留兼容签名」——历史包袱叙事 |
| 来源 | 「数据来源：某数据集 2.7.0」——数据出处 | 「来源：SecurityCenter.vue L166」——代码溯源 |
| 修复 | 「修复告警」「可修复降级」——业务术语 | 「修复：xxx」「修复了 N 次的问题」——过程叙事 |
| 根因 / 原因 | 「崩溃根因是句柄未关闭」——当前失败机理 | 「根因修复」「按根因调整」——变更史 |
| 见 / 参考 | 「见上文约束」——同文件内指向（谨慎） | 「见 xxx.md」「参考某规范」——外部指向 |

判断口诀：**说的是「现在必须怎样」就留，说的是「以前怎样、谁要求的、哪份文档写了」就删或改写。**

---

## 四、推荐约束词

写注释优先使用以下可验证的表述：

- 义务：必须、不得、禁止、只能、唯一、一律、始终
- 条件：前置条件、后置条件、仅在…时、否则、除非
- 不变量：不变量、单一权威源、唯一入口、同一实例、同一序列
- 失败：失败路径、降级、回滚、超时、重试、幂等、失败关闭
- 边界：上限、下限、预算、窗口、并发、竞态、生命周期
- 原因：用于、目的是、为避免、否则会、会导致

## 五、改写模板

| 原始写法 | 改写后 |
| --- | --- |
| 原实现用 `Date.now()`，现改为共享序列 | 装载与导入必须共用同一序列：双源生成会在同一毫秒内产生相同 ID，碰撞会误删第二条 |
| 旧版这里用 box-shadow，已根除 | 不得让 box-shadow 参与过渡：大半径模糊阴影逐帧重绘，滚动时会掉帧 |
| 详见 docs/xxx.md | 直接写出该文档中适用的一条约束（自包含） |
| 用户要求总时长 600ms | 总时长 600ms：超过会与下一段动画重叠 |
| 修复了 Wave 54 的闪烁问题 | 过渡目标仅 opacity：transform/filter 会让文字在动画首末帧重模糊 |
| 旧字段已删除，不得复活 | 该字段不得写回：读取方仍按旧位置解析，写回会导致错位 |
| 此处保留兼容分支 | 该分支用于解析 v1 容器；移除后旧备份无法导入 |

```powershell

```

### 使用要求

- 命中不等于违规：逐条按「判定三步」确认是否为注释、是否描述过去或外部指向。
- 测试用例名、日志字符串、错误消息、UI 文案、配置值中的命中一律跳过。
- 清理只改注释文本，不得顺带修改代码、格式或无关文件。

## 七、审查清单（提交前逐项过）

1. 新增注释是否只解释 Why / 约束 / 边界，没有逐行翻译？
2. 是否出现第二节任一硬禁用词？
3. 注释中的数值、符号、选择器、字段名是否与当前代码一致？
4. 是否用「见某文件」代替了本该写清楚的约束？
5. TODO 是否只写原因与影响，无日期、人名、编号？
6. 改动代码后，是否同步更新了相关注释？
7. 是否误改了测试名、日志、错误消息、UI 文案等代码字符？
8. 注释是否为中文，缩进与代码一致？
