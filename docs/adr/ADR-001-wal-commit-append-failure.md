# ADR-001：WAL COMMIT 追加失败不收尾，引用计数只多不少

- 状态：已采纳
- 日期：2026-09-22

## 背景

事务提交按序执行：超级块法定人数提交 → Extent 索引持久化 → 分区表
持久化 → WAL COMMIT 记录追加。WAL COMMIT 是回放规则锚点；若此步
追加失败（IO 故障），组内此前全部步骤已落盘，但盘上组形态为
PREPARE-only（无 COMMIT 帧）。

## 决策

1. `verthys_txn_v3_commit` 在 WAL COMMIT 追加失败时立即返回错误、
   不推进状态收尾（不回滚、不 confirm）：该失败与"同点崩溃"等价，
   恢复路径按 WAL 回放规则对该组重放收尾，提交语义由恢复机制兜底。
2. 崩溃恢复重放 EXTENT 帧时，已注册条目只做 `ref_count++`（方向安全：
   计数只多不少）。崩溃点晚于索引落盘时计数偏大，以空间泄漏换数据
   安全，由 GC 周期收敛；绝不 `ref_count--`（可能减到 0 释放仍被
   引用的块）。

## 后果

- 提交调用方面对 WAL 尾步失败会看到错误码，但事务实际已生效
  （法定人数含 txid）；重开容器后由恢复收尾，最终状态一致。
- 引用计数可能长期偏大，需要 GC 以"当前索引引用集 + 事务账本"
  为唯一权威重新对账，不能把计数本身当权威。
