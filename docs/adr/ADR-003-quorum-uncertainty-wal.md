# ADR-003：法定人数提交的不确定窗口由 WAL 恢复兜底

- 状态：已采纳
- 日期：2026-09-22

## 背景

超级块法定人数提交分两步：先逐副本写入并 fsync（≥2 成功即算
候选成立），再读回 ≥2 副本验证 HMAC。两步之间存在失败窗口：
例如写已 ≥2 成功、读回验证却失败（IO 抖动 / 局部坏块），调用方
拿到错误码，但盘面可能已有 ≥2 副本携带新 txid——"半提交"状态。
调用方无法仅凭返回值判定事务是否生效。

## 决策

该"不确定结果"不引入新的分布式协调：状态机一律按
"法定人数写入成功后的一切失败 ≡ 该点崩溃"处理。
裁决权威交给 WAL 恢复：组内 PREPARE 帧先于超级块候选写入，恢复
按水位与组提交形态重放收尾——已落盘副本含 txid 的组被收尾提交，
未达法定人数的组被丢弃，两种歧义终态收敛到同一正确结果。
事务层在法定人数成功后即置 `COMMITTED`，回滚通道永久关闭。

## 后果

- 无三方仲裁、无人工修复路径：一切交给崩溃恢复协议，语义简单
  且可测试（法定人数后任意点断电的模糊测试必须收敛）；
- 需要保证 WAL 帧与超级块副本的写入顺序（WAL 先行），该顺序是
  恢复正确性的前提，为红线不变式；
- 读回验证仍保留（把可当场识别的损坏尽早暴露为 `VERTHYS_ERR_IO`），
  但不改变上述终态收敛语义。
