# ADR-002：MemTable 重建失败降级只读态，WAL 帧留待重开幂等重放

- 状态：已采纳
- 日期：2026-09-22

## 背景

flush 收尾需要"销毁旧 MemTable + 创建新 MemTable"。若创建失败
（内存耗尽），条目已经全部持久化（新 SSTable + Manifest 已提交），
但若保留旧表并继续写，下一次 flush 会把已持久化条目重复写入
（重复条目污染索引）。若在此处复位 WAL，则崩溃恢复将丢失重放源。

## 决策

`verthys_lsm_flush_locked` 在新表创建失败时：
1. 销毁旧 MemTable（条目已全部在 SSTable，读路径无损）；
2. 置 `memtable_readonly = 1`，其后一切写入返回
   `VERTHYS_ERR_RESOURCE_LIMIT`（杜绝重复条目与半写语义）；
3. 不复位 WAL——帧留在盘上，Lock 重开时经幂等重放恢复写入能力。

## 后果

- 内存耗尽场景下容器变为只读，但已有数据完整可读、可安全关闭；
- 重开后的重放必须幂等（MemTable 条目写满短路），该约束由重放
  路径的"先查后写"语义保证；
- 该降级是显式的资源边界行为，不做静默的"假成功"。
