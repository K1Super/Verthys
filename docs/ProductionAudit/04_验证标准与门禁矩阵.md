> 本文定义**“通过”的可判定标准**。任何结论不得使用“应该/大概/看起来”，必须附命令输出或 `file:line` 证据。
> 门禁分为：**既有门禁**（仓库已具备）、**本轮新增门禁**（随修复引入）、**实测验收**（运行态）。

## 2. 全量门禁命令矩阵（收口必跑）

```powershell
# 前端（工作目录 verthys-tauri\）
npx vue-tsc --noEmit              # 期望 exit 0
npx vitest run                    # 期望 34 文件 / 388 例全绿
npm run build                     # 期望 exit 0（项目方执行）
npm audit --audit-level=high      # 期望 exit 0（Phase 1 后）

# Rust 主进程（工作目录 verthys-tauri\src-tauri\）
cargo test --lib                  # 期望 476 全绿
cargo clippy --all-targets -- -D warnings   # 期望 0 告警

# worker（工作目录 verthys-tauri\verthys-worker\）
cargo test                        # 期望 33 全绿

# C 核心（待核验，构建后）
ctest --test-dir build            # 或 verthys_tests.exe，全绿

# 体系静态（仓库根）
powershell -ExecutionPolicy Bypass -File ci\run_ci.ps1
```

> 说明：`cargo test --lib` 无法一次跑 worker（不同 crate），须分别执行。

## 6. 交付门禁（发布判定）

发布前须同时满足：

1. **全部静态门绿**：版本门 / 锚点门 / 常量门 / 导出契约门 / AST 二级。
2. **全部测试绿**：front 388 / Rust 476 / worker 33 / C（待核验基线）。
3. **依赖门绿**：`npm audit --audit-level=high` exit 0；Rust 依赖扫描无 high/critical（G-2，若无工具须先补）。
4. **构建门绿**：`build_production.ps1` 产物齐备 + 哈希一致。
5. **本轮缺陷闭环**：F1–F8、O1 全部处置且验证通过。
6. **实测项闭环**：V1–V8 全部留证据通过。
7. **文档同步**：`IMPL_PROGRESS.md` 与本套文档状态回填一致。

> 任一项未满足 → **不得发布**（红线）。

## 7. 证据留档规范

- 每条“通过”须附：**命令 + 输出摘要**（或 `file:line` + 代码摘录）。
- 实测项须附：**操作步骤 + 结果**（日志/截图/返回值）。
- 【待核验】在未取得证据前**一律不得标记为“通过”**。
- 结论若依赖推断，须显式标注“推断”及依据，且不得作为发布门禁依据。
