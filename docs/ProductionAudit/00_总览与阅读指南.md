## 一、本审查的定位与边界

### 1.1 定位

本审查面向“**可落地实施**”：不仅给出问题清单，更给出**排查路径、验证标准、分阶段执行步骤、红线约束**，使接手人可直接切入施工，无需二次调研。

### 1.2 视角优先级（按用户要求排序）

1. **外部视角**：入口面、攻击面、IPC 命令面、用户可见行为。
2. **运行态**：并发、超时、资源生命周期、故障恢复、可观测性。
3. **业务维度**：各功能模块的数据正确性、流程闭环、边界与失败语义。
4. **系统层面**：分层架构、依赖供应链、构建/发布/CI、文档与注释规范。

### 1.3 证据分级（贯穿全部文档）

| 标记 | 含义 | 使用规则 |
| --- | --- | --- |
| 【已证实】 | 已由静态代码取证（`file:line`）或门禁命令实测确认 | 结论可直接采信 |
| 【待核验】 | 需运行态实测 / 手工操作 / 环境依赖才能确认 | **禁止在未核验前当作结论**，列为排查项 |
| 【已排除】 | 初筛疑似缺陷，经代码取证判定为非缺陷（误报） | 记录以免重复排查 |

> 红线纪律：本套文档**不允许把【待核验】项写成确定性结论**，也不允许遗漏任一检查维度。凡不能确认者，一律显式标注。

## 四、关键约束（施工前必读）

1. **平台限制**：本机 `ninja` 缺失、`clang-tidy` 缺失——C 构建回退 VS 生成器路径，clang-tidy 门不可跑（见 03 Phase 0）。
2. **构建脚本约定**：历史约定为“构建脚本由项目方执行”；本套文档的 03 阶段中涉及构建的步骤标注为**需项目方授权执行**。
3. **注释红线**：代码注释/日志串禁止出现外部文档引用与编号（`.md`、`docs/`、`§`、“第 N 项”、“见/参考/依据/详见/参见/来源”等），详见 06 类约束（本文档集以 04 §5 与 03 各阶段红线小节承载）。
4. **禁止降级**：任何修复不得以“简化/临时/后续迭代”为由降低生产标准；不得伪造测试/日志/返回值。
5. **未提交改动**：当前工作树含未提交改动（Wave 0~58 系列），施工前须先冻结基线（03 Phase 0）。
