### 2A · 注释/日志红线清理（F2 + F5）

#### 目标
全仓（`core/src`、`verthys-worker/src`、`verthys-tauri/src-tauri/src`）**零**外部文档名与条款号。

#### 入口
- F2：`security/cleanup.rs:619,702`、`security/usb_guard.rs:559,918`（含 `SECURITY.md 第 N 项`）
- F5：`security/brute_force.rs:309,324,335,402`、`security/session_guard.rs:359,682,692,712,798,815`（“第 N 项”）

#### 步骤
1. 全仓扫描定位：`grep -rn "\.md\|docs/\|第 *[0-9]\+ *项\|§" core/src verthys-worker/src verthys-tauri/src-tauri/src`
2. 逐处改写为**自包含**描述（删除文档名与条款号前缀，保留技术语义）。
   - 例：`"[secure_delete] SECURITY.md 第 2 项：检测到稀疏文件..."` → `"[secure_delete] 检测到稀疏文件，仅覆写已分配区域..."`
3. **不得改变技术语义**；不得删除日志本身（日志是观测资产）。
4. 复查：扫描归零。
5. 编译与测试：`cargo clippy --all-targets -- -D warnings`、`cargo test --lib`。

#### 门禁
- 扫描门：`grep` 命中 = 0
- 编译门：clippy 0 告警、测试 476 全绿

#### 回滚
- 纯字符串改动，可整批回滚，无数据影响。

#### 红线约束
- 禁止把“第 N 项”简单删成空前缀导致语义不完整——必须补回可验证的技术描述。
- 禁止顺手改动无关注释与代码（最小改动原则）。
- 若发现“依据/来源/方案”等黑名单词属**自然用语**（非外部引用），**先标注口径、暂不改写**，待 Phase 5 统一决定（见 J-3）。

## §7 全局红线约束（贯穿全部阶段）

1. **禁止降级**：不得以“简化/临时/后续迭代”降低生产标准；不得省略核心逻辑；不得伪造测试/日志/返回。
2. **禁止注释外部引用**：代码注释与运行期日志不得出现外部文档名（`.md`、`docs/`）、条款号（“第 N 项”、“§”）、溯源词（见/参考/依据/详见/参见/来源）等；改写须**自包含且语义不变**。
3. **禁止绕过门禁**：不得以 `#[allow]`、`--omit`、注释规避等手段绕过检查；不得删除既有门禁以“通过”。
4. **fail-safe 方向不可逆**：任何改造失败路径必须朝“防护更严/数据更安全”方向；禁止朝“防护关闭/数据丢失”方向。
5. **构建脚本约定**：`build_production.ps1` / `build_dev.ps1` / `npm run build` **由项目方执行**；助手仅执行静态验证（`vue-tsc`/`vitest`/`cargo`/`npm audit`/`run_ci`）。
6. **单阶段闭环**：一阶段改动 + 该阶段门禁 + 该阶段回滚点，三者齐备方可进入下一阶段。
7. **证据留痕**：所有“通过”结论须附命令输出或 `file:line` 证据。
8. **冲突消解优先级**：安全合规 > 用户需求 > 功能正确性 > 可读性 > 性能。
